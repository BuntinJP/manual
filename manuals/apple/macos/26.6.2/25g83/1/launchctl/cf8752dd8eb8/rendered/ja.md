## 名前 {#NAME}


<p><code>launchctl</code> — launchd とのインターフェース</p>

## 書式 {#SYNOPSIS}

## 説明 {#DESCRIPTION}


<p><code>launchctl</code> は <code>launchd</code> と連携し、デーモン、エージェント、および XPC サービスを管理、調査します。</p>

## サブコマンド {#SUBCOMMANDS}


<p><code>launchctl</code> を使用すると、<code>launchd</code> のデータ構造を詳細に調査できます。基本となる構造は、ドメイン、サービス、およびエンドポイントです。ドメインは、サービス群の実行ポリシーを管理します。サービスは、要求に応じて起動できるよう常に利用可能な仮想プロセスとみなせます。各サービスは複数のエンドポイントを持ち、そのいずれかにメッセージを送ると、サービスがオンデマンドで起動します。ドメインは共有名前空間でこれらのエンドポイントを公開し、Mach ブートストラップのサブセットと同義とみなせます。</p>

<p><code>launchctl</code> の多くのサブコマンドは、その対象となるドメインまたはサービスを示す指定子を取ります。この指定子には、次のいずれかの形式を使用できます。</p>

<dl><dt><em>system/[service-name]</em></dt><dd><p>システムドメイン、またはシステムドメイン内のサービスを対象とします。システムドメインはルート Mach ブートストラップを管理し、特権実行コンテキストとみなされます。システムドメインの読み取りや照会は誰でも行えますが、変更には root 権限が必要です。</p></dd><dt><em>user/&lt;uid&gt;/[service-name]</em></dt><dd><p>指定した UID のユーザードメイン、またはそのドメイン内のサービスを対象とします。ユーザードメインは、ログイン中のユーザーがいなくても存在する場合があります。iOS にはユーザードメインは存在しません。</p></dd><dt><em>login/&lt;asid&gt;/[service-name]</em></dt><dd><p>ユーザーログインドメイン、またはそのドメイン内のサービスを対象とします。ユーザーログインドメインは、ユーザーが GUI からログインしたときに作成され、そのログインに関連付けられた監査セッション識別子によって識別されます。ユーザードメインにログインドメインが関連付けられている場合、<code>print</code> サブコマンドはそのログインドメインの ASID を表示します。iOS にはユーザーログインドメインは存在しません。</p></dd><dt><em>gui/&lt;uid&gt;/[service-name]</em></dt><dd><p><code>login</code> 指定子の別形式です。ユーザーログインドメインを ASID で指定する代わりに、関連付けられたユーザーに基づいてドメインを対象とするため、一般にはこちらの方が便利です。</p>
<p><em>Note</em>: GUI ドメインとユーザードメインは多くのリソースを共有します。Mach ブートストラップ名の検索に関しては両者は「フラット」であり、同じ登録名の集合を共有します。ただし、サービスの集合はそれぞれ独立しています。そのため、ユーザードメインの内容を表示すると、そのユーザーの GUI ドメインに存在するサービスによる Mach ブートストラップ名の登録が多数表示されることがありますが、その一覧にサービス自体は表示されません。</p></dd><dt><em>pid/&lt;pid&gt;/[service-name]</em></dt><dd><p>指定した PID のドメイン、またはそのドメイン内のサービスを対象とします。システム上の各プロセスには、そのプロセスから見え、<code>xpc_connection_create(3)</code> で到達できる XPC サービスで構成される PID ドメインが関連付けられます。</p></dd></dl>

<p>たとえば、UID 501 のユーザーの GUI ドメインに読み込まれた、識別子 <code>com.apple.example</code> のサービスを参照する場合、<code>domain-target</code> は <code>gui/501/</code>、<code>service-name</code> は <code>com.apple.example</code>、<code>service-target</code> は <code>gui/501/com.apple.example</code> です。</p>

<p><em>IMPORTANT</em>: この出力は、いかなる意味でも API ではありません（<em>NOT</em>）。出力される構造や情報には、どのような理由（<em>ANY</em>）であっても依存してはいけません（<em>NOT</em>）。これらはリリースごとに予告なく変更される可能性があります。</p></dd><dt><em>print-cache</em></dt><dd><p><code>launchd</code> のサービスキャッシュの内容を表示します。</p></dd><dt><em>print-disabled domain-target</em></dt><dd><p>指定したドメインで無効になっているサービスの一覧を表示します。</p></dd><dt><em>plist</em> [<em>segment,section</em>] <em>Mach-O</em></dt><dd><p>対象の Mach-O の __TEXT,__info_plist セグメント／セクション、または指定したセグメント／セクションに埋め込まれているプロパティリストを表示します。</p></dd><dt><em>procinfo</em> <em>pid</em></dt><dd><p>指定した PID の実行コンテキストに関する情報を表示します。この情報には、Mach のタスク特殊ポートと例外ポート、監査セッションコンテキストが含まれます。また、DEVELOPMENT 版 launchd に対して実行した場合は、ポートが Mach ブートストラップ名前空間でどの名前として公開されているかも、<code>launchd</code> がその名前を認識していれば表示されます。このサブコマンドは診断だけを目的としており、本番環境でその出力に依存してはいけません。このコマンドには root 権限が必要です。</p></dd><dt><em>hostinfo</em></dt><dd><p>ホスト例外ポートを含む、システムのホスト特殊ポートに関する情報を表示します。このサブコマンドには root 権限が必要です。</p></dd><dt><em>resolveport</em> <em>owner-pid</em> <em>port-name</em></dt><dd><p>PID と、そのプロセスのポート名前空間にある Mach ポート権の名前を指定すると、そのポートを <code>launchd</code> が認識しているエンドポイント名に解決します。このサブコマンドには root 権限が必要です。</p></dd><dt><em>examine</em> [<em>tool</em> <em>arg0</em> <em>arg1</em> <em>@PID</em> <em>...</em>]</dt><dd><p>プロファイリングツールで調査できるように、<code>launchd</code> 自身に <code>fork(2)</code> を実行させ、この新しいインスタンスの PID を標準出力に表示します。このスナップショットが不要になったら、利用者が終了させる必要があります。</p>
<p>多くのプロファイリングツールは、<code>launchd</code> が提供する機能に依存しているため、そのデーモンを安全に調査できません。このサブコマンドは、独立して調査できる <code>launchd</code> の実質的なスナップショットを作成します。Darwin プラットフォームでは、<code>fork(2)</code> は <code>fork(2)</code> を呼び出したスレッドだけが新しい子プロセスに複製されるよう実装されています。そのため、このサブコマンドはメインイベントループ以外のスレッドの調査には役立ちません。</p>
<p>このサブコマンドには、<code>launchd</code> のスナップショットに対して使用するツールの呼び出しを任意で指定できます。通常ならツールの呼び出しで調査対象プロセスの PID を指定する箇所に、代わりに引数「@PID」を指定すると、<code>launchctl</code> は後でツールを実行する際に、その引数を launchd スナップショットの PID に置き換えます。この形式で使用した場合、調査ツールが終了すると <code>launchctl</code> がスナップショットのインスタンスを自動的に終了します。</p>
<p>このサブコマンドは DEVELOPMENT 版の <code>launchd</code> に対してのみ使用できます。</p></dd><dt><em>config</em> <em>system</em> | <em>user</em> <em>parameter</em> <em>value</em></dt><dd><p><code>launchd(8)</code> ドメインの永続的な設定情報を設定します。設定できるのはシステムドメインとユーザードメインだけです。永続ストレージの場所は実装の詳細であり、そのストレージへの変更は必ずこのサブコマンドを介して行うべきです（<em>only</em>）。このサブコマンドによる変更を有効にするには再起動が必要です。</p>
<p>サポートされる設定パラメータは次のとおりです。</p>
<dl><dt>umask</dt><dd><p>対象ドメイン内のサービスの <code>umask(2)</code> を、<em>value</em> で指定した値に設定します。この値は <code>strtoul(3)</code> によって 8 進数として解析されるため、先頭に「0」を付ける必要はありません。</p></dd><dt>path</dt><dd><p>対象ドメイン内のすべてのサービスについて、PATH 環境変数を文字列 <em>value</em> に設定します。文字列 <em>value</em> は、<code>environ(7)</code> で説明されている PATH 環境変数の形式に従う必要があります。サービスが独自の PATH を指定している場合は、サービス固有の環境変数が優先されることに注意してください。</p>
<p><em>NOTE</em>: この機能を使用して、ドメイン内のすべてのサービスに汎用の環境変数を設定することはできません。セキュリティ上の理由から、意図的に PATH 環境変数だけが対象とされており、それ以外は設定できません。</p></dd></dl></dd><dt><em>reboot</em> <em>[system|userspace|halt|logout|apps]</em></dt><dd><p>ユーザー空間の終了処理を開始するよう <code>launchd</code> に指示します。引数を指定しない場合、または <em>system</em> 引数を指定した場合、ユーザー空間が完全に終了した時点で <code>launchd</code> が <code>reboot(2)</code> システムコールを実行します。<em>halt</em> 引数を指定した場合は、ユーザー空間が完全に終了した時点で <code>launchd</code> が <code>reboot(2)</code> システムコールを <em>RB_HALT</em> フラグ付きで実行し、再起動を開始せずにシステムを停止します。</p>
<p><em>userspace</em> 引数を指定した場合、ユーザー空間の終了後に <code>launchd</code> が自身を再 exec し、ユーザー空間を再び起動します。これは、カーネルのデータ構造やハードウェアを再初期化する必要がない状況で、システムをすばやく再起動するのに役立ちます。</p>
<p><em>logout</em> 引数を指定すると、launchd は Apple メニューから開始するログアウトと同様の方法で、呼び出し元の GUI ログインセッションを終了します。主な違いは、このサブコマンドから開始したログアウトでは、アプリがモーダルダイアログを表示してログアウトを無期限に妨げる機会を与えないため、処理が大幅に速いことです。そのため、このオプションの使用にはデータ破損のリスクがあります。実行中のアプリに未保存のデータがないと分かっている場合にのみ使用してください。</p>
<p><em>apps</em> 引数を指定すると、launchd は呼び出し元の GUI ログインセッションで実行中のアプリのうち、ディスク上の <code>launchd.plist(5)</code> から起動されたものではないアプリをすべて終了します。Finder、Dock、SystemUIServer などのアプリには影響しません。アプリは <em>logout</em> 引数の場合と同じ方法で終了され、同じ注意事項がすべて適用されます。</p></dd><dt><em>error</em> <em>[posix|mach|bootstrap]</em> <em>code</em></dt><dd><p>指定したエラー <em>code</em> を人が読める文字列で表示します。デフォルトでは、<code>launchctl</code> は指定されたコードがどのエラードメインに属するかを推測します。呼び出し元は、指定したコードをどのサブシステムのエラーとして解釈するか、ドメイン（<em>posix</em>、<em>mach</em>、<em>bootstrap</em> のいずれか）を任意で指定できます。</p></dd><dt><em>variant</em></dt><dd><p>システムで現在有効な <code>launchd</code> のバリアントを表示します。バリアントには RELEASE、DEVELOPMENT、DEBUG があります。</p></dd><dt><em>version</em></dt><dd><p><code>launchd</code> のバージョン文字列を表示します。</p></dd></dl>

## 旧式のサブコマンド {#LEGACY_SUBCOMMANDS}


<p>旧式のサブコマンドは、root として実行されているかどうかに基づいて対象ドメインを選択します。root として実行した場合は、システムドメインを対象とします。</p>

<dl><dt><em>load</em> | <em>unload</em> [<code>-wF</code>] [<code>-S</code> <em>sessiontype</em>] [<code>-D</code> <em>searchpath</em>] <em>paths ...</em></dt><dd><p>推奨される代替サブコマンド: <em>bootstrap</em> | <em>bootout</em> | <em>enable</em> | <em>disable</em></p>
<p>指定した設定ファイル、または設定ファイルを収めたディレクトリを読み込みます。オンデマンドではないジョブは、可能な限り早く起動されます。指定したすべてのジョブが読み込まれるまで、どのジョブも起動を許可されません。ユーザー単位の設定ファイル（LaunchAgents）は、<code>/Library/LaunchAgents</code> にある場合は root が、<code>$HOME/Library/LaunchAgents</code> にある場合はそれを読み込むユーザーが所有していなければなりません。システム全体のデーモン（LaunchDaemons）は、すべて root が所有していなければなりません。設定ファイルは、グループおよびその他のユーザーによる書き込みを許可してはいけません。この制限はセキュリティ上の理由によるものです。launchd の設定ファイルへの書き込みを許すと、起動する実行ファイルを指定できてしまうためです。</p>
<p><code>/System/Library/LaunchDaemons</code> ディレクトリへの root 以外の書き込みアクセスを許可すると、システムは必ず起動不能になることに注意してください。</p>

## 注意事項 {#CAVEATS}


<p>「旧式」のサブコマンド（主に <em>list</em>）が生成する出力は、以前の OS X リリースでの出力と一致するはずです。ただし、新しいサブコマンドの出力は特定の形式に準拠しておらず、リリース間で安定したままである保証はありません。これらのコマンドは、人間である開発者やシステム管理者が使用するためのものであり、プログラムやスクリプトによる自動化を目的としていません。その出力は API を構成するものではなく、出力を解析しようとするプログラムに対して前方互換性は一切保証されません。</p>

## 非推奨および削除された機能 {#DEPRECATED_AND_REMOVED_FUNCTIONALITY}


<p><code>launchctl</code> には対話モードがなくなり、標準入力からのコマンドも受け付けなくなりました。ブート初期に実行するサブコマンドの取得元として <code>/etc/launchd.conf</code> ファイルが参照されることもなくなりました。この機能はセキュリティ上の配慮から削除されました。ユーザーセッションを設定する前に <code>$HOME/.launchd.conf</code> が参照されると文書化されていましたが、この機能が実装されたことはありません。</p>

<p>launchd は通信に Unix ドメインソケットを使用しなくなったため、<code>LAUNCHD_SOCKET</code> 環境変数はもはや意味を持たず、設定されません。</p>

<p><code>launchd</code> はネットワークから設定ファイルを読み込まなくなりました。</p>

## ファイル {#FILES}


<dl><dt>~/Library/LaunchAgents</dt><dd><p>ユーザーが提供する、ユーザー単位のエージェント。</p></dd><dt>/Library/LaunchAgents</dt><dd><p>管理者が提供する、ユーザー単位のエージェント。</p></dd><dt>/Library/LaunchDaemons</dt><dd><p>管理者が提供する、システム全体のデーモン。</p></dd><dt>/System/Library/LaunchAgents</dt><dd><p>OS X のユーザー単位のエージェント。</p></dd><dt>/System/Library/LaunchDaemons</dt><dd><p>OS X のシステム全体のデーモン。</p></dd></dl>

## 終了ステータス {#EXIT_STATUS}


<p>サブコマンドが成功した場合、<code>launchctl</code> はステータス 0 で終了します。それ以外の場合は、<em>error</em> サブコマンドに渡して人が読める形式に変換できるエラーコードで終了します。</p>
