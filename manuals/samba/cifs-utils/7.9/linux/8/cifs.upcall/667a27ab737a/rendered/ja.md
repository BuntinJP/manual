## cifs\.upcall {#cifs-upcall}


### Common Internet File System（CIFS）用のユーザー空間 upcall ヘルパー {#Userspace-upcall-helper-for-Common-Internet-File-System--CIFS}


<dl><dt>マニュアルのセクション:</dt><dd><p>8</p></dd></dl>

#### 書式 {#SYNOPSIS}


<blockquote><dl><dt>cifs.upcall [<code>--trust-dns</code>|<code>-t</code>] [<code>--version</code>|<code>-v</code>] [<code>--legacy-uid</code>|<code>-l</code>] [<code>--debug</code>|<code>-d</code>]</dt><dd><p>[<code>--krb5conf</code>=/path/to/krb5.conf|<code>-k</code> /path/to/krb5.conf] [<code>--keytab</code>=/path/to/keytab|<code>-K</code> /path/to/keytab] [<code>--expire</code>|<code>-e</code> nsecs] {keyid}</p></dd></dl></blockquote>

#### 説明 {#DESCRIPTION}


<p>このツールは cifs-utils スイートの一部です。</p>

<p>cifs.upcall は Linux CIFS クライアントファイルシステム用のユーザー空間ヘルパープログラムです。カーネル自身では容易に実行できない処理がいくつかあります。このプログラムはそれらをカーネルに代わって行い、結果を返す呼び出し先プログラムです。</p>

<p>cifs.upcall は通常、特定のキータイプに対してカーネルが request-key(8) を呼び出したときに実行することを想定しています。コマンドラインから直接実行することもできますが、通常はそのような実行を意図していません。</p>

#### オプション {#OPTIONS}


<dl><dt><code>-c</code></dt><dd><p>このオプションは非推奨で、現在は無視されます。</p></dd></dl>

<dl><dt><code>--debug</code>|<code>-d</code></dt><dd><p>デバッグログを有効にします。既定ではデバッグメッセージは記録せず、エラーだけを記録します。</p></dd><dt><code>--no-env-probe</code>|<code>-E</code></dt><dd><p>通常、cifs.upcall は upcall を開始したプロセスの環境変数領域を調べ、$KRB5CCNAME の値を取得します。これにより、既定以外の場所にある資格情報キャッシュを見つけやすくなります。このオプションを設定すると、この調査を行わず、<em>krb5.conf</em> に指定された既定の場所で資格情報キャッシュを探します。UID が0の場合、この調査は決して行わないことに注意してください。UID が0の場合、プロセスの環境変数の設定に関係なく、常に既定の資格情報キャッシュの場所を使います。</p></dd><dt><code>--krb5conf</code>|<code>-k</code>=/path/to/krb5.conf</dt><dd><p>管理者は、このオプションで cifs.upcall が使用する <em>krb5.conf</em> ファイルの場所を変更できます。</p></dd><dt><code>--keytab</code>=|<code>-K</code>=/path/to/keytab</dt><dd><p>管理者は、このオプションで使用する keytab ファイルを指定できます。ユーザーがまだ資格情報キャッシュを確立していない場合、cifs.upcall はこの keytab を使って資格情報を取得しようとします。既定値はシステム全体の keytab <em>/etc/krb5.keytab</em> です。</p></dd><dt><code>--trust-dns</code>|<code>-t</code></dt><dd><p>krb5 upcall では、サービスプリンシパルのホスト部分に使用する名前は、既定で UNC のホスト名部分です。このオプションを使うと、upcall プログラムはサーバーのネットワークアドレスを逆引きしてホスト名を取得します。</p>
<p>これは DNS を信頼しない場合より安全性が低くなります。このオプションを使うと、攻撃者が DNS を掌握してクライアントをだまし、まったく別のサーバーをマウントさせる可能性があります。代わりに、あり得るすべてのホスト名について KDC にサーバープリンシパルを追加する方が望ましいですが、それができない場合のためにこのオプションがあります。既定では、このようなホスト名の逆引きを信頼しません。</p></dd><dt><code>--legacy-uid</code>|<code>-l</code></dt><dd><p>従来、カーネルは使用するユーザーの資格情報キャッシュを決める SPNEGO upcall に、単一の uid= パラメーターだけを送信していました。このパラメーターは、マウント上のファイルの所有者も制御する uid= マウントオプションの影響を受けます。</p>
<p>新しいカーネルは creduid= オプションも送信します。これには、探している資格情報を実際に所有するとカーネルが判断した UID が含まれます。マウント時は通常、マウントを行うユーザーの実 UID に設定されます。マルチセッションマウントでは、マウントユーザーの fsuid に設定されます。cifs.upcall に creduid= ではなく従来の uid= パラメーターを使わせるには、このオプションを設定します。</p></dd><dt><code>--expire</code>|<code>-e</code></dt><dd><p>dns_resolver キーの既定のタイムアウト値（600秒）を変更します。</p></dd><dt><code>--version</code>|<code>-v</code></dt><dd><p>バージョン番号を表示して終了します。</p></dd></dl>

#### 環境変数 {#ENVIRONMENT-VARIABLES}


<dl><dt>GSS_USE_PROXY=&quot;yes&quot;</dt><dd><p>資格情報の取得に gssproxy を使用します。これには keytab ベースのクライアント開始処理と、（リソースベースの）制約付き委任が含まれます。gssproxy-mech(8) を参照してください。</p></dd></dl>

#### KEYCTL の設定 {#CONFIGURATION-FOR-KEYCTL}


<p>cifs.upcall は、request-key 呼び出し先プログラムを介してカーネルから呼び出されるよう設計されています。そのため、request-key に、このプログラムをどこでどのように呼び出すかを知らせる必要があります。現在の cifs.upcall は、次の2種類のキータイプを扱います。</p>

<dl><dt>cifs.spnego</dt><dd><p>このキータイプは Kerberos セッションキーの取得用です。</p></dd><dt>dns_resolver</dt><dd><p>このキータイプはホスト名を IP アドレスへ解決するためのものです。このキータイプへの対応は将来非推奨になる可能性があります（後述）。</p>
<p>このプログラムを CIFS で利用するには、request-key.conf(5) にこれらのエントリーを設定する必要があります。各キータイプのエントリー例を示します。</p>
<pre><code>#OPERATION  TYPE           D C PROGRAM ARG1 ARG2...&#10;#=========  =============  = = ================================&#10;create      cifs.spnego    * * @sbindir@/cifs.upcall %k&#10;create      dns_resolver   * * @sbindir@/cifs.upcall %k</code></pre>
<p>各フィールドの詳細は request-key.conf(5) を参照してください。</p>
<p>keyutils パッケージにも dns_resolver を処理するプログラムが含まれるようになり、cifs.upcall のものより優先されます。keyutils のバージョン1.5以降を使用する場合は、dns_resolver キータイプの処理に cifs.upcall ではなく key.dns_resolver を使用してください。詳細は key.dns_resolver(8) を参照してください。</p></dd></dl>
