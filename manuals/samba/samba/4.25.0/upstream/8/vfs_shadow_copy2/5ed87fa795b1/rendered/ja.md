### 名前 {#Name}


<p>vfs_shadow_copy2 — スナップショットをシャドウコピーとして Windows クライアントに公開する</p>

### 書式 {#Synopsis}


<p><code>vfs objects = shadow_copy2</code></p>

### 説明 {#DESCRIPTION}


<p>この VFS モジュールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p><code>vfs_shadow_copy2</code> VFS モジュールは Microsoft Shadow Copy サービスに似た機能を提供します。適切に設定すると、Microsoft Shadow Copy クライアントが Samba 共有上のファイルシステムのスナップショットを「シャドウコピー」として閲覧できるようになります。</p>

<p>これはシャドウコピーモジュールの 2 番目の実装であり、元の <a href="https://www.samba.org/samba/docs/current/man-html/shadow_copy.8.html">shadow_copy(8)</a> モジュールと比べて次の追加機能があります。</p>

<ol><li><p>ファイルシステムがスナップショットを別の場所に保存する場合でも、共有のルートディレクトリーにスナップショットへのシンボリックリンクを配置する必要はなくなりました。代わりに、ファイルシステムのスナップショットを探す場所を柔軟に設定できます。共有が数千ある場合や [homes] を使用する場合には、特に重要です。</p></li><li><p>スナップショットディレクトリーは、中央の固定された 1 か所に置く必要はなく、ディレクトリーツリーのどこにでも配置できます。このモードは、GPFS の独立ファイルセットなど、特定のサブツリーのスナップショットを作成できるファイルシステムへの対応に役立ちます。</p></li><li><p>スナップショット名のカスタマイズ: str[fp]time 変換と互換性のある任意の形式で名前を付けられます。</p></li><li><p>タイムスタンプを UTC ではなくローカル時刻で表現できます。</p></li><li><p>ファイルの inode 番号を、元のものと異なる値に変更することもできます。これにより、GPFS のようにスナップショット内のファイルと元のファイルに同じデバイス番号と inode 番号を返すファイルシステムで、Windows GUI の「復元」ボタンが共有違反を起こさずに動作するようになります。</p></li><li><p>既定では、シャドウコピーの結果を並べ替えてからクライアントに送信します。これは、ディレクトリーをアルファベット順に読み取らないファイルシステム（Unix の既定の動作）で役立ちます。並べ替え順序は設定でき、ファイルシステムがディレクトリー一覧を整列する場合は、並べ替えを完全に無効にできます。</p></li></ol>

<p>このモジュールは、他のモジュールと重ねて使用できます。</p>

### 設定 {#CONFIGURATION}


<p><code>vfs_shadow_copy2</code> はファイルシステムのスナップショット実装に依存します。一般的なファイルシステムの多くは、この機能を標準でサポートしています。</p>

<p><code>vfs_shadow_copy2</code> が認識できるようにするには、特別な名前のディレクトリーの下でファイルシステムのスナップショットを利用できる必要があります。通常、このディレクトリーは共有ルートのマウントポイントの直接のサブディレクトリーですが、以下で詳述するパラメーターで設定できるほかのモードもあります。</p>

<p>ある時点のスナップショットは、スナップショットディレクトリーのサブディレクトリーにあり、そのディレクトリー名はスナップショット時刻を整形したものと想定します。<code>shadow:format</code> オプションで変更できる既定の形式は @GMT-YYYY.MM.DD-hh.mm.ss です。各部分の意味は次のとおりです。</p>

<ul><li><p><code>YYYY</code> は4桁の年</p></li><li><p><code>MM</code> は2桁の月</p></li><li><p><code>DD</code> は2桁の日</p></li><li><p><code>hh</code> は2桁の時</p></li><li><p><code>mm</code> は2桁の分</p></li><li><p><code>ss</code> は2桁の秒です。</p></li></ul>

<p><code>vfs_shadow_copy2</code> のスナップショット命名形式は、次の <a href="https://www.samba.org/samba/docs/current/man-html/date.1.html">date(1)</a> コマンドで生成できます。</p>

<pre><code>	TZ=GMT date +@GMT-%Y.%m.%d-%H.%M.%S</code></pre>

### オプション {#OPTIONS}


<dl><dt>shadow:mountpoint = MOUNTPOINT</dt><dd><p>このパラメーターは、共有パスを含むファイルシステムのマウントポイントを指定します。通常は自動検出されますが、特定の構成、特にテストでは指定できると便利です。</p>
<p>例: shadow:mountpoint = /path/to/filesystem</p>
<p>既定値: shadow:mountpoint = 未指定</p></dd><dt>shadow:snapdir = SNAPDIR</dt><dd><p>共有のファイルシステムがスナップショットを保持するディレクトリーへのパスです。絶対パスはそのまま使用します。相対パスは、共有ルートのファイルシステムのマウントポイントからの相対パスとして扱います（<code>shadow:mountpoint</code> を参照）。</p>
<p><code>shadow:snapdirseverywhere</code> はこのパラメーターに依存し、相対パスを必要とします。絶対パスを設定すると <code>shadow:snapdirseverywhere</code> は無効になります。</p>
<p><code>shadow:crossmountpoints</code> オプションも相対 snapdir を必要とします。絶対パスを設定すると <code>shadow:crossmountpoints</code> は無効になります。</p>
<p>例: shadow:snapdir = /some/absolute/path</p>
<p>既定値: shadow:snapdir = .snapshots</p></dd><dt>shadow:basedir = BASEDIR</dt><dd><p>basedir オプションは、共有のマウントポイントと共有ルートの間にあるディレクトリーを指定でき、ファイルシステムのスナップショットはそのディレクトリーを基準に作成されます。</p>
<p>たとえば、次の設定の場合、</p>
<ul><li><p><code>basedir = mountpoint/rel_basedir</code></p></li><li><p><code>share_root = basedir/rel_share_root</code></p></li><li><p><code>snapshot_path = mountpoint/snapdir</code></p>
<p>または、snapdir が絶対パスなら <code>snapshot_path = snapdir</code></p></li></ul>
<p>時刻 TIME における <code>file = mountpoint/rel_basedir/rel_share_root/rel_file</code> のスナップショットは <code>snapshot_path/FS_GMT_TOKEN(TIME)/rel_share_root/rel_file</code> の下にあります。FS_GMT_TOKEN(TIME) は、ファイルシステムが必要とする形式で TIME を表すタイムスタンプ文字列です（<code>shadow:format</code> を参照）。</p>
<p>basedir の既定値は、共有ルートのファイルシステムのマウントポイントです（<code>shadow:mountpoint</code> を参照）。</p>
<p><code>shadow:snapdirseverywhere</code> と <code>shadow:crossmountpoints</code> の各オプションは <code>shadow:basedir</code> と互換性がなく、basedir 設定を無効にします。</p></dd><dt>shadow:snapsharepath = SNAPSHAREPATH</dt><dd><p>このパラメーターは、スナップショットのルートディレクトリーを基準として、その中の共有ルートディレクトリーへの相対パスを指定します。<code>shadow:basedir</code> に代わる方法で、より細かく制御できます。</p>
<p>たとえば、各スナップショット内で共有のファイルのパスに <code>path/to/share/</code> という接頭辞がある場合、<code>shadow:snapsharepath</code> を <code>path/to/share</code> に設定できます。</p>
<p>このパラメーターを使用すると、スナップショットが元のファイルシステムまたはその一部のイメージであるとは想定しなくなります。たとえば、共有に含まれるファイルだけをバックアップし、そのバックアップファイルを次の論理構造で公開するシステムも考えられます。</p>
<ul><li><p>share1/</p></li><li><p>share2/</p></li><li><p>.../</p></li></ul>
<p><code>shadow:snapdirseverywhere</code> と <code>shadow:basedir</code> の各オプションは <code>shadow:snapsharepath</code> と互換性がなく、<code>shadow:snapsharepath</code> 設定を無効にします。</p>
<p>例: shadow:snapsharepath = path/to/share</p>
<p>既定値: shadow:snapsharepath = 未指定</p></dd><dt>shadow:sort = asc/desc</dt><dd><p>既定では、シャドウコピーのデータをアルファベット順に並べ替えてからクライアントに送信します。このパラメーターで並べ替え順序を指定できます。認識する値は desc（降順、既定値）と asc（昇順）です。ファイルシステムがディレクトリーをアルファベット順に一覧表示する場合、その他の値を指定すると、このモジュールでの並べ替えを無効にできます。</p>
<p>例: shadow:sort = asc</p>
<p>例: shadow:sort = none</p>
<p>既定値: shadow:sort = desc</p></dd><dt>shadow:localtime = yes/no</dt><dd><p>スナップショット名が UTC/GMT かローカル時刻かを示す任意のパラメーターです。無効な場合は UTC/GMT と想定します。</p>
<p>shadow:localtime = no</p></dd><dt>shadow:format = スナップショット名の書式指定</dt><dd><p>ファイルシステム内のスナップショット名の書式を指定する任意のパラメーターです。書式は str[fp]time が認識する変換指定と互換性がなければなりません。</p>
<p>既定値: shadow:format = &quot;@GMT-<code>%Y</code>.<code>%m</code>.<code>%d</code>-<code>%H</code>.<code>%M</code>.<code>%S</code>&quot;</p></dd><dt>shadow:sscanf = yes/no</dt><dd><p>このパラメーターを使用すると、書式文字列内の時刻が、strptime() で解析できる時刻ではなく unsigned long 整数（<code>%l</code>u）であることを指定できます。結果は Unix time_t の時刻でなければなりません。</p>
<p>既定値: shadow:sscanf = no</p></dd><dt>shadow:fixinodes = yes/no</dt><dd><p><code>shadow:fixinodes</code> を有効にすると、スナップショットディレクトリー内のファイルの見かけの inode 番号を、ファイルパスのハッシュを使って変更します。GPFS スナップショットのように、スナップショットが元のファイルと同じ device:inode 番号を持つシステムで必要です。このオプションを設定しないと、シャドウコピー UI の「復元」ボタンは共有違反で失敗します。</p>
<p>既定値: shadow:fixinodes = no</p></dd><dt>shadow:snapdirseverywhere = yes/no</dt><dd><p><code>shadow:snapdirseverywhere</code> を有効にすると、現在の作業ディレクトリーとすべての親ディレクトリーでスナップショットディレクトリーを探し、既定ではマウントポイントで停止します。この動作を変える方法については <code>shadow:crossmountpoints</code> を参照してください。</p>
<p>必要になる例として IBM GPFS の独立ファイルセットがありますが、ほかのファイルシステムでも特定のサブツリーだけのスナップショット作成をサポートする場合があります。</p>
<p><code>shadow:snapdirseverywhere</code> は <code>shadow:snapdir</code> に依存し、その値が相対パスであることを必要とします。snapdir に絶対パスを設定すると <code>shadow:snapdirseverywhere</code> は無効になります。</p>
<p>このオプションは <code>shadow:basedir</code> オプションと互換性がなく、それ自体で <code>shadow:basedir</code> 設定を取り除きます。</p>
<p>例: shadow:snapdirseverywhere = yes</p>
<p>既定値: shadow:snapdirseverywhere = no</p></dd><dt>shadow:crossmountpoints = yes/no</dt><dd><p>このオプションは <code>shadow:snapdirseverywhere = yes</code> の場合に有効です。設定すると、snapdir を探す際に最初に見つかったマウントポイントで停止せず、代わりにパス全体にわたって検索できるようになります。</p>
<p>必要になる例として IBM GPFS の独立ファイルセットがありますが、ほかのファイルシステムでも特定のサブツリーだけのスナップショット作成をサポートする場合があります。</p>
<p><code>shadow:crossmountpoints</code> は <code>shadow:snapdir</code> に依存し、その値が相対パスであることを必要とします。snapdir に絶対パスを設定すると <code>shadow:crossmountpoints</code> は無効になります。</p>
<p>このオプションは <code>shadow:basedir</code> オプションと互換性がなく、それ自体で <code>shadow:basedir</code> 設定を取り除きます。</p>
<p>例: shadow:crossmountpoints = yes</p>
<p>既定値: shadow:crossmountpoints = no</p></dd><dt>shadow:snapprefix</dt><dd><p>スナップショット数が増えると、月次、週次、手動、特別なイベントなど、スナップショットの集合を区別する仕組みがファイルシステムに必要になります。そのため、時刻だけに基づかない名前を設定できる仕組みなど、スナップショットにタグを付けるさまざまな方法を提供しています。<code>shadow:format</code> だけでこれらを絞り込むことは非常に困難です。この任意のパラメーターは、ファイルシステム内のスナップショットディレクトリー名の可変の接頭辞部分を指定します。設定されている場合、<code>shadow:format</code> および <code>shadow:delimiter</code> と合わせて、使用可能なスナップショットディレクトリー名を決定します。このオプションは基本正規表現 (BRE) のみをサポートします。</p></dd><dt>shadow:delimiter</dt><dd><p>この任意のパラメーターは <code>shadow:snapprefix</code> と <code>shadow:format</code> の間の区切り文字として使用します。<code>shadow:snapprefix</code> が設定されている場合にのみ使用します。</p>
<p>既定値: shadow:delimiter = &quot;_GMT&quot;</p></dd></dl>

### 例 {#EXAMPLES}


<p>ユーザーのホームディレクトリにシャドウコピーのサポートを追加します。</p>

<pre><code>        [homes]
	vfs objects = shadow_copy2
	shadow:snapdir = /data/snapshots
	shadow:basedir = /data/home
	shadow:sort = desc</code></pre>

### 注意事項 {#CAVEATS}


<p>これはバックアップ、アーカイブ、バージョン管理のためのソリューションではありません。</p>

<p>Samba サーバーでも Windows サーバーでも、<code>vfs_shadow_copy2</code> はエンドユーザー向けのツールとしてのみ設計されています。バックアップやアーカイブの仕組みを置き換えたり強化したりするものではなく、そのように考えるべきではありません。また、バージョン管理が必要な場合は、バージョン管理システムを導入してください。</p>
