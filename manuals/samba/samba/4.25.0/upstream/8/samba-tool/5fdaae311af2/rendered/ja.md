### 名前 {#Name}


<p>samba-tool — Samba の主要な管理ツール</p>

### 書式 {#Synopsis}


<p><code>samba-tool</code> [<code>-h</code>] [<code>-W</code> myworkgroup] [<code>-U</code> user] [<code>-d</code> debuglevel] [<code>-V</code>]</p>

### 説明 {#DESCRIPTION}


<p>このツールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

### オプション {#OPTIONS}


<p>samba-tool は多数のサブコマンドからなり、それぞれ固有のオプションを持ちます。この節では、複数のサブコマンドに共通するオプションを示します。</p>

<dl><dt><code>-h</code>|<code>--help</code></dt><dd><p>ヘルプメッセージを表示して終了します。</p></dd><dt><code>-r</code>|<code>--realm</code>=REALM</dt><dd><p>ドメインの realm を設定します。</p>
<p>ここでこのパラメーターを指定すると、<code>${prefix}/etc/smb.conf</code> ファイルの <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#REALM">realm</a> パラメーターを上書きします。</p></dd><dt><code>--simple-bind-dn</code>=DN</dt><dd><p>単純バインドに使う DN です。</p></dd><dt><code>--password</code></dt><dd><p>コマンドラインでパスワードを指定します。</p>
<p>スクリプトにパスワードを含めたり、ユーザーが入力した値をコマンドラインへ渡したりする際は注意してください。安全性のため、必要に応じて Samba クライアントツールにパスワードを尋ねさせるか、<code>kinit</code> で一度パスワードを取得する方が適切です。</p>
<p><code>--password</code> を指定しない場合、ツールは <code>PASSWD</code> 環境変数を調べ、次に、開いたファイル記述子（FD）の番号を含むはずの <code>PASSWD_FD</code> を調べます。</p>
<p>最後に、開くファイルのパスを含む <code>PASSWD_FILE</code> を調べます。そのファイルにはパスワードだけを含めてください。ファイルのアクセス権で、意図しないユーザーからのアクセスを確実に制限してください。</p>
<p>Samba はプロセスタイトル（ps に表示されるもの）からパスワードを消去しようとしますが、起動後に行うため競合状態が生じます。</p></dd><dt><code>-U</code>|<code>--user</code>=[DOMAIN\]USERNAME[<code>%P</code>ASSWORD]</dt><dd><p>SMB ユーザー名、またはユーザー名とパスワードを設定します。</p>
<p><code>%P</code>ASSWORD を指定しない場合、ユーザーに入力を求めます。クライアントは最初に <code>USER</code> 環境変数（% で区切ったパスワードを含めることも可能）、次に <code>LOGNAME</code> 変数（パスワードを含めることは不可）を調べ、どちらかがあればその値を使います。これらの環境変数がない場合、Kerberos 資格情報キャッシュにあるユーザー名を使うことがあります。</p>
<p>3つ目の方法は、ユーザー名とパスワードを平文で含む資格情報ファイルを使うことです。主に、管理者がコマンドラインや環境変数で資格情報を渡したくないスクリプト向けです。この方法を使う場合、ファイルのアクセス権で、意図しないユーザーからのアクセスを確実に制限してください。詳しくは <em><code>-A</code></em> を参照してください。</p>
<p>スクリプトにパスワードを含めたり、ユーザーが入力した値をコマンドラインへ渡したりする際は注意してください。安全性のため、必要に応じて Samba クライアントツールにパスワードを尋ねさせるか、<code>kinit</code> で一度パスワードを取得する方が適切です。</p>
<p>Samba はプロセスタイトル（ps に表示されるもの）からパスワードを消去しようとしますが、起動後に行うため競合状態が生じます。</p></dd><dt><code>-W</code>|<code>--workgroup</code>=WORKGROUP</dt><dd><p>ユーザー名の SMB ドメインを設定します。smb.conf で定義された既定のドメインを上書きします。指定したドメインがサーバーの NetBIOS 名と同じ場合、クライアントはドメイン SAM ではなく、サーバーのローカル SAM を使ってログオンします。</p>
<p>ここでこのパラメーターを指定すると、<code>${prefix}/etc/smb.conf</code> ファイルの <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#WORKGROUP">workgroup</a> パラメーターを上書きします。</p></dd><dt><code>-N</code>|<code>--no-pass</code></dt><dd><p>指定すると、クライアントが通常ユーザーに表示するパスワード入力要求を抑止します。パスワードを必要としないサービスへのアクセスに役立ちます。</p>
<p>コマンドラインでパスワードを指定せず、このパラメーターも指定していない場合、クライアントはパスワードを要求します。</p>
<p>コマンドラインでパスワードを指定し、このオプションも指定した場合、コマンドラインのパスワードは通知なく無視され、パスワードは使用されません。</p></dd><dt><code>--use-kerberos</code>=desired|required|off</dt><dd><p>Samba クライアントツールが Kerberos 認証を試みるかどうかを指定します。Kerberos 認証では、サービスへの接続時に IP アドレスではなく DNS 名を使ってください。既定では、Samba クライアントツールは既定の Kerberos 資格情報キャッシュ（ccache）を使おうとします。ccache がない場合、または <code>-U</code>|<code>--user</code> オプションを指定した場合、クライアントはパスワード入力を求め、Kerberos チケットを取得します（kinit）。別の Kerberos 資格情報キャッシュを使う場合は <code>--use-krb5-ccache</code> オプションを指定してください。</p>
<p>ここでこのパラメーターを指定すると、<code>${prefix}/etc/smb.conf</code> ファイルの <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#CLIENTUSEKERBEROS">client use kerberos</a> パラメーターを上書きします。</p></dd><dt><code>--use-krb5-ccache</code>=CCACHE</dt><dd><p>Kerberos 認証の資格情報キャッシュの場所を指定します。</p>
<p><code>--use-kerberos</code>=required を強制します。</p></dd><dt><code>-A</code>|<code>--authentication-file</code>=filename</dt><dd><p>接続に使うユーザー名とパスワードを読み取るファイルを指定できます。ファイルの形式は次のとおりです。</p>
<pre><code>				username = &lt;value&gt;
				password = &lt;value&gt;
				domain   = &lt;value&gt;
			</code></pre>
<p>ファイルのアクセス権で、意図しないユーザーからのアクセスを確実に制限してください。</p></dd><dt><code>-H</code> URL, <code>--URL</code>=URL</dt><dd><p>データベースまたは対象サーバーの LDB URL。</p>
<p>URL は単なるファイルパスか、次に示すスキームを指定できます。単なるパスは &#39;tdb://&#39; を使った場合と同じに扱います。</p>
<dl><dt>tdb://PATH</dt><dd><p>PATH は TDB データベースの場所です。</p></dd><dt>mdb://PATH</dt><dd><p>PATH は LMDB データベースの場所です。</p></dd><dt>ldb://PATH</dt><dd><p>PATH は LMDB または TDB 形式の LDB データベースの場所です。成功するかすべて失敗するまで、順に形式を試します。ファイル形式が不明な場合も安全に使えます。</p></dd><dt>ldap://HOSTNAME, ldaps://HOSTNAME</dt><dd><p>指定した LDAP サーバーを LDB バックエンドにします。ldaps:// は接続を TLS で包みます。</p></dd><dt>ldapi://SOCKET</dt><dd><p>バックエンドは UNIX ドメインソケットを使うローカル LDAP サーバーです。</p></dd></dl></dd><dt><code>--color</code>=always|never|auto</dt><dd><p>利用可能なら色を使います（既定値: auto）。</p></dd><dt><code>--ipaddress</code>=IPADDRESS</dt><dd><p>サーバーの IP アドレス。</p></dd><dt><code>-s</code> FILE, <code>--configfile</code>=FILE</dt><dd><p>この smb.conf 設定ファイルを使います。</p></dd><dt><code>--color</code>=always|never|auto</dt><dd><p>出力に ANSI カラーコードを使うか指定します。&#39;auto&#39;（既定）では、出力先が端末なら色を使います。ただし NO_COLOR 環境変数が設定され、空でない場合は使いません。</p>
<p>&#39;yes&#39; と &#39;force&#39; は &#39;always&#39;、&#39;no&#39; と &#39;none&#39; は &#39;never&#39;、&#39;tty&#39; と &#39;if-tty&#39; は &#39;auto&#39; の同義語です。</p>
<p>色を要求しても、必ずしも多彩な出力になるわけではありません。多くのコマンドは、特に成功時には単色です。</p></dd><dt><code>-V</code>, <code>--version</code></dt><dd><p>バージョン番号を表示して終了します。</p></dd><dt><code>-d</code>|<code>--debuglevel</code>=level</dt><dd><p><em><code>level</code></em> は0から10の整数です。このパラメーターを指定しない場合、クライアントアプリケーションの既定値は1です。</p>
<p>値を大きくすると、サーバーの動作についてログファイルに記録する詳細が増えます。レベル0では重大なエラーと深刻な警告だけを記録します。レベル1は日常的な運用に適しており、実行した操作について少量の情報を生成します。</p>
<p>1より上のレベルは大量のログデータを生成するため、問題の調査時だけ使ってください。3より上は開発者専用に設計されており、大部分が非常に難解な、極めて大量のログデータを生成します。</p>
<p>ここでこのパラメーターを指定すると、<code>${prefix}/etc/smb.conf</code> ファイルの <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#LOGLEVEL">log level</a> パラメーターを上書きします。</p></dd><dt><code>--debug-stdout</code></dt><dd><p>デバッグ出力を STDOUT へリダイレクトします。既定ではすべてのクライアントは STDERR にログを出します。</p></dd></dl>

##### computer keytrust add computername public-key-or-certificate\[options\] {#computer-keytrust-add-computername-public-key-or-certificate-options}


<p>バイナリーフィールドに公開鍵を保持するリンク属性 key-credential-link を追加します。</p>

<p>第2引数は、PEM または DER 形式の2048ビット RSA 鍵、またはその鍵を含む証明書を指すファイル名です。既定では符号化形式を自動検出しますが、<code>--encoding</code> オプションで上書きを試みることもできます。他種の公開鍵は非対応ですが、<code>--force</code> オプションで2048ビット以外の鍵を追加できます。</p>

<dl><dt><code>--link-target</code>=DN</dt><dd><p>この DN へリンクします（既定: コンピューターの DN）。</p></dd><dt><code>--encoding</code>=ENCODING</dt><dd><p>鍵形式は <code>pem</code>、<code>der</code>、<code>auto</code> のいずれかです。既定の <code>auto</code> は、ほぼどの状況でも正しい形式を検出すると考えられます。</p></dd><dt><code>--force</code></dt><dd><p>失敗しそうに見える操作も続行します。</p></dd></dl>

##### computer keytrust delete computername \[options\] {#computer-keytrust-delete-computername--options}


<p>key-credential-link を削除します。</p>

<p>削除するリンクには複数の選択方法があります。<code>--all</code> はコンピューターの全リンクを削除します（多くの場合は1つだけです）。<code>--link-target</code> はリンク先 DN、<code>--fingerprint</code> は鍵のフィンガープリントで選択します。フィンガープリントは DER 符号化した鍵素材の SHA256 をコロン区切りの16進数ペアで表したものです。リンクとフィンガープリントの一覧は <code>computer keytrust view</code> で確認できます。</p>

<p><code>--link-target</code>、<code>--fingerprint</code>、<code>--all</code> の複数を使うと、いずれかに一致するリンクを削除します。</p>

<p><code>--dry-run</code> オプションを使うと削除は行わず、省略した場合に何が起きるかを表示します。</p>

<dl><dt><code>--link-target</code>=DN</dt><dd><p>この DN の Key Credential Link を削除します。</p></dd><dt><code>--fingerprint</code>=HH:HH:..</dt><dd><p>この鍵フィンガープリントの Key Credential Link を削除します。</p></dd><dt><code>--all</code></dt><dd><p>すべての Key Credential Link を削除します。</p></dd><dt><code>-n</code>, <code>--dry-run</code></dt><dd><p>何も変更せず、何が起きるかだけを表示します。</p></dd></dl>

<dl><dt><code>-h</code>, <code>--help</code></dt><dd><p>このヘルプメッセージを表示して終了します。</p></dd><dt><code>-v</code>, <code>--verbose</code></dt><dd><p>詳細に出力します。</p></dd></dl>

##### user add username \[password\] {#user-add-username--password}

##### user addunixattrs username uid-number \[options\] {#user-addunixattrs-username-uid-number--options}


<p>ユーザーに RFC2307 属性を追加します。</p>

<p>Active Directory ドメインのユーザーアカウントに Unix 属性を追加します。</p>

<p>指定する username は sAMaccountName です。</p>

<p>一意の UID を指定する必要があります。</p>

<p>ユーザーアカウントに Unix（RFC2307）属性を追加します。</p>

<p>&#39;<code>--gid-number</code>&#39; でグループIDを指定すると、ユーザーの Unix &#39;gidNumber&#39; 属性に使います。</p>

<p>&#39;<code>--gid-number</code>&#39; を指定しない場合、&#39;Domain Users&#39; の gidNumber を使います。そのため Domain Users に gidNumber 属性が必要です。</p>

<p>&#39;<code>--unix-home</code>&#39; を指定しない場合、Unix ホームディレクトリは /home/DOMAIN/username になります。</p>

<p>&#39;<code>--login-shell</code>&#39; を指定しない場合、Unix ログインシェルは &#39;/bin/sh&#39; になります。</p>

<p>---gecos&#39; を指定しない場合、Unix gecos フィールドはユーザーの &#39;CN&#39; 属性になります。</p>

<p>UID/GID 対応付けに使うには、DC の smb.conf に &#39;idmap_ldb:use rfc2307 = Yes&#39; を追加します。</p>

<p>root または許可された別のユーザーIDで実行できます。<code>-H</code> または <code>--URL</code>= オプションで、リモートサーバーに対して実行できます。</p>

<p>例1:</p>

<pre><code>samba-tool user addunixattrs User1 10001</code></pre>

<p>例1は、ドメインで有効なユーザーアカウントへ RFC2307 属性を追加し、Domain Users をユーザーの gidNumber とする方法です。</p>

<p>未使用ならユーザーの Unix ID を &#39;10001&#39; に設定します。</p>

<p>例2:</p>

<pre><code>samba-tool user addunixattrs User2 10002 --gid-number=10001 --unix-home=/home/User2</code></pre>

<p>例2は、ドメインで有効なユーザーアカウントへ RFC2307 属性を追加する方法です。</p>

<p>未使用ならユーザーの Unix ID を &#39;10002&#39; に設定します。</p>

<p>ユーザーの gidNumber 属性を &#39;10001&#39; に設定します。</p>

<p>ユーザーの Unix ホームディレクトリを &#39;/home/user2&#39; に設定します。</p>

<p>例3:</p>

<pre><code>samba-tool user addunixattrs User3 10003 --gid-number=10001 --login-shell=/bin/false --gecos=&#39;User3 test&#39;</code></pre>

<p>例3は、ドメインで有効なユーザーアカウントへ RFC2307 属性を追加する方法です。</p>

<p>未使用ならユーザーの Unix ID を &#39;10003&#39; に設定します。gidNumber 属性は &#39;10001&#39;、Unix ログインシェルは &#39;/bin/false&#39;、gecos フィールドは &#39;User3 test&#39; に設定します。</p>

<dl><dt><code>-H</code> URL, <code>--URL</code>=URL</dt><dd><p>データベースまたは対象サーバーの LDB URL。</p></dd><dt><code>--gid-number</code>=GROUP_ID</dt><dd><p>ユーザーの Unix/RFC2307 GID。</p></dd><dt><code>--unix-home</code>=DIR</dt><dd><p>ユーザーの Unix/RFC2307 ホームディレクトリ。</p></dd><dt><code>--login-shell</code>=SHELL</dt><dd><p>ユーザーの Unix/RFC2307 ログインシェル。</p></dd><dt><code>--gecos</code>=GECOS</dt><dd><p>ユーザーの Unix/RFC2307 GECOS フィールド。</p></dd><dt><code>--uid</code>=USER_ID</dt><dd><p>ユーザーの Unix/RFC2307 ユーザーID。</p></dd></dl>

##### user keytrust add username public-key-or-certificate\[options\] {#user-keytrust-add-username-public-key-or-certificate-options}


<p>バイナリーフィールドに公開鍵を保持するリンク属性 key-credential-link を追加します。</p>

<p>第2引数は、PEM または DER 形式の2048ビット RSA 鍵、またはその鍵を含む証明書を指すファイル名です。既定では符号化形式を自動検出しますが、<code>--encoding</code> オプションで上書きを試みることもできます。他種の公開鍵は非対応ですが、<code>--force</code> オプションで2048ビット以外の鍵を追加できます。</p>

<dl><dt><code>--link-target</code>=DN</dt><dd><p>この DN へリンクします（既定: ユーザーの DN）。</p></dd><dt><code>--encoding</code>=ENCODING</dt><dd><p>鍵形式は <code>pem</code>、<code>der</code>、<code>auto</code> のいずれかです。既定の <code>auto</code> は、ほぼどの状況でも正しい形式を検出すると考えられます。</p></dd><dt><code>--force</code></dt><dd><p>失敗しそうに見える操作も続行します。</p></dd></dl>

##### user keytrust delete username \[options\] {#user-keytrust-delete-username--options}


<p>key-credential-link を削除します。</p>

<p>削除するリンクには複数の選択方法があります。<code>--all</code> はユーザーの全リンクを削除します（多くの場合は1つだけです）。<code>--link-target</code> はリンク先 DN、<code>--fingerprint</code> は鍵のフィンガープリントで選択します。フィンガープリントは DER 符号化した鍵素材の SHA256 をコロン区切りの16進数ペアで表したものです。リンクとフィンガープリントの一覧は <code>user keytrust view</code> で確認できます。</p>

<p><code>--link-target</code>、<code>--fingerprint</code>、<code>--all</code> の複数を使うと、いずれかに一致するリンクを削除します。</p>

<p><code>--dry-run</code> オプションを使うと削除は行わず、省略した場合に何が起きるかを表示します。</p>

<dl><dt><code>--link-target</code>=DN</dt><dd><p>この DN の Key Credential Link を削除します。</p></dd><dt><code>--fingerprint</code>=HH:HH:..</dt><dd><p>この鍵フィンガープリントの Key Credential Link を削除します。</p></dd><dt><code>--all</code></dt><dd><p>すべての Key Credential Link を削除します。</p></dd><dt><code>-n</code>, <code>--dry-run</code></dt><dd><p>何も変更せず、何が起きるかだけを表示します。</p></dd></dl>

##### user keytrust view username \[options\] {#user-keytrust-view-username--options}


<p>ユーザーの Key Credential Link を表示します。&lt;title&gt;user keytrust delete&lt;/title&gt; に使うフィンガープリントと対象 DN の確認に利用できます。<code>--verbose</code> を使うと、あまり役に立たないと思われる情報も追加します。</p>

<dl><dt><code>-h</code>, <code>--help</code></dt><dd><p>このヘルプメッセージを表示して終了します。</p></dd><dt><code>-v</code>, <code>--verbose</code></dt><dd><p>詳細に出力します。</p></dd></dl>

#### visualize \[options\] subcommand {#visualize--options--subcommand}


<p>Samba ネットワークの状態を図で表します。複製グラフで何が起きているかを理解するには、可視化が役立つ場合があります。</p>

<p>サブコマンドは2つ、図の表示モードは2つ、情報源の場所に関する動作モードはおおよそ2つです。</p>

##### 動作モード {#MODES-OF-OPERATION}


<p>samba-tool visualize ntdsconn は NTDS 接続を調べます。samba-tool visualize reps は repsTo と repsFrom オブジェクトを調べます。samba-tool visualize uptodateness は、最新性ベクトルが示す複製の遅れを調べます。</p>

##### 図の表示モード {#GRAPHICAL-MODES}


<p><code>--distance</code> DC 間の距離を端末の行列で表示します。<code>--dot</code> Graphviz dot 出力を生成します（ntdsconn と reps モード用）。dot または xdot で表示すると、DC を頂点、接続を辺とするグラフになります。一部の異常な辺は、色や線種を変えて表示します。<code>--xdot</code> [<code>--dot</code>] と同様に Graphviz dot 出力を生成し、<code>/usr/bin/xdot</code> ですぐ表示しようとします。</p>

<p><code>-r</code> 通常 <code>samba-tool</code> は1つのデータベースと通信しますが、[<code>-r</code>] では、そのデータベースが認識する全 DC への接続を試みます。repsFrom/To オブジェクトは複製されないため、<code>samba-tool visualize uptodateness</code> と <code>samba-tool visualize reps</code> で必要です。他のモードでも複製の問題の発見に役立ちます。</p>
