### 名前 {#Name}


<p>vfs_glusterfs — GlusterFS が提供する機能を利用する</p>

### 書式 {#Synopsis}


<p><code>vfs objects = glusterfs</code></p>

### 説明 {#DESCRIPTION}


<p>この VFS モジュールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.8.html">samba(8)</a> スイートの一部です。</p>

<p>GlusterFS (<a href="http://www.gluster.org/">http://www.gluster.org</a>) は、数ペタバイトまで拡張できるオープンソースのクラスターファイルシステムです。FUSE ベースのネイティブクライアントにより POSIX 準拠ファイルシステムとして利用できるため、追加の手順なしで Samba によって共有できます。</p>

<p><code>vfs_glusterfs</code> VFS モジュールは、Samba から共有用の Gluster ファイルシステムにアクセスする、代替となる優れた方法を提供します。Gluster FUSE マウントは不要で、ライブラリー <code>libgfapi</code> を介して GlusterFS デーモンに直接アクセスします。これにより、コストの高いカーネルとユーザー空間間のコンテキスト切り替えを省き、GlusterFS のより高度な機能を利用できます。</p>

<p>このモジュールは他のモジュールと組み合わせられますが、<code>vfs objects</code> リストの最後に置いてください。glusterfs エントリーの右側に追加したモジュールは、まったく効果を持たない可能性があります。</p>

### 設定 {#CONFIGURATION}


<p>基本的な設定は次のようになります。</p>

<pre><code>		[share]
		vfs objects = glusterfs
		path = /relative/base/path
		glusterfs:volume = gv0
		kernel share modes = no</code></pre>

<p><code>vfs_glusterfs</code> は Gluster マウントを必要としないため、共有の <code>path</code> は他の共有とは異なる扱いになります。使用する Gluster ボリュームに対する共有の相対的な基底パスとして解釈されます。これは通常システムパスと一致しないため、ctdb が Samba を管理するクラスター構成では、ctdb の設定ファイルで <code>CTDB_SAMBA_SKIP_SHARE_CHECK=yes</code> を設定する必要があります。そうしないと ctdb は正常状態になりません。</p>

<p>現在、glusterfs VFS モジュールを使用する共有でファイル提供を正しく動作させるには、kernel share modes を無効にする必要があります。</p>

### オプション {#OPTIONS}


<dl><dt>glusterfs:logfile = path</dt><dd><p>vfs_glusterfs 固有のログファイルを保存するかどうかと、その保存先を定義します。クライアント変数の置換（<code>%M</code>, <code>%m</code>, <code>%I</code>）をサポートしているため、クライアントごとのログファイルを指定できます。</p>
<p>例: glusterfs:logfile = /var/log/samba/glusterfs-vol2.<code>%M</code>.log</p></dd><dt>glusterfs:loglevel = 0-9</dt><dd><p>ログレベルを定義します。数値が大きいほど詳細になります。0 はログなし、9 はトレースレベルです。情報ログレベルにあたる 7 を推奨します。</p>
<p>このオプションでログレベルを明示しない場合、GlusterFS の既定値を使用します（現在はログレベル 7）。</p></dd><dt>glusterfs:volfile_server = servername</dt><dd><p>使用する volfile サーバーを定義します。既定値は localhost です。空白で区切った要素のリストにすることもでき、各要素には次の形式を使用できます。</p>
<p>1. unix+/path/to/socket/file</p>
<p>2. [tcp+]IP|hostname|\[IPv6\][:port]</p>
<p>IPv6 ホスト名の指定には制限があります。RFC 2732 に従う URL 内の IPv6 表記と同じ制限に従います。</p></dd><dt>glusterfs:volume = volumename</dt><dd><p>この共有に使用する GlusterFS のボリューム名を定義します。</p></dd></dl>

### 注意事項 {#CAVEATS}


<p>GlusterFS の write-behind 性能トランスレーターは、Samba と組み合わせるとデータ破損の原因になり得ます。このトランスレーターは書き込み呼び出しの処理時に直ちに成功を返しますが、その後もバックグラウンドでサーバーへのデータ書き込みを続けます。データ整合性の提供を Samba に依存する 2 つのクライアントが同じファイルを操作すると、データが破損する可能性があります。</p>

<p>write-behind トランスレーターは GlusterFS で既定で有効です。vfs_glusterfs プラグインは、このトランスレーターの存在を確認し、検出すると接続を拒否します。プラグインがボリュームに接続できるようにするには、その GlusterFS ボリュームの write-behind トランスレーターを無効にしてください。次の呼び出しで簡単に無効にできます。</p>

<pre><code>                        gluster volume set &lt;volumename&gt; performance.write-behind off</code></pre>

<p>上記をコマンドラインで実行します。</p>

<p>GlusterFS バージョン 9 以降では、初回接続時に write-behind トランスレーターを通知せずに迂回するため、失敗を回避します。</p>
