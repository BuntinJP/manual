### 名前 {#Name}


<p>smbd — クライアントに SMB/CIFS サービスを提供するサーバー</p>

### 書式 {#Synopsis}


<p><code>smbd</code> [<code>-D</code>|<code>--daemon</code>] [<code>-i</code>|<code>--interactive</code>] [<code>-F</code>|<code>--foreground</code>] [<code>--no-process-group</code>] [<code>-b</code>|<code>--build-options</code>] [<code>-p</code> &lt;port number(s)&gt;] [<code>-P</code> &lt;profiling level&gt;] [<code>-d</code> &lt;debug level&gt;] [<code>--debug-stdout</code>] [<code>--configfile</code>=&lt;configuration file&gt;] [<code>--option</code>=&lt;name&gt;=&lt;value&gt;] [<code>-l</code>|<code>--log-basename</code> &lt;log directory&gt;] [<code>--leak-report</code>] [<code>--leak-report-full</code>] [<code>-V</code>|<code>--version</code>]</p>

### 説明 {#DESCRIPTION}


<p>このプログラムは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p><code>smbd</code> は、Windows クライアントにファイル共有と印刷のサービスを提供するサーバーデーモンです。SMB（または CIFS）プロトコルを使い、クライアントにファイル領域とプリンターのサービスを提供します。LanManager プロトコルと互換性があり、LanManager クライアントにもサービスを提供できます。これには DOS 用 MSCLIENT 3.0、Windows for Workgroups、Windows 95/98/ME、Windows NT、Windows 2000、OS/2、Macintosh 用 DAVE、Linux 用 smbfs が含まれます。</p>

<p>サーバーが提供できるサービスの詳しい説明は、それらのサービスの属性を制御する設定ファイルのマニュアルページ（<a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html">smb.conf(5)</a> を参照）にあります。このマニュアルページではサービスではなく、サーバーの実行に関する管理面を中心に説明します。</p>

<p>このサーバーの実行にはセキュリティ上の重大な影響があるため、インストールを進める前に <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html">smb.conf(5)</a> マニュアルページを必ず読んでください。</p>

<p>クライアントが要求するたびにセッションを作成します。クライアントごとに、各セッション用のサーバーのコピーが割り当てられます。このコピーは、そのセッション中にクライアントが行うすべての接続を処理します。そのクライアントからの接続がすべて閉じられると、そのクライアント用のサーバーのコピーは終了します。</p>

<p>設定ファイルと、それがインクルードするファイルは、変更があれば3分ごとに自動的に再読み込みされます。サーバーに SIGHUP を送ることで強制的に再読み込みさせることもできます。設定ファイルの再読み込みは、すでに確立されているサービスへの接続には影響しません。ユーザーがサービスから切断するか、<code>smbd</code> を終了して再起動する必要があります。</p>

<p>SIGHUP シグナルを送る代わりに、<a href="https://www.samba.org/samba/docs/current/man-html/smbcontrol.1.html">smbcontrol(1)</a> プログラムを使って設定ファイルの再読み込みを要求できます。</p>

### オプション {#OPTIONS}


<dl><dt><code>-D</code>|<code>--daemon</code></dt><dd><p>指定すると、サーバーはデーモンとして動作します。つまり、自身を切り離してバックグラウンドで実行し、適切なポートで要求を処理します。単発の利用にとどまらずファイルや印刷のサービスを提供するサーバーでは、<code>smbd</code> をデーモンとして実行することを推奨します。シェルのコマンドラインで <code>smbd</code> を実行した場合、このスイッチを指定したものとみなします。</p></dd><dt><code>-i</code>|<code>--interactive</code></dt><dd><p>指定すると、シェルのコマンドラインから実行した場合でも、サーバーはデーモンではなく「対話的」に動作します。コマンドラインからの実行時に暗黙に選ばれるデーモンモードを無効にします。<code>smbd</code> は接続を1つだけ受け付けて終了します。また、<code>-S</code> パラメーターを指定した場合と同様に、標準出力へログを出力します。</p></dd><dt><code>-F</code>|<code>--foreground</code></dt><dd><p>指定すると、主 <code>smbd</code> プロセスはデーモン化、つまり2回の fork と端末からの切り離しを行いません。各接続要求を処理する子プロセスは通常どおり作成しますが、主プロセスは終了しません。この動作モードは、Daniel J. Bernstein の <code>daemontools</code> パッケージの <code>supervise</code> や <code>svscan</code>、または AIX プロセスモニターなどのプロセス監視プログラムの下で <code>smbd</code> を実行するのに適しています。</p></dd><dt><code>--no-process-group</code></dt><dd><p>smbd 用の新しいプロセスグループを作成しません。</p></dd><dt><code>-b</code>|<code>--build-options</code></dt><dd><p>Samba のビルド方法に関する情報を表示します。</p></dd><dt><code>-p</code>|<code>--port</code>&lt;port number(s)&gt;</dt><dd><p><em><code>port number(s)</code></em> は、smbd が待ち受ける TCP ポートを空白またはカンマで区切った一覧です。既定値は <code>${prefix}/etc/smb.conf</code> の <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#PORTS">ports</a> パラメーターから取得します。</p>

<p>値を大きくすると、サーバーの動作についてログファイルに記録する詳細が増えます。レベル0では重大なエラーと深刻な警告だけを記録します。レベル1は日常的な運用に適しており、実行した操作について少量の情報を生成します。</p>
<p>1より上のレベルは大量のログデータを生成するため、問題の調査時だけ使ってください。3より上は開発者専用に設計されており、大部分が非常に難解な、極めて大量のログデータを生成します。</p>
<p>ここでこのパラメーターを指定すると、<code>${prefix}/etc/smb.conf</code> ファイルの <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#LOGLEVEL">log level</a> パラメーターを上書きします。</p></dd><dt><code>--debug-stdout</code></dt><dd><p>デバッグ出力を STDOUT へリダイレクトします。既定ではサーバーデーモンはログファイルへ記録します。</p></dd><dt><code>--configfile</code>=CONFIGFILE</dt><dd><p>指定するファイルには、サーバーに必要な設定の詳細を記述します。使用する printcap ファイルなどサーバー固有の情報と、サーバーが提供するすべてのサービスの説明を含みます。詳しくは <code>${prefix}/etc/smb.conf</code> を参照してください。既定の設定ファイル名はコンパイル時に決まります。</p></dd><dt><code>--option</code>=&lt;name&gt;=&lt;value&gt;</dt><dd><p>コマンドラインから <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html">smb.conf(5)</a> オプション &quot;&lt;name&gt;&quot; を値 &quot;&lt;value&gt;&quot; に設定します。コンパイル時の既定値と設定ファイルから読み込んだオプションを上書きします。名前や値に空白が含まれる場合は、<code>--option</code>=name=value 全体を引用符で囲んでください。</p></dd><dt><code>-l</code>|<code>--log-basename</code>=logdirectory</dt><dd><p>ログ/デバッグファイルの基底ディレクトリ名です。拡張子 <code>&quot;.progname&quot;</code> が追加されます（log.smbclient、log.smbd など）。クライアントがログファイルを削除することはありません。</p></dd><dt><code>--leak-report</code></dt><dd><p>終了時の talloc リーク報告を有効にします。</p></dd><dt><code>--leak-report-full</code></dt><dd><p>終了時の完全な talloc リーク報告を有効にします。</p></dd><dt><code>-V</code>|<code>--version</code></dt><dd><p>プログラムのバージョン番号を表示します。</p></dd><dt>-?|<code>--help</code></dt><dd><p>コマンドラインオプションの概要を表示します。</p></dd><dt><code>--usage</code></dt><dd><p>簡単な使用方法を表示します。</p></dd></dl>

### 制限事項 {#LIMITATIONS}


<p>一部のシステムでは、<code>smbd</code> は setuid() 呼び出し後に uid を root に戻せません。このようなシステムを trapdoor uid システムと呼びます。この種のシステムでは、クライアント（PC など）から異なる2人のユーザーとして同時に接続することはできません。2人目のユーザーの接続を試みると、アクセス拒否などになります。</p>

### PAM との連携 {#PAM-INTERACTION}


<p>Samba は、認証（平文のパスワードが渡された場合）、アカウントの確認（無効なアカウントかどうか）、セッション管理に PAM を使います。Samba の PAM 対応の範囲は、SMB プロトコルの制約と <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html">smb.conf(5)</a> の <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#OBEYPAMRESTRICTIONS">obey pam restrictions</a> パラメーターにより制限されます。これを設定すると、次の制限が適用されます。</p>

<ul><li><p><em>アカウントの検証</em>: Samba サーバーへのすべてのアクセスで、アカウントが有効で、無効化されておらず、その時点でログインを許可されていることを PAM で確認します。これは暗号化されたログインにも適用されます。</p></li><li><p><em>セッション管理</em>: 共有レベルのセキュリティーを使わない場合、アクセスを許可されるには PAM のセッション検査に合格する必要があります。ただし、共有レベルのセキュリティーではこの検査を迂回します。また、一部の古い PAM 設定ファイルでは、セッション対応のために行の追加が必要な場合があります。</p></li></ul>

### シグナル {#SIGNALS}


<p><code>smbd</code> に SIGHUP を送ると、短時間のうちに <code>smb.conf</code> 設定ファイルを再読み込みします。</p>

<p>ユーザーの <code>smbd</code> プロセスを終了させるには、最後の手段を除き、<code>SIGKILL (-9)</code> を<em>使わない</em>ことを推奨します。共有メモリ領域に不整合が残るおそれがあるためです。<code>smbd</code> を安全に終了する方法は、SIGTERM (-15) シグナルを送り、プロセスが自ら終了するのを待つことです。</p>

<p><code>smbd</code> のデバッグログレベルは <a href="https://www.samba.org/samba/docs/current/man-html/smbcontrol.1.html">smbcontrol(1)</a> プログラムで上げ下げできます（Samba 2.2 以降、SIGUSR[1|2] シグナルは使いません）。通常は低いログレベルで運用しながら、一時的な問題を診断するための機能です。</p>

<p>シグナルハンドラーはデバッグ出力を書き込むため、<code>smbd</code> ではリエントラントではありません。したがって、<code>smbd</code> が着信 SMB を待つ状態になるまで、シグナルを送るのを待ってください。select 呼び出し前にシグナルのブロックを解除し、その後再びブロックすればシグナルハンドラーを安全にできますが、性能に影響します。</p>
