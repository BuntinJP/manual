### 名前 {#Name}


<p>smbpasswd — ユーザーの SMB パスワードを変更する</p>

### 書式 {#Synopsis}


<p><code>smbpasswd</code> [<code>-a</code>] [<code>-c</code> &lt;config file&gt;] [<code>-x</code>] [<code>-d</code>] [<code>-e</code>] [<code>-D</code> debuglevel] [<code>-n</code>] [<code>-r</code> &lt;remote machine&gt;] [<code>-R</code> &lt;name resolve order&gt;] [<code>-m</code>] [<code>-U</code> username[<code>%p</code>assword]] [<code>-h</code>] [<code>-s</code>] [<code>-w</code> pass] [<code>-W</code>] [<code>-i</code>] [<code>-L</code>] [username]</p>

### 説明 {#DESCRIPTION}


<p>このツールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p>smbpasswd プログラムは、<em>root</em> ユーザーとして実行するかどうかによって複数の機能を持ちます。通常のユーザーが実行すると、SMB パスワードを保存する任意のマシンで、自身の SMB セッションに使うパスワードを変更できます。</p>

<p>既定では（引数なしで実行すると）、ローカルマシン上の現在のユーザーの SMB パスワードを変更しようとします。これは <code>passwd(1)</code> プログラムの動作に似ています。ただし <code>smbpasswd</code> は passwd と異なり、<em>setuid root</em> ではなく、クライアントサーバーモードでローカルの <a href="https://www.samba.org/samba/docs/current/man-html/smbd.8.html">smbd(8)</a> と通信します。そのため、成功するにはローカルマシンで smbd デーモンが動作している必要があります。UNIX マシンでは、暗号化された SMB パスワードは通常、既定の passdb バックエンドに保存します。</p>

<p>通常のユーザーがオプションなしで実行すると、smbpasswd は古い SMB パスワードを求め、続いて入力が正しいことを確認するため、新しいパスワードを2回求めます。入力中のパスワードは画面に表示しません。SMB パスワードが空（smbpasswd ファイルの &quot;NO PASSWORD&quot; で指定）であれば、古いパスワードの入力時に &lt;Enter&gt; キーだけを押してください。</p>

<p>通常のユーザーは、smbpasswd で Windows NT プライマリードメインコントローラーなどのリモートマシンの SMB パスワードも変更できます。後述の（<em><code>-r</code></em>）および <em><code>-U</code></em> オプションを参照してください。</p>

<p>root が実行すると、smbpasswd ファイルへのユーザーの追加・削除と、このファイルのユーザー属性の変更ができます。root が実行する <code>smbpasswd</code> はローカルの smbpasswd ファイルへ直接アクセスするため、smbd が動作していなくても変更できます。</p>

### オプション {#OPTIONS}


<dl><dt><code>-a</code></dt><dd><p>後に指定したユーザー名を、新しく入力したパスワードでローカルの smbpasswd ファイルへ追加します（古いパスワードの入力では &lt;Enter&gt; を押します）。ユーザー名が既に存在する場合、このオプションを無視して通常のパスワード変更コマンドとして扱います。既定の passdb バックエンドでは、そのユーザーがシステムのパスワードファイル（通常 <code>/etc/passwd</code>）に既に存在する必要があり、そうでなければ追加要求は失敗します。</p>
<p>このオプションは root として smbpasswd を実行する場合にだけ使えます。</p></dd><dt><code>-c</code></dt><dd><p>既定のファイルや場所以外を使う必要がある場合、<code>${prefix}/etc/smb.conf</code> 設定ファイルのパスとファイル名を指定できます。</p></dd><dt><code>-x</code></dt><dd><p>後に指定したユーザー名をローカルの smbpasswd ファイルから削除します。</p>
<p>このオプションは root として smbpasswd を実行する場合にだけ使えます。</p></dd><dt><code>-d</code></dt><dd><p>後に指定したユーザー名を、ローカルの smbpasswd ファイルで <code>disabled</code> にします。smbpasswd ファイルのアカウント制御領域に <code>&#39;D&#39;</code> フラグを書き込みます。これを行うと、このユーザー名での SMB 認証はすべて失敗します。</p>
<p>smbpasswd ファイルが「旧」形式（Samba 2.0 より前の形式）の場合、ユーザーのパスワードエントリーにこの情報を書き込む場所がないため、コマンドは失敗します。新旧のパスワードファイル形式の詳細は <a href="https://www.samba.org/samba/docs/current/man-html/smbpasswd.5.html">smbpasswd(5)</a> を参照してください。</p>
<p>このオプションは root として smbpasswd を実行する場合にだけ使えます。</p></dd><dt><code>-e</code></dt><dd><p>後に指定したユーザー名のアカウントが無効であった場合、ローカルの smbpasswd ファイルで <code>enabled</code> にします。無効でなければ効果はありません。有効にすると、そのユーザーは再び SMB 認証を行えます。</p>
<p>smbpasswd ファイルが「旧」形式の場合、<code>smbpasswd</code> によるアカウントの有効化は失敗します。新旧のパスワードファイル形式の詳細は <a href="https://www.samba.org/samba/docs/current/man-html/smbpasswd.5.html">smbpasswd(5)</a> を参照してください。</p>
<p>このオプションは root として smbpasswd を実行する場合にだけ使えます。</p></dd><dt><code>-D</code> debuglevel</dt><dd><p><em><code>debuglevel</code></em> は0から10の整数です。このパラメーターを指定しない場合の既定値は0です。</p>
<p>値を大きくすると、smbpasswd の動作についてログファイルに記録する詳細が増えます。レベル0では重大なエラーと深刻な警告だけを記録します。</p>
<p>1より上のレベルは大量のログデータを生成するため、問題の調査時だけ使ってください。3より上は開発者専用に設計されており、大部分が非常に難解な、極めて大量のログデータを生成します。</p></dd><dt><code>-n</code></dt><dd><p>後に指定したユーザー名のパスワードを、ローカルの smbpasswd ファイルで null（空のパスワード）にします。smbpasswd ファイルに保存される最初のパスワードの先頭部分に &quot;NO PASSWORD&quot; と書き込みます。</p>
<p>smbpasswd ファイルで &quot;NO PASSWORD&quot; を設定したユーザーが Samba サーバーへログオンできるようにするには、管理者が <code>smb.conf</code> ファイルの [global] セクションに次のパラメーターを設定する必要があります。</p>
<p><code>null passwords = yes</code></p>
<p>このオプションは root として smbpasswd を実行する場合にだけ使えます。</p></dd><dt><code>-r</code> remote machine name</dt><dd><p>パスワードを変更するマシンを指定できます。このパラメーターがなければ、既定はローカルホストです。<em><code>remote machine name</code></em> は、パスワード変更のために接続する SMB/CIFS サーバーの NetBIOS 名です。この名前は、Samba スイートのすべてのプログラムで使う標準の名前解決機構によって IP アドレスへ解決します。解決機構の変更については <em><code>-R name resolve order</code></em> パラメーターを参照してください。</p>
<p>パスワードを変更するのは、現在 UNIX にログオンしているユーザーです。別のユーザー名のパスワード変更については <em><code>-U username</code></em> パラメーターを参照してください。</p>
<p>Windows NT ドメインのパスワードを変更する場合、指定するリモートマシンはそのドメインのプライマリードメインコントローラーでなければなりません（バックアップドメインコントローラーはユーザーアカウントデータベースの読み取り専用コピーしか持たず、パスワード変更を許しません）。</p>
<p><em>注意</em>: Windows 95/98 は実際のパスワードデータベースを持たないため、Win95/98 マシンをリモートの対象として指定してパスワードを変更することはできません。</p></dd><dt><code>-R</code> name resolve order</dt><dd><p>接続先ホストの NetBIOS 名を検索するときに使う名前解決サービスを指定できます。</p>
<p>選択肢は &quot;lmhosts&quot;、&quot;host&quot;、&quot;wins&quot;、&quot;bcast&quot; です。それぞれ次のように名前を解決します。</p>
<ul><li><p><code>lmhosts</code>: Samba の lmhosts ファイルで IP アドレスを検索します。lmhosts の行で NetBIOS 名に名タイプが付いていない場合（詳細は <a href="https://www.samba.org/samba/docs/current/man-html/lmhosts.5.html">lmhosts(5)</a> を参照）、どの名タイプも検索に一致します。</p></li><li><p><code>host</code>: システムの <code>/etc/hosts</code>、NIS、DNS を使って標準的なホスト名から IP アドレスへの解決を行います。この方法は OS に依存します。たとえば IRIX や Solaris では <code>/etc/nsswitch.conf</code> ファイルで制御する場合があります。この方法は、問い合わせる NetBIOS 名タイプが0x20（サーバー）の場合だけ使い、それ以外では無視します。</p></li><li><p><code>wins</code>: <em><code>wins server</code></em> パラメーターに記載した IP アドレスへ名前を問い合わせます。WINS サーバーを指定していない場合、この方法は無視します。</p></li><li><p><code>bcast</code>: <em><code>interfaces</code></em> パラメーターに記載した既知のローカルインターフェースそれぞれでブロードキャストします。対象ホストがローカル接続のサブネット上にあることに依存するため、名前解決方法の中では最も信頼性が低い方法です。</p></li></ul>
<p>既定の順序は <code>lmhosts, host, wins, bcast</code> です。このパラメーターも <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html">smb.conf(5)</a> ファイルのエントリーもなければ、この順序で名前解決を試みます。</p></dd><dt><code>-m</code></dt><dd><p>変更するアカウントがマシンアカウントであることを smbpasswd に伝えます。現在は Samba を NT プライマリードメインコントローラーとして使う場合に利用します。</p>
<p>このオプションは root として smbpasswd を実行する場合にだけ使えます。</p></dd><dt><code>-U</code> username</dt><dd><p><em><code>-r</code></em> オプションと組み合わせた場合にだけ使えます。リモートマシンでパスワードを変更するとき、そのマシン上の対象ユーザー名を指定できます。システムごとに異なるユーザー名を持つユーザーがパスワードを変更するためのものです。</p></dd><dt><code>-h</code></dt><dd><p>root または通常のユーザーのどちらとして実行しているかに応じて、適切な <code>smbpasswd</code> のヘルプを表示します。</p></dd><dt><code>-s</code></dt><dd><p>smbpasswd が入力を促すメッセージを出さず、古いパスワードと新しいパスワードを <code>/dev/tty</code> ではなく標準入力から読み取るようにします（<code>passwd(1)</code> プログラムと同様です）。smbpasswd を操作するスクリプトを作成する人を支援するオプションです。</p></dd><dt><code>-w</code> password</dt><dd><p>LDAP 対応で Samba をコンパイルした場合だけ使えます。<em><code>-w</code></em> スイッチは、<a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#LDAPADMINDN">ldap admin dn</a> とともに使うパスワードを指定します。パスワードは <code>secrets.tdb</code> に保存され、管理者の DN をキーとします。そのため、<em><code>ldap admin dn</code></em> の値が変わった場合、パスワードも手動で更新する必要があります。</p></dd><dt><code>-W</code></dt><dd><p><code>NOTE:</code> このオプションは、パスワードを標準入力から入力する点を除いて &quot;<code>-w</code>&quot; と同じです。</p>
<p>LDAP 対応で Samba をコンパイルした場合だけ使えます。<em><code>-W</code></em> スイッチは、<a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#LDAPADMINDN">ldap admin dn</a> とともに使うパスワードを指定します。パスワードは <code>secrets.tdb</code> に保存され、管理者の DN をキーとします。そのため、<em><code>ldap admin dn</code></em> の値が変わった場合、パスワードも手動で更新する必要があります。</p></dd><dt><code>-i</code></dt><dd><p>変更するアカウントがドメイン間信頼アカウントであることを smbpasswd に伝えます。現在は Samba を NT プライマリードメインコントローラーとして使う場合に利用します。このアカウントには、別の信頼ドメインの情報を含みます。</p>
<p>このオプションは root として smbpasswd を実行する場合にだけ使えます。</p></dd><dt><code>-L</code></dt><dd><p>ローカルモードで実行します。</p></dd><dt>username</dt><dd><p>すべての<em>root 専用</em>オプションが操作するユーザー名を指定します。ローカルの smbpasswd ファイルの属性を直接変更する権限を持つのは root だけなので、このパラメーターを指定できるのも root だけです。</p></dd></dl>

### 注記 {#NOTES}


<p>root 以外のユーザーが使う <code>smbpasswd</code> は、ローカルの smbd と通信するクライアントサーバーモードで動くため、smbd デーモンが動作している必要があります。よくある問題は、<a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html">smb.conf(5)</a> ファイルに <em><code>allow hosts</code></em> または <em><code>deny hosts</code></em> エントリーを指定して、ローカルマシンの <code>smbd</code> にアクセスできるホストを制限した際に、&quot;localhost&quot; から smbd へのアクセスを許可し忘れることです。</p>

<p>また、smbpasswd コマンドは、Samba を暗号化パスワードを使うように設定している場合にだけ役立ちます。</p>
