### 名前 {#Name}


<p>vfs_fileid — クラスター構成用に一意のデバイス ID 値を持つ file_id 構造体を生成する。特定の inode のロック整合性を意図的に破る方法も提供する</p>

### 書式 {#Synopsis}


<p><code>vfs objects = fileid</code></p>

### 説明 {#DESCRIPTION}


<p>この VFS モジュールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p>Samba はロックのためにファイルを一意に識別する目的で file_id 構造体を使用します。既定では、file_id に <code>stat()</code> システムコールが返すデバイス番号と inode 番号を含めます。file_id はファイルの一意な識別子なので、クラスター構成のすべてのノードで同じでなければなりません。このモジュールは <code>SMB_VFS_FILE_ID_CREATE()</code> 操作を置き換え、設定されたアルゴリズムに基づいてデバイス番号を生成します（&quot;fileid:algorithm&quot; オプションを参照）。</p>

<p>fsname または fsid アルゴリズムを使用する場合、file_id の生成のために、マウントされているすべてのファイルシステムで <code>stat()</code> と <code>statfs()</code> の呼び出しが必要です。たとえば NFS ファイルシステムが応答しないと、この呼び出しがブロックし、smbd プロセスも応答しなくなる可能性があります。&quot;fileid:fstype deny&quot;、&quot;fileid:fstype allow&quot;、&quot;fileid:mntdir deny&quot;、&quot;fileid:mntdir allow&quot; を使用して、応答しなくなる可能性のあるファイルシステムを無視してください。</p>

### オプション {#OPTIONS}


<dl><dt>fileid:algorithm = ALGORITHM</dt><dd><p>利用可能なアルゴリズムは <code>fsname</code>、<code>fsid</code>、<code>next_module</code> です。既定値は <code>fsname</code> です。このほか、従来のアルゴリズム <code>fsname_nodirs</code>、<code>fsname_norootdir</code>、<code>fsname_norootdir_ext</code>、<code>hostname</code> もあります。</p>
<p><code>fsname</code> アルゴリズムは、カーネルのデバイス名をハッシュ化してデバイス ID を生成します。</p>
<p><code>fsid</code> アルゴリズムは、<code>statfs()</code> システムコールが返す <code>f_fsid</code> からデバイス ID を生成します。</p>
<p><code>next_module</code> アルゴリズムは、モジュールチェーン内の次の VFS モジュールに ID を生成させます。主に fileid モジュールが提供する各種 nolock 機能と組み合わせて使用します。</p>
<p>従来の <code>hostname</code> アルゴリズムは、ホスト名と低レベルのデバイス ID をハッシュ化して一意の devid を生成します。<code>fileid:nolock_all_inodes=yes</code> も暗黙に設定します。これはクラスター内のロック整合性を意図的に破るために使用でき、<code>fileid:nolock_max_slots</code> を使用するとノード内のローカルプロセス間の整合性も破れます。注意: 何を行うのか理解せずに使用しないでください。SMB のセマンティクスを破り、データ破損につながる可能性があります。<code>fileid:nolock_all_inodes=yes</code> も暗黙に設定します。</p>
<p>従来の <code>fsname_nodirs</code> アルゴリズムは、<code>fsname</code> アルゴリズムを <code>fileid:nolock_all_dirs=yes</code> とともに使用することの別名です。注意: 何を行うのか理解せずに使用しないでください。SMB のセマンティクスを破ります。より細かく制御する方法については <code>fileid:nolock_paths</code> を参照してください。</p>

<p>従来の <code>fsname_norootdir_ext</code> アルゴリズムは、<code>fsname</code> アルゴリズムを <code>fileid:nolock_paths= “.”</code> と <code>fileid:nolock_max_slots = 18446744073709551615</code> ### 使用例 {#EXAMPLES}


<p><code>fileid</code> モジュールを <code>fsid</code> アルゴリズムで使用する例:</p>

<pre><code>        [global]
	vfs objects = fileid
	fileid:algorithm = fsid</code></pre>

<p>激しく競合する（おそらく読み取り専用の）inode の負荷を避けるために <code>fileid</code> モジュールを使用する例。</p>

<pre><code>        [global]
	vfs objects = fileid
	fileid:algorithm = next_module
	fileid:nolock_paths = . ContendedFolder1 /path/to/contended.exe
	fileid:nolock_max_slots = 256</code></pre>
