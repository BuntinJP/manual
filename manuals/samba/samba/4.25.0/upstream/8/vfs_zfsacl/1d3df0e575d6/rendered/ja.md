### 名前 {#Name}


<p>vfs_zfsacl — ZFS ACL 用 Samba モジュール</p>

### 書式 {#Synopsis}


<p><code>vfs objects = zfsacl</code></p>

### 説明 {#DESCRIPTION}


<p>この VFS モジュールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p><code>zfsacl</code> VFS モジュールには、Samba が ZFS と適切に統合するために必要なすべての ACL 拡張機能が含まれます。</p>

<p>現在、zfsacl VFS モジュールは次の分野の拡張機能を提供します。</p>

<ul><li><p>ZFS 向けの設定可能なオプションを備えた NFSv4 ACL インターフェース</p></li></ul>

<p><code>NOTE:</code>このモジュールは posix-acl の動作に従うため、chown による権限の奪取を許します。将来、Samba がこのモジュールを介した chown の制限を可能にすることも考えられますが、そのような制限は Samba よりも基盤ファイルシステムが責任を負うものです。</p>

<p>このモジュールは smb.conf パラメーター <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#ACLMAPFULLCONTROL">acl map full control = acl map full control</a> を使用します。yes（既定値）に設定すると、ディレクトリーではなくファイルについて返される ACE エントリーが、FILE_DELETE と FILE_DELETE_CHILD 以外のすべてのファイル権限を既に含む場合、そのエントリーに FILE_DELETE_CHILD ビットを追加します。これにより、NFSv4 互換 ACL を持つファイルシステムに対して動作する Windows アプリケーションが GENERIC_ALL アクセスを要求したときに、ACCESS_DENIED エラーが発生することを防げます。</p>

<p>ZFS には ACL の動作を決める複数のデータセット設定パラメーターがあります。各パラメーターの細かな違いはこのマニュアルページの範囲外ですが、&quot;aclmode&quot; と &quot;aclinherit&quot; は Samba 共有にとって特に重要です。Samba 共有専用のデータセットでは、&quot;aclmode = restricted&quot; と &quot;aclinherit = passthrough&quot; によって NTFS ACL と最も整合性の高い継承動作を実現できます。&quot;restricted&quot; aclmode は、単純でない ACL（情報を失わずに POSIX モードで表現できない ACL）を持つファイルに対する chmod() を防ぎます。詳細については関連する ZFS マニュアルページを参照してください。</p>

<p>このモジュールはスタック可能です。</p>

<p>Samba 4.0 以降、すべてのオプションは共有ごとのオプションです。</p>

### オプション {#OPTIONS}


<p>nfs4:mode = [ simple | special ] NFS4 ACL の特殊 ID (OWNER@ と GROUP@) の置換を制御します。simple モードの使用を推奨します。このモードでは、ファイル所有者とグループに関する継承しない ACL エントリーだけを特殊 ID に対応付けます。このモジュールは次の MODE を認識します。<code>simple(default)</code> - 継承しない ACE に限って OWNER@ と GROUP@ の特殊 ID を使用します。<code>special(deprecated)</code> - ファイル所有者とグループに関するすべての ACE で OWNER@ と GROUP@ の特殊 ID を使用します。nfs4:acedup = [dontcare|reject|ignore|merge] このパラメーターは、NFS4 ACL で重複する ACE が見つかった場合の Samba の処理を設定します。同じ ID に異なるビットを持つ重複 ACE を作成できるため、Windows クライアントが混乱することがあります。各値に対する Samba の動作は次のとおりです。<code>dontcare</code> - ACE をそのままコピーします。<code>reject (deprecated)</code> - ACL 設定操作を停止し、エラーで終了します。<code>ignore (deprecated)</code> - 2 番目に一致する ACE を含めません。<code>merge (default)</code> - 重複する 2 つの ACE の ace.flag フィールド同士、ace.mask フィールド同士のビット単位 OR を取り、1 つの ACE にまとめます。nfs4:chown = [yes|no] このパラメーターは、基盤ファイルシステムがサポートする chown を有効または無効にします。システムを安全でない状態にする可能性があるため、有効にする際は注意が必要です。ファイルシステムによっては chown を a) 譲渡、b) 奪取として許可します。危険とされるのは後者です。各値に対する Samba の動作は次のとおりです。<code>yes</code> - 基盤ファイルシステムがサポートする場合、chown を有効にします。<code>no (default)</code> - chown を無効にします。</p>

<dl><dt>zfsacl:denymissingspecial = [yes|no]</dt><dd><p>NFSv4 の特殊エントリー (owner@, group@, everyone@) が欠けた ACL をユーザーが設定することを防ぎます。親ディレクトリーの ACL に継承可能な特殊エントリーがない場合、ZFS は新しいファイルの継承 ACL を計算するときにこれらのエントリーを自動生成します。その結果、継承 ACL の生成に伴いユーザーが混乱したり、ファイルやディレクトリーの権限が予期せず変わったりすることがあります。</p>
<ul><li><p><code>yes</code></p></li><li><p><code>no (default)</code></p></li></ul></dd><dt>zfsacl:block_special = [yes|no]</dt><dd><p>ZFS が NFSv4 の特殊エントリー (owner@, group@, everyone@) を自動追加することを防ぎます。親ディレクトリーの ACL に継承可能な特殊エントリーがない場合、ZFS は新しいファイルの継承 ACL を計算するときにこれらのエントリーを自動生成します。その結果、継承 ACL の生成に伴いユーザーが混乱したり、ファイルやディレクトリーの権限が予期せず変わったりすることがあります。この動作を阻止するには、権限を一切付与しない継承可能な everyone@ を設定し、そのエントリーをファイルのセキュリティ記述子に追加しないようにします。</p>
<ul><li><p><code>yes (default)</code></p></li><li><p><code>no</code></p></li></ul></dd><dt>zfsacl:map_dacl_protected = [yes|no]</dt><dd><p>有効な場合、基盤ファイルシステム上の ZFS ACL に継承されたアクセス制御エントリーが一つも含まれていなければ、SMB クライアントに返すセキュリティ記述子に SEC_DESC_DACL_PROTECTED フラグを設定します。これにより、ディレクトリーの継承を無効にするときの Windows クライアントの動作が正しくなります。</p>
<p>各値に対する Samba の動作は次のとおりです。</p>
<ul><li><p><code>yes</code> - SEC_DESC_DACL_PROTECTED への対応付けを有効にします。</p></li><li><p><code>no (default)</code></p></li></ul></dd></dl>

### 使用例 {#EXAMPLES}


<p>ZFS マウントは、次のように Samba 経由で公開できます。</p>

<pre><code>        [samba_zfs_share]
	vfs objects = zfsacl
	path = /test/zfs_mount
	nfs4: mode = simple
	nfs4: acedup = merge</code></pre>
