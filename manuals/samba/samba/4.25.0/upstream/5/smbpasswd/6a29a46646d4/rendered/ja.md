### 名前 {#Name}


<p>smbpasswd — Samba の暗号化パスワードファイル</p>

### 書式 {#Synopsis}


<p><code>smbpasswd</code></p>

### 説明 {#DESCRIPTION}


<p>このツールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p>smbpasswd は Samba の暗号化パスワードファイルです。ユーザー名、Unix ユーザー ID、ユーザーの SMB ハッシュ化パスワードに加え、アカウントフラグ情報とパスワードの最終変更時刻を含みます。このファイル形式は Samba とともに発展してきており、過去にはいくつかの異なる形式がありました。</p>

### ファイル形式 {#FILE-FORMAT}


<p>Samba 2.2 で使用する smbpasswd ファイルの形式は、よく知られた Unix の <code>passwd(5)</code> ファイルに非常によく似ています。各ユーザーを 1 行で表す ASCII ファイルです。各行のフィールドはコロンで区切られます。&#39;#&#39; で始まるエントリーは無視されます。smbpasswd ファイルは各ユーザーについて次の情報を含みます。</p>

<dl><dt>name</dt><dd><p>ユーザー名です。標準の UNIX passwd ファイルに既に存在する名前でなければなりません。</p></dd><dt>uid</dt><dd><p>UNIX uid です。標準の UNIX passwd ファイル内の同じユーザーエントリーの uid フィールドと一致する必要があります。一致しない場合、Samba はこの smbpasswd ファイルのエントリーを有効なユーザーのものとして認識しません。</p></dd><dt>LANMAN パスワードハッシュ</dt><dd><p>ユーザーのパスワードの LANMAN ハッシュを 32 桁の 16 進数でエンコードしたものです。LANMAN ハッシュは、ユーザーのパスワードを DES キーとして、よく知られた文字列を DES 暗号化することで作成します。Windows 95/98 マシンで使用するのと同じパスワードです。このパスワードハッシュは辞書攻撃に弱く、2 人のユーザーが同じパスワードを選ぶとこのエントリーが同一になるため（UNIX パスワードのようにソルトが付いていないため）、弱いと見なされています。ユーザーのパスワードが空の場合、このフィールドの 16 進文字列の先頭に &quot;NO PASSWORD&quot; という文字が入ります。16 進文字列が 32 個の &#39;X&#39; である場合、ユーザーのアカウントは <code>disabled</code> とされ、そのユーザーは Samba サーバーにログオンできません。</p>
<p><em>警告!!</em> SMB/CIFS 認証プロトコルはチャレンジレスポンス方式であるため、このパスワードハッシュを知る者は誰でもネットワーク上でユーザーになりすませます。このため、これらのハッシュは <em>平文相当</em> と呼ばれ、root ユーザー以外には<em>決して公開してはいけません</em>。保護のため、smbpasswd ファイルは root ユーザーだけが読み取りと通過を行えるディレクトリーに配置し、ファイル自体も root のみが読み書きでき、他のアクセスを一切許可しないように設定する必要があります。</p></dd><dt>NT パスワードハッシュ</dt><dd><p>ユーザーのパスワードの Windows NT ハッシュを 32 桁の 16 進数でエンコードしたものです。Windows NT ハッシュは、ユーザーのパスワードを 16 ビットのリトルエンディアン UNICODE で表現し、MD4（Internet RFC1321）ハッシュアルゴリズムを適用して作成します。</p>
<p>このパスワードハッシュは、パスワードの大文字と小文字を維持し、より高品質のハッシュアルゴリズムを使うため、LANMAN パスワードハッシュより安全と見なされています。ただし、2 人のユーザーが同じパスワードを選ぶとこのエントリーが同一になる点は変わりません（UNIX パスワードのようにソルトが付いていません）。</p>
<p><em>警告!!</em> SMB/CIFS 認証プロトコルはチャレンジレスポンス方式であるため、このパスワードハッシュを知る者は誰でもネットワーク上でユーザーになりすませます。このため、これらのハッシュは <em>平文相当</em> と呼ばれ、root ユーザー以外には<em>決して公開してはいけません</em>。保護のため、smbpasswd ファイルは root ユーザーだけが読み取りと通過を行えるディレクトリーに配置し、ファイル自体も root のみが読み書きでき、他のアクセスを一切許可しないように設定する必要があります。</p></dd><dt>アカウントフラグ</dt><dd><p>この部分には、ユーザーアカウントの属性を表すフラグが入ります。このフィールドは &#39;[&#39; と &#39;]&#39; で囲まれ、長さは常に 13 文字です（&#39;[&#39; と &#39;]&#39; も含みます）。次の文字を含めることができます。</p>
<ul><li><p><em>U</em> - &quot;User&quot; アカウント、つまり通常のユーザーであることを示します。</p></li><li><p><em>N</em> - アカウントにパスワードがないことを示します（LANMAN パスワードハッシュと NT パスワードハッシュの各フィールドは無視されます）。ただし、パスワードなしのログオンが許可されるのは、<a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html">smb.conf(5)</a> 設定ファイルで <em><code>null passwords</code></em> パラメーターが設定されている場合のみです。</p></li><li><p><em>D</em> - アカウントが無効であり、このユーザーの SMB/CIFS ログインを許可しないことを示します。</p></li><li><p><em>X</em> - パスワードが期限切れにならないことを示します。</p></li><li><p><em>W</em> - &quot;Workstation Trust&quot; アカウントであることを示します。この種類のアカウントは Samba PDC のコード系統で使用され、Windows NT Workstation と Server を Samba PDC がホストするドメインに参加できるようにします。</p></li></ul>
<p>将来コードが拡張されると、ほかのフラグも追加される可能性があります。このフィールドの残りは空白で埋めます。サポートされるフラグの詳細については、<code>pdbedit</code> コマンドのマニュアルページを参照してください。</p></dd><dt>最終変更時刻</dt><dd><p>このフィールドは、アカウントの最終変更時刻です。&#39;LCT-&#39;（&quot;Last Change Time&quot; の略）という文字の後に、最後の変更が行われた UNIX 時刻を、エポック（1970 年）からの秒数で数値エンコードした値を続けます。</p></dd></dl>

<p>その他のコロン区切りフィールドは、現在はすべて無視されます。</p>
