### 名前 {#Name}


<p>traffic_learner — トラフィック生成を支援する Samba ツール</p>

### 書式 {#Synopsis}


<p><code>traffic_learner</code> {<code>-o</code> OUTPUT_FILE ...} [<code>-h</code>] [<code>--dns-mode</code> {inline|count}] [SUMMARY_FILE] [SUMMARY_FILE ...]</p>

### 説明 {#DESCRIPTION}


<p>このツールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p>このツールは Samba トラフィックの生成を支援します。<code>traffic_summary.pl</code> が作成したトラフィック要約ファイルを入力として受け取り、<code>traffic_replay</code> がトラフィック生成に使用できるトラフィックモデルファイルを作成します。</p>

<p>モデルファイルは、ネットワーク上で発生するトラフィックの種類（ホストと Samba DC の間の「会話」）を要約します。ネットワークで観測されたものより多い（または少ない）パケットを、より速い（または遅い）速度で送信するよう拡大・縮小できる形式でトラフィックを記述します。</p>

### オプション {#OPTIONS}


<dl><dt><code>-h</code>|<code>--help</code></dt><dd><p>コマンドラインオプションの概要を表示します。</p></dd><dt>SUMMARY_FILE</dt><dd><p>ネットワークトラフィックの要約を含むファイルです。実際のネットワークトラフィックのパケットキャプチャーから <code>traffic_summary.pl</code> で生成してください。複数のファイルを指定すると、そのトラフィックを 1 つのモデルにまとめます。SUMMARY_FILE を指定しない場合、標準入力から要約を読み込みます。つまり、traffic_summary.pl の出力をこのツールに直接パイプできます。</p></dd><dt><code>-o</code>|<code>--out</code> OUTPUT_FILE</dt><dd><p>生成するトラフィックモデルをこのファイルに書き込みます。その後 OUTPUT_FILE を <code>traffic_replay</code> に渡して Samba ネットワークトラフィックを生成（および操作）できます。</p></dd><dt><code>--dns-mode</code> [inline|count]</dt><dd><p>モデルで DNS トラフィックをどのように処理するかを指定します。</p></dd></dl>

### 使用例 {#EXAMPLES}


<p>トラフィック要約ファイルからトラフィックモデルファイルを作成するには、次を使用します。</p>

<p><code>traffic_learner traffic-summary.txt -o traffic-model.txt</code></p>

<p>パケットキャプチャーからトラフィックモデルを作成するには、次のようにトラフィック要約を標準入力にパイプできます。</p>

<p><code>tshark -r capture.pcapng -T pdml | traffic_summary.pl | traffic_learner -o traffic-model.txt</code></p>

### 出力ファイル形式 {#OUTPUT-FILE-FORMAT}


<p>出力モデルファイルは、直前の 2 パケットが与えられたときのパケットの出現確率を推定するマルコフモデルを記述します。</p>

<p>連続する 2 パケットの組の後に続く各パケットの回数を保存し、その回数の比率から次のパケットの確率を計算します。</p>

<p>モデルは JSON 形式で保存され、パケットレートと DNS トラフィックレートの情報も含みます。</p>

#### ngram リストの例 {#Example-ngram-listing}


<p>次のリストは、単一の ngram エントリーを説明のために作った例です。</p>

<pre><code>          &quot;ngrams&quot;: {
             &quot;ldap:0\tdcerpc:11&quot;: {
                 &quot;lsarpc:77&quot;: 1,
                 &quot;ldap:2&quot;: 370,
                 &quot;ldap:3&quot;: 62,
                 &quot;wait:3&quot;: 2,
                 &quot;-&quot;: 1
             }, [...]
          }</code></pre>

<p>これは opcode 0（bind）の ldap パケットの後に opcode 11（これも bind）の dcerpc パケットが続いた後で観測された、後続パケットの回数を数えています。最も多い次のパケットは unbind である &quot;<code>ldap:2</code>&quot; なので、再生時に最も選ばれやすい種類です。逆に、lsarpc opcode 77（名前の検索）は一度しか観測されていないため、再生時に選ばれる可能性は低いものの、あり得ます。</p>

<p>ここには 2 種類の特殊パケットがあります。&quot;<code>wait:3</code>&quot; は会話の一時停止を表し、疑似 opcode &quot;<code>3</code>&quot; は待機時間の長さを指数尺度で示します。つまり、&quot;<code>wait:4</code>&quot; の停止は &quot;<code>wait:3</code>&quot; の約 2.7 倍長く、後者はさらに &quot;<code>wait:2</code>&quot; より同様に長くなります。</p>

<p>もう一方の特殊パケットは &quot;-&quot; で、会話の境界を表します。この例では、観測されたある会話がこの特定の ngram の後で終了したことを示します。この特殊 opcode は会話の開始にも使用し、その開始は ngram &quot;<code>-\t-</code>&quot; で表します。</p>
