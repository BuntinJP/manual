### 名前 {#Name}


<p>samba-dcerpcd — Samba の DCERPC サーバープロセスの1つです。RPC サービスを提供するソケットで待ち受けることができ、呼び出す DCERPC サービスの親プロセスになります。個別に起動しない限り、<code>smbd</code> または <code>winbind</code> から必要に応じて起動され、ヘルパープロセスとして名前付きパイプ（np）経由だけで DCERPC を提供します。起動スクリプトを変更しない限り、ほとんどの構成（スタンドアロンサーバー、メンバーサーバー、AD サーバー）ではこれが標準です。Samba を Active Directory ドメインコントローラーに設定した場合、<code>smbd</code> を呼び出す <code>samba</code> プロセスが引き続き通常の DCERPC サービスを提供し、<code>samba-dcerpcd</code> が提供するわけではないことに注意してください。システムの起動スクリプトやデーモンによって個別に起動する場合は、<code>samba-dcerpcd</code> の単独起動を許可するようグローバル smb.conf オプション <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#RPCSTARTONDEMANDHELPERS">rpc start on demand helpers = false</a> を設定しなければなりません。</p>

### 説明 {#DESCRIPTION}


<p>このツールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p>samba-dcerpcd は2通りの方法で使えます。通常、起動スクリプトを変更せず、グローバル smb.conf オプション <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#RPCSTARTONDEMANDHELPERS">rpc start on demand helpers = true</a> が設定されている場合（既定の設定）は、<code>smbd</code> または <code>winbind</code> から、<code>--np-helper</code> を含むコマンドラインで必要に応じて起動され、名前付きパイプ（np）経由で DCERPC を提供します。また、システムの起動スクリプトから <code>smbd</code> または <code>winbind</code> とは別に起動する、単独モードでも使えます。単独デーモンとして、またはシステムの起動スクリプトから起動する場合、グローバル smb.conf オプション <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#RPCSTARTONDEMANDHELPERS">rpc start on demand helpers = false</a> を false に設定しなければなりません。<a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#RPCSTARTONDEMANDHELPERS">rpc start on demand helpers = true</a> が true または既定のままの場合、<code>samba-dcerpcd</code> は起動に失敗し、エラーメッセージを記録します。</p>

<p>Samba を Active Directory ドメインコントローラーモードで動かす場合、<code>samba</code> の AD コードが引き続き通常の DCERPC サービスを提供する一方、samba-dcerpcd は、この構成で従来 <code>smbd</code> が提供していたのと同様に SRVSVC などのサービスを提供できることに注意してください。</p>

<p>単独モードは、Linux カーネルの SMB2 サーバー ksmbd や、その他の SMB2 サーバー実装など、Samba の枠組みの外で使う場合にも役立ちます。このモードでは inetd のように動作し、RPC サーバー実装の代わりにソケットで待ち受けます。</p>

<p>クライアントが接続すると、<code>samba-dcerpcd</code> は必要に応じて該当する RPC サービスの実行ファイルを起動し、接続をそのサービスへ引き渡します。RPC サービスがしばらく使われないと、<code>samba-dcerpcd</code> はそのサービスに終了を要求します。</p>

### オプション {#OPTIONS}


<dl><dt><code>-D</code>|<code>--daemon</code></dt><dd><p>指定すると、サーバーはデーモンとして動作します。すなわち端末から切り離れてバックグラウンドで動き、適切なポートへの要求を処理します。デーモンとしての実行は、Samba の枠組みの外で <code>samba-dcerpcd</code> を動かす場合に役立ちます。Samba 内でも、システムの起動スクリプトから起動するよう設定したメンバーサーバーで使えます。シェルのコマンドラインから <code>samba-dcerpcd</code> を実行した場合、このスイッチが指定されたものとみなします。</p></dd><dt><code>-i</code>|<code>--interactive</code></dt><dd><p>指定すると、シェルのコマンドラインから起動した場合でも、サーバーをデーモンではなく「対話的」に実行します。コマンドライン実行時の暗黙のデーモンモードを打ち消します。<code>samba-dcerpcd</code> は1つの接続だけを受け付けて終了します。また、<code>-S</code> パラメーターを指定した場合のように標準出力へログを出します。</p></dd><dt><code>-F</code>|<code>--foreground</code></dt><dd><p>指定すると、メインの <code>samba-dcerpcd</code> プロセスはデーモン化（2回の fork と端末からの切り離し）を行いません。各接続要求を処理する子プロセスは通常どおり起動しますが、メインプロセスは終了しません。このモードは、Daniel J. Bernstein の <code>daemontools</code> パッケージの <code>supervise</code> や <code>svscan</code>、または AIX プロセスモニターなどのプロセス監視機構の下で <code>samba-dcerpcd</code> を動かすのに適しています。</p></dd><dt><code>--no-process-group</code></dt><dd><p>samba-dcerpcd の新しいプロセスグループを作成しません。</p></dd><dt><code>--libexec-rpcds</code></dt><dd><p>Samba の LIBEXECDIR 内にあるすべてのデーモンの RPC サービスを提供します。&quot;rpcd_&quot; で始まるプログラムはすべて RPC サービスを提供するものとみなします。<code>--libexec-rpcds</code> オプションを使わない場合は、すべての RPC サービスヘルパーをコマンドラインで明示的に列挙できます。</p></dd><dt><code>--np-helper</code></dt><dd><p><code>samba-dcerpcd</code> を必要に応じて実行し、<code>smbd</code> または <code>winbind</code> のヘルパーとして名前付きパイプソケットを開きます。このモードで動かすには、グローバル smb.conf オプション <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#RPCSTARTONDEMANDHELPERS">rpc start on demand helpers = true</a> を true にする必要があります（既定の設定です）。</p></dd><dt><code>--np-only</code></dt><dd><p><code>samba-dcerpcd</code> を <code>--np-helper</code> なしでデーモンとして実行します。<code>--np-only</code> オプションでは、引き続き ncacn_np サービスだけにバインドします。</p></dd><dt><code>--ready-signal-fd</code>=&lt;fd&gt;</dt><dd><p>この fd を通じて <code>smbd</code> または <code>winbind</code> にサービスの準備完了を通知します。内部使用専用です。</p></dd></dl>
