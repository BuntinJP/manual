### 名前 {#Name}


<p>idmap_tdb2 — Winbind用のSamba idmap_tdb2バックエンド</p>

### 説明 {#DESCRIPTION}


<p>idmap_tdb2プラグインは、SambaとCTDBを使用するクラスタ環境でSID/uid/gidの対応表を保存するためにwinbinddが使用する、既定のidmap_tdbバックエンドの代替です。</p>

<p>idmap_ridのような読み取り専用バックエンドとは異なり、割り当てを行うバックエンドです。つまり、新しい対応を作成するために、新しいユーザーIDとグループIDを割り当てる必要があります。</p>

### IDMAPオプション {#IDMAP-OPTIONS}


<dl><dt>range = low - high</dt><dd><p>このバックエンドが管理する、対応付けに使用可能なuidとgidの範囲を定義します。</p></dd><dt>script</dt><dd><p>tdbカウンターを使う代わりに、IDの対応付けを行う外部プログラムを、このオプションで設定できます。得られた対応はtdb2 idmapデータベースに保存されます。詳細は後述の「IDMAPスクリプト」を参照してください。</p></dd></dl>

### IDMAPスクリプト {#IDMAP-SCRIPT}


<p>tdb2 idmapバックエンドは、smb.confの <em><code>idmap config * : script</code></em> オプション、または非推奨の旧形式 <em><code>idmap : script</code></em> により、IDの対応付けを行う外部プログラムをサポートします。</p>

<p>増分IDカウンターによって作成する対応の代わりに、スクリプトが取得した対応をidmap tdb2データベースに保存します。このため、SIDからUnix IDへの対応付けに渡される可能性があるSIDの全範囲を、スクリプトが扱うことが重要です。そうしないと、スクリプトが対応付けなかったSIDが、スクリプトによりすでに対応付けられたIDへ対応付けられる可能性があります。</p>

<p>スクリプトは、次のコマンドラインオプションを受け付ける必要があります。</p>

<pre><code>	SIDTOID S-1-xxxx
	IDTOSID UID xxxx
	IDTOSID GID xxxx</code></pre>

<p>また、次の応答のいずれかを、1行のテキストとして返す必要があります。</p>

<pre><code>	UID:yyyy
	GID:yyyy
	SID:yyyy
	ERR:yyyy</code></pre>

### 使用例 {#EXAMPLES}


<p>次の例は、tdb2を既定のidmapバックエンドとして使用する方法を示します。</p>

<pre><code>	[global]
	idmap config * : backend = tdb2
	idmap config * : range = 1000000-2000000</code></pre>

<p>次の例は、scriptパラメーター経由で外部プログラムを使用し、tdb2を既定のidmapバックエンドとする方法を示します。</p>

<pre><code>	[global]
	idmap config * : backend = tdb2
	idmap config * : range = 1000000-2000000
	idmap config * : script = /usr/local/samba/bin/idmap_script.sh</code></pre>
