### 名前 {#Name}


<p>vfs_nfs4acl_xattr — NTFS ACL を NFS4 エンコードの blob として拡張属性に保存する</p>

### 書式 {#Synopsis}


<p><code>vfs objects = nfs4acl_xattr</code></p>

### 説明 {#DESCRIPTION}


<p>この VFS モジュールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p><code>vfs_nfs4acl_xattr</code> VFS モジュールは、クライアントが期待する SMB ACL と、ファイルシステムが提供し得る NFSv4 ACL 実装との間の相互運用層を提供します。</p>

<p>このモジュールはスタック可能です。</p>

### オプション {#OPTIONS}


<p>nfs4:mode = [ simple | special ] NFS4 ACL の特殊 ID (OWNER@ と GROUP@) の置換を制御します。simple モードの使用を推奨します。このモードでは、ファイル所有者とグループに関する継承しない ACL エントリーだけを特殊 ID に対応付けます。このモジュールは次の MODE を認識します。<code>simple(default)</code> - 継承しない ACE に限って OWNER@ と GROUP@ の特殊 ID を使用します。<code>special(deprecated)</code> - ファイル所有者とグループに関するすべての ACE で OWNER@ と GROUP@ の特殊 ID を使用します。nfs4:acedup = [dontcare|reject|ignore|merge] このパラメーターは、NFS4 ACL で重複する ACE が見つかった場合の Samba の処理を設定します。同じ ID に異なるビットを持つ重複 ACE を作成できるため、Windows クライアントが混乱することがあります。各値に対する Samba の動作は次のとおりです。<code>dontcare</code> - ACE をそのままコピーします。<code>reject (deprecated)</code> - ACL 設定操作を停止し、エラーで終了します。<code>ignore (deprecated)</code> - 2 番目に一致する ACE を含めません。<code>merge (default)</code> - 重複する 2 つの ACE の ace.flag フィールド同士、ace.mask フィールド同士のビット単位 OR を取り、1 つの ACE にまとめます。nfs4:chown = [yes|no] このパラメーターは、基盤ファイルシステムがサポートする chown を有効または無効にします。システムを安全でない状態にする可能性があるため、有効にする際は注意が必要です。ファイルシステムによっては chown を a) 譲渡、b) 奪取として許可します。危険とされるのは後者です。各値に対する Samba の動作は次のとおりです。<code>yes</code> - 基盤ファイルシステムがサポートする場合、chown を有効にします。<code>no (default)</code> - chown を無効にします。</p>

<dl><dt>nfs4acl_xattr:encoding = [nfs|ndr|xdr]</dt><dd><p>このパラメーターは、ACL blob で使用するマーシャリング形式と、その blob を保存する拡張属性の既定の名前を設定します。</p>
<p><em>nfs</em> に設定すると、NT ACL を NFS 4.0 または 4.1 互換の XDR エンコードで取得・保存します。既定では拡張属性 &quot;system.nfs4_acl&quot; を使用します。この設定は <em>validate_mode</em> も無効にします。</p>
<p><em>ndr (default)</em> に設定すると、NT ACL を POSIX 草案 NFSv4 互換の NDR エンコードで保存します。既定では拡張属性 &quot;security.nfs4acl_ndr&quot; を使用します。</p>
<p><em>xdr</em> に設定すると、NT ACL を NFS 4.1 RFC 5661 に似た形式で XDR エンコードして保存します。RFC 5661 との主な違いは、ユーザーとグループの識別子に文字列ではなく ID を使用することと、nfsace4 ごとに追加の属性があることです。このエンコードは既定で blob を拡張属性 &quot;security.nfs4acl_xdr&quot; に保存します。</p></dd><dt>nfs4acl_xattr:version = [40|41]</dt><dd><p>このパラメーターは NFS4 ACL のレベルを設定します。NT ACL の対応付けを完全にサポートするのは <em>41</em> のみであり、これを使用してください。既定値は <em>41</em> です。</p></dd><dt>nfs4acl_xattr:default acl style = [posix|windows|everyone]</dt><dd><p>このパラメーターは、ファイルまたはディレクトリーに ACL 拡張属性がない場合に合成する ACL の種類を決定します。</p>
<p><em>posix</em> に設定すると、ユーザー、グループ、その他の POSIX モード権限に基づいて ACL を合成し、完全な権限を持つ <em>NT Authority\SYSTEM</em> の ACE を追加します。</p>
<p><em>windows</em> に設定すると、Windows と同じ方法で ACL を合成し、所有者と <em>NT Authority\SYSTEM</em> の権限のみを含めます。</p>
<p><em>everyone</em> に設定すると、everyone (S-1-1-0) に完全な権限を付与する ACL を合成します。</p>
<p>このオプションの既定値は <em>everyone</em> です。</p></dd><dt>nfs4acl_xattr:xattr_name = STRING</dt><dd><p>このパラメーターは、マーシャリングした ACL を保存する拡張属性の名前を設定します。</p>
<p>既定値は <em>nfs4acl_xattr:encoding</em> の設定に依存します。</p></dd><dt>nfs4acl_xattr:nfs4_id_numeric = yes|no (default: no)</dt><dd><p>このパラメーターは、NFS4 サーバーがネットワーク上でユーザーとグループの識別子をどのようにエンコードするかをモジュールに伝えます。既定の設定では、モジュールは NFS4 RFC に従って user@domain としてエンコードされた識別子を想定します。</p>
<p><em>yes</em> に設定すると、モジュールは識別子を数値文字列として想定します。</p>
<p>このオプションの既定値は <em>no</em> です。</p></dd><dt>nfs4acl_xattr:validate_mode = yes|no</dt><dd><p>このパラメーターは、ディレクトリーの POSIX モードを 0777、ファイルの POSIX モードを 0666 に設定することをモジュールが強制するかどうかを設定します。この制約を満たさない場合、ACL blob を含む xattr は破棄されます。</p>
<p>既定値は <em>nfs4acl_xattr:encoding</em> の設定に依存します。<em>nfs</em> に設定されている場合、この設定は既定で無効、それ以外では有効です。</p></dd></dl>

### 使用例 {#EXAMPLES}


<p>このモジュールを使用すると、次のように Samba 経由でディレクトリーを公開できます。</p>

<pre><code>      [samba_gpfs_share]
      vfs objects = nfs4acl_xattr
      path = /foo/bar</code></pre>
