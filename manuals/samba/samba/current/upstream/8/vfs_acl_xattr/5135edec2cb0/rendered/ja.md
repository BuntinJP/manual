### 名前 {#Name}


<p>vfs_acl_xattr — NTFS ACL を拡張属性 (EA) に保存する</p>

### 書式 {#Synopsis}


<p><code>vfs objects = acl_xattr</code></p>

### 説明 {#DESCRIPTION}


<p>この VFS モジュールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p>このモジュールは、標準化された NFS4 ACL をサポートせず、廃止扱いの POSIX ACL 草案の実装だけを備えるシステム向けです。Linux システムは通常これに該当します。NFSv4 ACL をサポートするシステムでは、このモジュールではなく NFSv4 ACL を直接使用します。そのサポートは通常、NFS4 ACL をサポートする基盤ファイルシステムに固有のファイルシステム VFS モジュールによって提供されます。</p>

<p><code>vfs_acl_xattr</code> VFS モジュールは NTFS アクセス制御リスト (ACL) を拡張属性 (EA) に保存します。これにより、ACL 実装自体にその能力がなくても、Samba サーバー上で Windows ACL を完全に対応付けられます。</p>

<p>NT ACL は、ACL 内のユーザーとグループを表す Windows SID を含む形式で、ファイルとディレクトリーの <em><code>security.NTACL</code></em> 拡張属性に保存されます。これはローカルファイルシステムの ACL に保存される uid や gid とは異なります。保存された NT ACL の意味を維持するには、ユーザーおよびグループと Windows SID の対応付けに一貫性が必要です。この拡張属性は Linux コマンド <code>getfattr -d filename</code> では表示され<em>ません</em>。現在の値を表示するには EA の名前を指定する必要があります（例: <code>getfattr -n security.NTACL filename</code>）。</p>

<p>このモジュールは次のパラメーターを強制します。</p>

<ul><li><p>inherit acls = true</p></li><li><p>dos filemode = true</p></li><li><p>force unknown acl user = true</p></li></ul>

<p>このモジュールはスタック可能です。</p>

### オプション {#OPTIONS}


<dl><dt>acl_xattr:security_acl_name = NAME</dt><dd><p>このオプションは NTACL 拡張属性 (xattr) の既定の保存場所を再定義できます。未設定の場合、NTACL xattr は保護された場所である security.NTACL に書き込まれます。つまり、通常のユーザーは Samba の外部から security.NTACL 属性の内容にアクセスできません。このオプションを user.NTACL などのユーザー定義値に設定すると、どのユーザーもこの情報にアクセスして上書きできる可能性があります。このモジュールは SMB 経由でのこの xattr へのアクセスを防止しますが、別の手段（ローカルアクセス、SSH、NFS など）では引き続きアクセスできる可能性があります。このオプションは、その影響を明確に理解し、ACL の内容が侵害されないよう具体的な予防措置を講じた場合にのみ使用してください。</p></dd><dt>acl_xattr:ignore system acls = [yes|no]</dt><dd><p><em>yes</em> に設定すると、このモジュールは POSIX 草案 ACL 層との間で可能な限りの対応付けを行い<em>ません</em>。既定値は <em>no</em> で、Samba はシステム ACL と NT ACL の両方を設定・評価し続けます。ローカルアクセスや NFS によるファイルアクセスのためにもシステム ACL を設定する必要がある場合には、こちらが適しています。Samba 経由でしかデータにアクセスしない場合は、yes に設定すると NT ACL との互換性を向上できる可能性があります。</p>
<p><em>acl_xattr:ignore system acls</em> を <em>yes</em> に設定すると、次の追加設定が強制されます。</p>
<ul><li><p>create mask = 0666</p></li><li><p>directory mask = 0777</p></li><li><p>map archive = no</p></li><li><p>map hidden = no</p></li><li><p>map readonly = no</p></li><li><p>map system = no</p></li><li><p>store dos attributes = yes</p></li></ul></dd><dt>acl_xattr:default acl style = [posix|windows|everyone]</dt><dd><p>このパラメーターは、ファイルまたはディレクトリーに <em>security.NTACL</em> 拡張属性がない場合に合成する ACL の種類を決定します。</p>
<p><em>posix</em> に設定すると、ユーザー、グループ、その他の POSIX モード権限に基づいて ACL を合成し、完全な権限を持つ <em>NT Authority\SYSTEM</em> の ACE を追加します。</p>
<p><em>windows</em> に設定すると、Windows と同じ方法で ACL を合成し、所有者と <em>NT Authority\SYSTEM</em> の権限のみを含めます。</p>
<p><em>everyone</em> に設定すると、everyone (S-1-1-0) に完全な権限を付与する ACL を合成します。</p>
<p>このオプションの既定値は <em>posix</em> です。</p></dd></dl>
