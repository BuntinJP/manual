## send-command¶ {#send-command}

### オプション¶ {#Options}


<p><code>--instance-ids</code> (list)</p>

<blockquote><p>コマンドを実行するマネージドノードの ID。マネージドノード ID の指定は、限られた数のマネージドノードを対象とする場合に最も有用ですが、最大 50 個の ID を指定できます。</p>
<p>より多数のマネージドノードを対象とする場合、または個々のノード ID を列挙したくない場合は、代わりに <code>Targets</code> オプションを使用することをお勧めします。コマンド送信先のマネージドノードを識別するタグのキーと値のペアを受け取る <code>Targets</code> を使用すると、数十、数百、数千のノードに一度にコマンドを送信できます。</p>
<p>ターゲットの使用方法の詳細については、<em>Amazon Web Services Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/send-commands-multiple.html">Run commands at scale</a> を参照してください。</p>
<p>制約:</p>
<ul><li><p>最小: <code>0</code></p></li><li><p>最大: <code>50</code></p></li></ul>
<p>(string)</p>
<blockquote><p>制約:</p>
<ul><li><p>パターン: <code>(^i-(\w{8}|\w{17})$)|(^mi-\w{17}$)</code></p></li></ul></blockquote></blockquote>

<p>構文:</p>

<pre><code>&quot;string&quot; &quot;string&quot; ...</code></pre>

<p><code>--targets</code> (list)</p>

<blockquote><p>指定した <code>Key,Value</code> の組み合わせを使用してマネージドノードを対象にする検索条件の配列。ターゲットの指定は、多数のマネージドノードに一度にコマンドを送信する場合に最も有用です。マネージドノードを識別するタグのキーと値のペアを受け取る <code>Targets</code> を使用すると、数十、数百、数千のノードに一度にコマンドを送信できます。</p>
<p>より少数のマネージドノードにコマンドを送信するには、代わりに <code>InstanceIds</code> オプションを使用できます。</p>
<p>ターゲットの使用方法の詳細については、<em>Amazon Web Services Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/send-commands-multiple.html">Run commands at scale</a> を参照してください。</p>
<p>制約:</p>
<ul><li><p>最小: <code>0</code></p></li><li><p>最大: <code>5</code></p></li></ul>
<p>(structure)</p>
<blockquote><p>指定したキーと値のペアを使用してマネージドノードを対象にする、検索条件の配列。</p>
<h4 id="Note">注記</h4>
<p>メンテナンスウィンドウの Run Command タイプのタスクには、1 つ以上の対象を指定する必要があります。ほかのメンテナンスウィンドウのタスクタイプ (Automation、Lambda、Step Functions) では、タスクによって対象の指定は任意です。対象を指定しないタスクの実行については、<em>Amazon Web Services Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/maintenance-windows-targetless-tasks.html">Registering maintenance window tasks without targets</a> を参照してください。</p>
<p>サポートされる形式は次のとおりです。</p>
<blockquote><p><strong>すべての Systems Manager ツールの場合:</strong></p></blockquote>
<ul><li><p><code>Key=tag-key,Values=tag-value-1,tag-value-2</code></p></li></ul>
<blockquote><p><strong>Automation と Change Manager の場合:</strong></p></blockquote>
<ul><li><p><code>Key=tag:tag-key,Values=tag-value</code></p></li><li><p><code>Key=ResourceGroup,Values=resource-group-name</code></p></li><li><p><code>Key=ParameterValues,Values=value-1,value-2,value-3</code></p></li><li><p>Amazon Web Services リージョン内のすべてのインスタンスを対象とするには:</p>
<ul><li><p><code>Key=AWS::EC2::Instance,Values=*</code></p></li><li><p><code>Key=InstanceIds,Values=*</code></p></li></ul></li></ul>
<blockquote><p><strong>Run Command と Maintenance Windows の場合:</strong></p></blockquote>
<ul><li><p><code>Key=InstanceIds,Values=instance-id-1,instance-id-2,instance-id-3</code></p></li><li><p><code>Key=tag:tag-key,Values=tag-value-1,tag-value-2</code></p></li><li><p><code>Key=resource-groups:Name,Values=resource-group-name</code></p></li><li><p>また、Maintenance Windows はリソースタイプによる対象指定をサポートします。</p>
<ul><li><p><code>Key=resource-groups:ResourceTypeFilters,Values=resource-type-1,resource-type-2</code></p></li></ul></li></ul>
<blockquote><p><strong>State Manager の場合:</strong></p></blockquote>
<ul><li><p><code>Key=InstanceIds,Values=instance-id-1,instance-id-2,instance-id-3</code></p></li><li><p><code>Key=tag:tag-key,Values=tag-value-1,tag-value-2</code></p></li><li><p>Amazon Web Services リージョン内のすべてのインスタンスを対象とするには:</p>
<ul><li><p><code>Key=InstanceIds,Values=*</code></p></li></ul></li></ul>
<p><code>Key,Value</code> パラメーターを使ってマネージドノードを対象とするコマンドの送信方法については、<em>Amazon Web Services Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/send-commands-multiple.html#send-commands-targeting">Targeting multiple managed nodes</a> を参照してください。</p>
<p>Key -&gt; (string)</p>
<blockquote><p>条件を満たすマネージドノードを対象にコマンドを送信するための、ユーザー定義の条件。</p>
<p>制約:</p>
<ul><li><p>最小: <code>1</code></p></li><li><p>最大: <code>163</code></p></li><li><p>パターン: <code>^[\p{L}\p{Z}\p{N}_.:/=\-@]*$|resource-groups:ResourceTypeFilters|resource-groups:Name</code></p></li></ul></blockquote>
<p>Values -&gt; (list)</p>
<blockquote><p><code>Key</code> に対応するユーザー定義の条件。たとえば、<code>tag:ServerRole</code> を指定した場合、<code>value:WebServer</code> を指定すると、EC2 タグに <code>ServerRole,WebServer</code> を含むインスタンスでコマンドを実行できます。</p>
<p>対象の種類によっては、キーに指定できる値の最大数が、全体の上限である 50 より少なくなる場合があります。</p>
<p>制約:</p>
<ul><li><p>最小: <code>0</code></p></li><li><p>最大: <code>50</code></p></li></ul>
<p>(string)</p></blockquote></blockquote></blockquote>

<p>短縮構文:</p>

<pre><code>Key=string,Values=string,string ...</code></pre>

<p>JSON 構文:</p>

<pre><code>[
  {
    &quot;Key&quot;: &quot;string&quot;,
    &quot;Values&quot;: [&quot;string&quot;, ...]
  }
  ...
]</code></pre>

<p><code>--document-name</code> (string) [必須]</p>

<blockquote><p>実行する Amazon Web Services Systems Manager ドキュメント (SSM ドキュメント) の名前。公開ドキュメントまたはカスタムドキュメントを指定できます。別のアカウントに属する共有ドキュメントを実行するには、ドキュメントの Amazon リソースネーム (ARN) を指定します。共有ドキュメントの使用方法の詳細については、<em>Amazon Web Services Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/ssm-using-shared.html">Sharing SSM documents</a> を参照してください。</p>

<ul><li><p>パターン: <code>^[a-zA-Z0-9_\-.:/]{3,128}$</code></p></li></ul></blockquote>

<p><code>--document-version</code> (string)</p>

<blockquote><p>リクエストで使用する SSM ドキュメントのバージョン。$DEFAULT、$LATEST、または特定のバージョン番号を指定できます。コマンドラインインターフェイス (Amazon Web Services CLI) を使用してコマンドを実行する場合、最初の 2 つのオプションはバックスラッシュを使用してエスケープする必要があります。バージョン番号を指定する場合、バックスラッシュは不要です。例:</p>

<blockquote><p>–document-version “$LATEST”</p>

<blockquote><p>制約:</p>

<p>制約:</p>
<ul><li><p>最小: <code>1</code></p></li><li><p>最大: <code>7</code></p></li><li><p>パターン: <code>^([1-9][0-9]*|[0]|[1-9][0-9]%|[0-9]%|100%)$</code></p></li></ul></blockquote>

<p>(structure)</p>
<blockquote><p>オートメーションまたはコマンドに適用する CloudWatch アラーム。</p>
<p>Name -&gt; (string) [必須]</p>
<blockquote><p>CloudWatch アラームの名前。</p>
<p>制約:</p>
<ul><li><p>最小: <code>1</code></p></li><li><p>最大: <code>255</code></p></li><li><p>パターン: <code>^(?!\s*$).+</code></p></li></ul></blockquote></blockquote></blockquote></blockquote>

<p>短縮構文:</p>

<pre><code>IgnorePollAlarmFailure=boolean,Alarms=[{Name=string},{Name=string}]</code></pre>

<p>JSON 構文:</p>

<pre><code>{
  &quot;IgnorePollAlarmFailure&quot;: true|false,
  &quot;Alarms&quot;: [
    {
      &quot;Name&quot;: &quot;string&quot;
    }
    ...
  ]
}</code></pre>

<p><code>--cli-input-json</code> | <code>--cli-input-yaml</code> (string) 指定された JSON 文字列から引数を読み取ります。JSON 文字列は <code>--generate-cli-skeleton</code> が提供する形式に従います。コマンドラインでほかの引数を指定した場合、その値が JSON で指定した値を上書きします。文字列はそのまま解釈されるため、JSON で指定する値を使って任意のバイナリ値を渡すことはできません。<code>--cli-input-yaml</code> と同時には指定できません。</p>

<p><code>--generate-cli-skeleton</code> (string) API リクエストを送信せずに、JSON スケルトンを標準出力に表示します。値を指定しない場合、または値に <code>input</code> を指定した場合は、<code>--cli-input-json</code> の引数に使用できる入力 JSON のサンプルを表示します。同様に、<code>yaml-input</code> を指定した場合は、<code>--cli-input-yaml</code> で使用できる入力 YAML のサンプルを表示します。値に <code>output</code> を指定した場合は、コマンドの入力を検証し、そのコマンドの出力 JSON のサンプルを返します。生成される JSON スケルトンは AWS CLI のバージョン間で一定ではなく、生成される JSON スケルトンの後方互換性は保証されません。</p>

### グローバルオプション¶ {#Global-Options}


<p><code>--debug</code> (boolean)</p>

<p>デバッグログを有効にします。</p>

<p><code>--endpoint-url</code> (string)</p>

<p>コマンドの既定の URL を、指定した URL で上書きします。</p>

<p><code>--no-verify-ssl</code> (boolean)</p>

<p>既定では、AWS CLI は AWS サービスとの通信に SSL を使用します。AWS CLI は各 SSL 接続で SSL 証明書を検証します。このオプションは、SSL 証明書を検証する既定の動作を上書きします。</p>

<p><code>--no-paginate</code> (boolean)</p>

<p>自動ページネーションを無効にします。自動ページネーションを無効にすると、AWS CLI は結果の最初のページを取得するために 1 回だけ呼び出しを行います。</p>

<p><code>--output</code> (string)</p>

<p>コマンド出力の書式。</p>

<ul><li><p>json</p></li><li><p>text</p></li><li><p>table</p></li><li><p>yaml</p></li><li><p>yaml-stream</p></li><li><p>off</p></li></ul>

<p><code>--profile</code> (string)</p>

<p>認証情報ファイル内の特定のプロファイルを使用します。</p>

<p><code>--region</code> (string)</p>

<p>使用するリージョン。設定ファイルおよび環境変数の設定を上書きします。</p>

<p><code>--version</code> (string)</p>

<p>このツールのバージョンを表示します。</p>

<p><code>--color</code> (string)</p>

<p>カラー出力を有効または無効にします。</p>

<ul><li><p>on</p></li><li><p>off</p></li><li><p>auto</p></li></ul>

<p><code>--ca-bundle</code> (string)</p>

<p>SSL 証明書の検証に使用する CA 証明書バンドル。設定ファイルおよび環境変数の設定を上書きします。</p>

<p><code>--cli-read-timeout</code> (int)</p>

<p>ソケット読み取りの最大待ち時間 (秒)。値を 0 に設定すると、ソケット読み取りはブロックし、タイムアウトしません。既定値は 60 秒です。</p>

<p><code>--cli-connect-timeout</code> (int)</p>

<p>ソケット接続の最大待ち時間 (秒)。値を 0 に設定すると、ソケット接続はブロックし、タイムアウトしません。既定値は 60 秒です。</p>

<p><code>--cli-binary-format</code> (string)</p>

<p>バイナリ BLOB に使用する書式。既定の形式は base64 です。base64 形式では、バイナリ BLOB を base64 エンコードされた文字列として指定する必要があります。raw-in-base64-out 形式は AWS CLI V1 の動作との互換性を維持し、バイナリ値はそのまま渡す必要があります。バイナリ BLOB に対応する内容をファイルから指定する場合、<code>fileb://</code> は常にバイナリとして扱われ、<code>cli-binary-format</code> の設定にかかわらずファイルの内容が直接使用されます。<code>file://</code> を使用する場合、ファイルの内容を、設定された <code>cli-binary-format</code> に適した形式にする必要があります。</p>

<ul><li><p>base64</p></li><li><p>raw-in-base64-out</p></li></ul>

<p><code>--no-cli-pager</code> (boolean)</p>

<p>出力用の CLI ページャーを無効にします。</p>

<p><code>--cli-auto-prompt</code> (boolean)</p>

<p>CLI 入力パラメーターの自動プロンプトを有効にします。</p>

<p><code>--no-cli-auto-prompt</code> (boolean)</p>

<p>CLI 入力パラメーターの自動プロンプトを無効にします。</p>

<p><code>--cli-error-format</code> (string)</p>

<p>エラー出力の書式。既定では、エラーは enhanced 形式で表示されます。</p>

<ul><li><p>legacy</p></li><li><p>json</p></li><li><p>yaml</p></li><li><p>text</p></li><li><p>table</p></li><li><p>enhanced</p></li></ul>
