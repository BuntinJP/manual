### 名前 {#NAME}


<p>wg - WireGuard インターフェースの設定と取得</p>

### 書式 {#SYNOPSIS}


<p><strong>wg</strong> [ <em>COMMAND</em> ] [ <em>OPTIONS</em> ]... [ <em>ARGS</em> ]...</p>

### 説明 {#DESCRIPTION}


<p><strong>wg</strong> は、WireGuard トンネルインターフェースの設定を取得・設定するユーティリティーです。インターフェース自体の追加と削除には <strong>ip-link</strong>(8) を使い、IP アドレスとルーティングテーブルは <strong>ip-address</strong>(8) および <strong>ip-route</strong>(8) で設定できます。<strong>wg</strong> ユーティリティーには、WireGuard インターフェースの WireGuard 固有の項目を変更するための一連のサブコマンドがあります。</p>

<p>COMMAND を指定しない場合、COMMAND の既定値は <strong>show</strong> です。INTERFACE を引数に取るサブコマンドには、WireGuard インターフェースを渡す必要があります。</p>

### 設定ファイルの形式 {#CONFIGURATION_FILE_FORMAT}


<p>設定ファイルの形式は <em>INI</em> に基づきます。最上位のセクションは <em>Interface</em> と <em>Peer</em> の2種類です。<em>Peer</em> セクションは複数指定できますが、<em>Interface</em> セクションは1つしか指定できません。</p>

<p><em>Interface</em> セクションには、次のフィールドを記述できます。</p>

<ul><li><p>PrivateKey — <em>wg genkey</em> で生成した base64 形式の秘密鍵。必須です。</p></li><li><p>ListenPort — 待ち受けに使う16ビットのポート。任意です。指定しなければランダムに選択します。</p></li><li><p>FwMark — 送信パケットに付ける32ビットの fwmark。0または &quot;off&quot; に設定すると、このオプションは無効になります。先頭に &quot;0x&quot; を付けて16進数で指定できます。任意です。</p></li></ul>

<p><em>Peer</em> セクションには、次のフィールドを記述できます。</p>

<ul><li><p>PublicKey — 秘密鍵から <em>wg pubkey</em> で計算した base64 形式の公開鍵。通常は設定ファイルの作成者に別の経路で伝えられます。必須です。</p></li><li><p>PresharedKey — <em>wg genpsk</em> で生成した base64 形式の事前共有鍵。任意で、省略できます。このオプションは、既存の公開鍵暗号に混ぜる対称鍵暗号の層を追加し、耐量子性を持たせます。</p></li><li><p>AllowedIPs — CIDR マスク付きの IP（v4またはv6）アドレスをコンマで区切った一覧。このピアからの受信トラフィックを許可する送信元であり、このピアへの送信トラフィックの宛先でもあります。すべての IPv4 アドレスに一致する包括指定として <em>0.0.0.0/0</em> を、すべての IPv6 アドレスに一致する指定として <em>::/0</em> を使えます。複数回指定できます。</p></li><li><p>Endpoint — エンドポイントの IP アドレスまたはホスト名に、コロンとポート番号を続けたもの。このエンドポイントは、ピアから届いた正しく認証されたパケットのうち、最新の送信元 IP アドレスとポートに自動更新されます。任意です。</p></li><li><p>PersistentKeepalive — 認証された空パケットをピアへ送信する間隔を1以上65535以下の秒数で指定し、ステートフルファイアウォールや NAT のマッピングを継続的に有効に保ちます。たとえば、インターフェースからの送信はごくまれでも、ピアからはいつでも受信する可能性があり、NAT の背後にある場合、持続的キープアライブの間隔を25秒にすると役立つことがあります。0または &quot;off&quot; に設定すると、このオプションは無効になります。既定または未指定の場合、このオプションはオフです。ほとんどのユーザーには不要です。任意です。</p></li></ul>

### デバッグ情報 {#DEBUGGING_INFORMATION}


<p>トンネルの現在の実行時状態に関する情報が役立つ場合があります。動的デバッグをサポートするカーネル上で Linux カーネルモジュールを使う場合、root として次を実行すると、<strong>dmesg</strong>(1) にデバッグ情報を書き出せます。</p>

<p><strong> # modprobe wireguard &amp;&amp; echo module wireguard +p &gt; /sys/kernel/debug/dynamic_debug/control</strong></p>

<p>OpenBSD と FreeBSD では、<strong>ifconfig</strong>(1) を使って、インターフェースごとに <strong>dmesg</strong>(1) へデバッグ情報を書き出せます。</p>

<p><strong> # ifconfig wg0 debug</strong></p>

<p>ユーザー空間の実装では、<em>LOG_LEVEL</em> 環境変数を <em>verbose</em> に設定するのが一般的です。</p>

### 環境変数 {#ENVIRONMENT_VARIABLES}


<dl><dt><em>WG_COLOR_MODE</em></dt><dd><p><em>always</em> に設定すると、常に ANSI カラー付きで出力します。<em>never</em> に設定すると、ANSI カラー付きでは出力しません。<em>auto</em>、無効な値、または未設定の場合は、TTY へ書き込むときだけ ANSI カラー付きで出力します。</p></dd><dt><em>WG_HIDE_KEYS</em></dt><dd><p><em>never</em> に設定すると、整形表示を行う <strong>show</strong> サブコマンドの出力に秘密鍵と事前共有鍵を表示します。<em>always</em>、無効な値、または未設定の場合、秘密鍵と事前共有鍵は &quot;(hidden)&quot; と表示されます。</p></dd><dt><em>WG_ENDPOINT_RESOLUTION_RETRIES</em></dt><dd><p>整数または <em>infinity</em> に設定すると、各ピアのエンドポイントの DNS 名前解決で一時的なエラーが発生した場合、その回数だけ再試行します。再試行の間隔は次第に長くなります。未設定の場合、既定の再試行回数は15回です。</p></dd></dl>
