### 名前 {#Name}


<p>nmbd — クライアントに NetBIOS over IP の名前サービスを提供する NetBIOS ネームサーバー</p>

### 書式 {#Synopsis}


<p><code>nmbd</code> [<code>-D</code>|<code>--daemon</code>] [<code>-i</code>|<code>--interactive</code>] [<code>-F</code>|<code>--foreground</code>] [<code>--no-process-group</code>] [<code>-b</code>|<code>--build-options</code>] [<code>-p</code> &lt;port number(s)&gt;] [<code>-P</code> &lt;profiling level&gt;] [<code>-d</code> &lt;debug level&gt;] [<code>--debug-stdout</code>] [<code>--configfile</code>=&lt;configuration file&gt;] [<code>--option</code>=&lt;name&gt;=&lt;value&gt;] [<code>-l</code>|<code>--log-basename</code> &lt;log directory&gt;] [<code>--leak-report</code>] [<code>--leak-report-full</code>] [<code>-V</code>|<code>--version</code>]</p>

### 説明 {#DESCRIPTION}


<p>このプログラムは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p><code>nmbd</code> は、Windows 95/98/ME、Windows NT、Windows 2000、Windows XP、LanManager などの SMB/CIFS クライアントが送る NetBIOS over IP 名前サービス要求を解釈して応答するサーバーです。また、Windows の「ネットワークコンピューター」表示を構成するブラウズプロトコルにも参加します。</p>

<p>SMB/CIFS クライアントは起動時に SMB/CIFS サーバーを探す場合があります。つまり、指定したホストが使っている IP アドレスを知ろうとします。</p>

<p><code>nmbd</code> は他のサービスに加えて、このような要求を待ち受け、自身の NetBIOS 名が指定されていれば、自身が動作しているホストの IP アドレスを返します。「自身の NetBIOS 名」は既定ではホストの主 DNS 名ですが、<code>${prefix}/etc/smb.conf</code> の <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#NETBIOSNAME">netbios name</a> で変更できます。このため、<code>nmbd</code> は自身の名前へのブロードキャスト問い合わせに応答します。<code>nmbd</code> が応答する名前は、<a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html">smb.conf(5)</a> 設定ファイルのパラメーターで追加できます。</p>

<p><code>nmbd</code> は WINS（Windows Internet Name Server）サーバーとしても使用できます。基本的には、受信した名前登録要求からデータベースを作成し、クライアントからの名前の問い合わせに応答する WINS データベースサーバーとして動作するということです。</p>

<p>さらに、<code>nmbd</code> は WINS プロキシーとして動作し、WINS プロトコルで通信する方法を知らないクライアントからのブロードキャスト問い合わせを WINS サーバーへ中継できます。</p>

### シグナル {#SIGNALS}


<p><code>nmbd</code> プロセスを停止する際は、名前データベースが不整合な状態になる可能性があるため、最後の手段を除き SIGKILL (-9) を<em>使わない</em>ことを推奨します。<code>nmbd</code> を終了する正しい方法は、SIGTERM (-15) シグナルを送り、自身で終了するのを待つことです。</p>

<p><code>nmbd</code> は SIGHUP を受け付け、<code>/usr/local/samba/var/locks</code> ディレクトリ（または Samba のインストール先として設定された場所の下の <code>var/locks</code> ディレクトリ）内の <code>namelist.debug</code> ファイルへ名前一覧を書き出します。また、<code>nmbd</code> は <code>log.nmb</code> ファイルへサーバーデータベースを書き出します。さらに、このシグナルにより <code>nmbd</code> の設定を再読み込みします。</p>

<p>SIGHUP シグナルを送る代わりに、<a href="https://www.samba.org/samba/docs/current/man-html/smbcontrol.1.html">smbcontrol(1)</a> プログラムを使って、名前一覧のファイルへの書き出しと設定ファイルの再読み込みを要求できます。</p>

<p>nmbd のデバッグログレベルは <a href="https://www.samba.org/samba/docs/current/man-html/smbcontrol.1.html">smbcontrol(1)</a> で上げ下げできます（Samba 2.2 以降、SIGUSR[1|2] シグナルは使われません）。これにより、通常は低いログレベルで運用しつつ、一時的な問題を診断できます。</p>
