### 名前 {#Name}


<p>winbindd — NT サーバーの名前を解決する Name Service Switch デーモン</p>

### 書式 {#Synopsis}


<p><code>winbindd</code> [<code>-D</code>|<code>--daemon</code>] [<code>-i</code>|<code>--interactive</code>] [<code>-F</code>|<code>--foreground</code>] [<code>--no-process-group</code>] [<code>-n</code>|<code>--no-caching</code>] [<code>-d</code> &lt;debug level&gt;] [<code>--debug-stdout</code>] [<code>--configfile</code>=&lt;configuration file&gt;] [<code>--option</code>=&lt;name&gt;=&lt;value&gt;] [<code>-l</code>|<code>--log-basename</code> &lt;log directory&gt;] [<code>--leak-report</code>] [<code>--leak-report-full</code>] [<code>-V</code>|<code>--version</code>]</p>

### 説明 {#DESCRIPTION}


<p>このプログラムは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p><code>winbindd</code> は、多くの現代の C ライブラリーにある Name Service Switch 機能、PAM と <code>ntlm_auth</code> を介する任意のアプリケーション、および Samba 自体に各種サービスを提供するデーモンです。</p>

<p>winbind を nsswitch に使用しなくても、ドメインコントローラーへの接続を管理することで、<code>smbd</code>、<code>ntlm_auth</code>、<code>pam_winbind.so</code> PAM モジュールにサービスを提供します。この構成では <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#IDMAPCONFIG*:RANGE">idmap config * : range</a> パラメーターは不要です（netlogon proxy only mode と呼びます）。</p>

<p>Name Service Switch は NIS や DNS などの異なるデータベースサービスからユーザー情報とシステム情報を取得できるようにします。正確な動作は <code>/etc/nsswitch.conf</code> ファイルで設定できます。ユーザーとグループが解決されると、Samba 管理者が指定したユーザー ID とグループ ID の範囲から ID を割り当てます。</p>

<p><code>winbindd</code> が提供するサービスは winbind と呼ばれ、Windows NT サーバーからユーザーとグループの情報を解決できます。関連する PAM モジュールを介した認証サービスも提供できます。</p>

<p><code>pam_winbind</code> モジュールは <em><code>auth</code></em>、<em><code>account</code></em>、<em><code>password</code></em> のモジュールタイプをサポートします。<em><code>account</code></em> モジュールは、ドメインコントローラーがアクセス制御を既に行っているため、単に getpwnam() でユーザーの uid をシステムが取得できるか確認する点に注意してください。<code>libnss_winbind</code> ライブラリーが正しくインストールされているか、別の名前情報源が設定されていれば、これは常に成功するはずです。</p>

<p>winbindd サービスは次の nsswitch データベースを実装します。</p>

<dl><dt>hosts</dt><dd><p>この機能は IRIX でのみ利用できます。従来 <code>hosts(5)</code> ファイルに保存され、<code>gethostbyname(3)</code> 関数で使用されるユーザー情報です。名前は WINS サーバーまたはブロードキャストで解決します。</p></dd><dt>passwd</dt><dd><p>従来 <code>passwd(5)</code> ファイルに保存され、<code>getpwent(3)</code> 関数で使用されるユーザー情報。</p></dd><dt>group</dt><dd><p>従来 <code>group(5)</code> ファイルに保存され、<code>getgrent(3)</code> 関数で使用されるグループ情報。</p></dd></dl>

<p>たとえば <code>/etc/nsswitch.conf</code> ファイルに次の簡単な設定をすると、まず <code>/etc/passwd</code> と <code>/etc/group</code>、次に Windows NT サーバーからユーザーとグループ情報を解決できます。</p>

<pre><code>passwd:         files winbind
group:          files winbind
## only available on IRIX: use winbind to resolve hosts:
# hosts:        files dns winbind
## All other NSS enabled systems should use libnss_wins.so like this:
hosts:          files dns wins
</code></pre>

<p><code>/etc/nsswitch.conf</code> ファイルに次の簡単な設定をすると、まず <code>/etc/hosts</code>、次に WINS サーバーからホスト名を解決できます。</p>

<pre><code>hosts:		files wins</code></pre>

### オプション {#OPTIONS}


<dl><dt><code>-D</code>|<code>--daemon</code></dt><dd><p>指定すると、サーバーはデーモンとして動作します。つまり端末から切り離され、適切なポートでバックグラウンド動作します。シェルのコマンドラインから <code>winbindd</code> を実行する場合、このスイッチが指定されたものと見なします。</p></dd><dt><code>-i</code>|<code>--interactive</code></dt><dd><p><code>winbindd</code> をデーモン化せず、現在の端末から切り離さないようにします。開発者が <code>winbindd</code> を対話的にデバッグするときに使用します。<code>winbindd</code> は <code>-S</code> を指定した場合と同様、標準出力にもログを出します。</p></dd><dt><code>-F</code>|<code>--foreground</code></dt><dd><p>指定すると、主 <code>winbindd</code> プロセスはデーモン化、つまり 2 回の fork と端末からの切り離しを行いません。各接続要求を処理する子プロセスは通常どおり作成されますが、主プロセスは終了しません。Daniel J. Bernstein の <code>daemontools</code> パッケージの <code>supervise</code> と <code>svscan</code>、または AIX プロセスモニターなどのプロセス監視下で <code>winbindd</code> を動かすのに適したモードです。</p></dd><dt><code>--no-process-group</code></dt><dd><p>winbindd の新しいプロセスグループを作成しません。</p></dd><dt><code>-n</code>|<code>--no-caching</code></dt><dd><p>一部のキャッシュを無効にします。クライアントに応答する前にドメインコントローラーの応答を待つことが多くなるため、処理が遅くなります。ただし、キャッシュが最新でない可能性がなくなるため、結果はより正確になります。DC が応答しない場合、winbindd が一時的に停止したようになる可能性もあります。信頼関係のある環境でグループメンバーシップを追跡するために必要な samlogon キャッシュは無効にしません。</p></dd><dt><code>-d</code>|<code>--debuglevel</code>=level</dt><dd><p><em><code>level</code></em> は0から10の整数です。このパラメーターを指定しない場合の既定値は0です。</p>
<p>値を大きくすると、サーバーの動作についてログファイルに記録する詳細が増えます。レベル0では重大なエラーと深刻な警告だけを記録します。レベル1は日常的な運用に適しており、実行した操作について少量の情報を生成します。</p>

<p>ここでこのパラメーターを指定すると、<code>${prefix}/etc/smb.conf</code> ファイルの <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#LOGLEVEL">log level</a> パラメーターを上書きします。</p></dd><dt><code>--debug-stdout</code></dt><dd><p>デバッグ出力を STDOUT へリダイレクトします。既定ではサーバーデーモンはログファイルへ記録します。</p></dd><dt><code>--configfile</code>=CONFIGFILE</dt><dd><p>指定するファイルには、サーバーに必要な設定の詳細を記述します。使用する printcap ファイルなどサーバー固有の情報と、サーバーが提供するすべてのサービスの説明を含みます。詳しくは <code>${prefix}/etc/smb.conf</code> を参照してください。既定の設定ファイル名はコンパイル時に決まります。</p></dd><dt><code>--option</code>=&lt;name&gt;=&lt;value&gt;</dt><dd><p>コマンドラインから <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html">smb.conf(5)</a> オプション &quot;&lt;name&gt;&quot; を値 &quot;&lt;value&gt;&quot; に設定します。コンパイル時の既定値と設定ファイルから読み込んだオプションを上書きします。名前や値に空白が含まれる場合は、<code>--option</code>=name=value 全体を引用符で囲んでください。</p></dd><dt><code>-l</code>|<code>--log-basename</code>=logdirectory</dt><dd><p>ログ/デバッグファイルの基底ディレクトリー名。親プロセスは log.winbindd、子プロセスは log.wb-&lt;name&gt; をファイル名に使用します。winbindd がログファイルを削除することはありません。</p></dd><dt><code>--leak-report</code></dt><dd><p>終了時の talloc リーク報告を有効にします。</p></dd><dt><code>--leak-report-full</code></dt><dd><p>終了時の完全な talloc リーク報告を有効にします。</p></dd><dt><code>-V</code>|<code>--version</code></dt><dd><p>プログラムのバージョン番号を表示します。</p></dd><dt>-?|<code>--help</code></dt><dd><p>コマンドラインオプションの概要を表示します。</p></dd><dt><code>--usage</code></dt><dd><p>簡単な使用方法を表示します。</p></dd></dl>

### 名前と ID の解決 {#NAME-AND-ID-RESOLUTION}


<p>Windows NT サーバー上のユーザーとグループには、作成時にグローバルで一意のセキュリティ ID (SID) が割り当てられます。Unix のユーザーやグループに変換するには、SID と Unix のユーザー ID・グループ ID の対応付けが必要です。これは <code>winbindd</code> が行う仕事の一つです。</p>

<p>winbindd がサーバーからユーザーとグループを解決すると、指定された範囲からユーザー ID とグループ ID を割り当てます。先着順ですが、クライアントがユーザーまたはグループの列挙を行うと、その時点ですべての既存ユーザーとグループが対応付けられます。割り当てた Unix ID はデータベースに保存して記憶します。</p>

<p>警告: SID と Unix ID のデータベースは、winbindd がユーザーとグループの対応付けを保存する唯一の場所です。削除または破損すると、Windows NT のユーザーやグループの RID にどの ID が対応するかを winbindd が判定する方法はありません。</p>

### 設定例 {#EXAMPLE-SETUP}


<p>ドメインコントローラーからのユーザー/グループ検索と認証のために winbindd を設定するには、次のような構成を使用します。これは初期の Red Hat Linux マシンでテストされたものです。</p>

<p><code>/etc/nsswitch.conf</code> に次を記述します。</p>

<pre><code>passwd: files winbind
group:  files winbind</code></pre>

<p><code>/etc/pam.d/*</code> の <em><code>auth</code></em> 行を次のように置き換えます。</p>

<pre><code>auth  required    /lib/security/pam_securetty.so
auth  required	  /lib/security/pam_nologin.so
auth  sufficient  /lib/security/pam_winbind.so
auth  required    /lib/security/pam_unix.so \
                  use_first_pass shadow nullok</code></pre>

#### 注 {#Note}


<p>PAM モジュール pam_unix は最近 pam_pwdb に取って代わりました。一部の Linux システムは pam_unix の代わりに pam_unix2 を使用します。</p>

<p>特に <em><code>sufficient</code></em> と <em><code>use_first_pass</code></em> キーワードの使用に注意してください。</p>

<p>次に account 行を以下に置き換えます。</p>

<p><code>account required /lib/security/pam_winbind.so</code></p>

<p>次の手順はドメインへの参加です。<code>net</code> プログラムを次のように使用します。</p>

<p><code>net join -S PDC -U Administrator</code></p>

<p><em><code>-U</code></em> の後のユーザー名には、そのマシンの管理者権限を持つ任意のドメインユーザーを指定できます。&quot;PDC&quot; は PDC の名前または IP に置き換えてください。</p>

<p>次に <code>libnss_winbind.so</code> を <code>/lib</code> へ、<code>pam_winbind.so</code> を <code>/lib/security</code> へコピーします。<code>/lib/libnss_winbind.so</code> から <code>/lib/libnss_winbind.so.2</code> へのシンボリックリンクを作成する必要があります。古い glibc を使用している場合、リンク先は <code>/lib/libnss_winbind.so.1</code> にしてください。</p>

<p>最後に、次のようなディレクティブを含む <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html">smb.conf(5)</a> を設定します。</p>

<pre><code>[global]
	winbind separator = +
        winbind cache time = 10
        template shell = /bin/bash
        template homedir = /home/%D/%U
        idmap config * : range = 10000-20000
        workgroup = DOMAIN
        security = domain
        password server = *</code></pre>

<p>winbindd を起動すると、ユーザーとグループのデータベースが NT のユーザーとグループを含むように拡張され、ユーザー名に DOMAIN+user 構文を使用して、ドメインユーザーとして Unix マシンにログインできるはずです。正しい動作を確認するには <code>getent passwd</code> と <code>getent group</code> コマンドを使用できます。</p>

### 注記 {#NOTES}


<p><code>winbindd</code> の設定と実行には次の注意事項が役立ちます。</p>

<p>PAM は設定を誤りやすいものです。設定ファイルを変更するときは、何を行うか確実に理解してください。設定によっては、システムにログインできなくなる可能性があります。</p>

<p>複数の UNIX マシンで <code>winbindd</code> を実行している場合、一般に割り当てられるユーザー ID とグループ ID は同じにはなりません。共有の <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#IDMAPCONFIG*:BACKEND">idmap config * : backend</a> を設定しない限り、これらの ID はローカルマシンでのみ有効です。</p>

<p>Windows NT SID と UNIX ユーザー/グループ ID のマッピングファイルが破損または破壊されると、対応付けは失われます。</p>

### シグナル {#SIGNALS}


<p>次のシグナルで <code>winbindd</code> デーモンを操作できます。</p>

<dl><dt>SIGHUP</dt><dd><p><a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html">smb.conf(5)</a> ファイルを再読み込みし、変更したパラメーターを実行中の winbindd に適用します。キャッシュされたユーザーとグループ情報も消去し、winbindd が信頼するほかのドメインのリストも再読み込みします。</p>
<p>SIGHUP を送る代わりに、<a href="https://www.samba.org/samba/docs/current/man-html/smbcontrol.1.html">smbcontrol(1)</a> プログラムで設定ファイルの再読み込み要求を送ることもできます。</p></dd><dt>SIGUSR2</dt><dd><p>SIGUSR2 は <code>winbindd</code> に winbind ログファイルへの状態情報の書き込みを行わせます。</p>
<p>ログは log file パラメーターが指定するファイル名に保存します。</p></dd></dl>

### ファイル {#FILES}


<dl><dt><code>/etc/nsswitch.conf(5)</code></dt><dd><p>Name Service Switch の設定ファイル。</p></dd><dt>${prefix}/var/run/winbindd/pipe</dt><dd><p>クライアントが <code>winbindd</code> と通信する UNIX パイプ。安全性のため、winbind クライアントは <code>${prefix}/var/run/winbindd</code> ディレクトリーと <code>${prefix}/var/run/winbindd/pipe</code> ファイルの両方が root 所有である場合にのみ、winbindd デーモンへの接続を試みます。</p>
<p><a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#WINBINDDSOCKETDIRECTORY">winbindd socket directory</a> はこの既定値を上書きします。</p></dd><dt>$STATEDIR/winbindd_privileged/pipe</dt><dd><p>特権クライアントが <code>winbindd</code> と通信する UNIX パイプ。安全性のため、<code>ntlm_auth</code> ユーティリティーが必要とするものなど、一部の機能へのアクセスは制限されています。既定では root グループのユーザーだけがアクセスできますが、管理者は $STATEDIR/winbindd_privileged のグループ権限を変更し、squid などが ntlm_auth を使用できるようにできます。winbind クライアントが接続を試みるのは、<code>$STATEDIR/winbindd_privileged</code> ディレクトリーと <code>$STATEDIR/winbindd_privileged/pipe</code> ファイルの両方が root 所有である場合だけです。</p>
<p><a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#STATEDIR">state dir</a> は $STATEDIR が指す場所を制御します。</p></dd><dt>/lib/libnss_winbind.so.X</dt><dd><p>Name Service Switch ライブラリーの実装。</p></dd><dt>$STATEDIR/winbindd_idmap.tdb</dt><dd><p>Windows NT RID と UNIX ユーザー/グループ ID のマッピングの保存先。ディレクトリーは Samba の最初のコンパイル時に <em><code>--with-statedir</code></em> オプション、または <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#STATEDIR">state dir</a> で指定します。このインストールでの既定のディレクトリーは <code>${prefix}/var/locks</code> です。</p></dd><dt>$LOCKDIR/winbindd_cache.tdb</dt><dd><p>キャッシュされたユーザーとグループ情報の保存先。</p></dd></dl>
