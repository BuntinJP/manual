### 名前 {#Name}


<p>pam_winbind.conf — Winbind 用 PAM モジュールの設定ファイル</p>

### 説明 {#DESCRIPTION}


<p>この設定ファイルは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p>pam_winbind.conf は pam_winbind PAM モジュールの設定ファイルです。詳細は <a href="https://www.samba.org/samba/docs/current/man-html/pam_winbind.8.html">pam_winbind(8)</a> を参照してください。</p>

### 書式 {#SYNOPSIS}


<p>pam_winbind.conf は従来型の INI 形式の設定ファイルです。セクションは global の1つだけで、その中に各種オプションを定義します。</p>

### オプション {#OPTIONS}


<p>pam_winbind は、PAM 設定ファイルまたは <code>/etc/security/pam_winbind.conf</code> にある pam_winbind 設定ファイルで設定できるオプションをいくつかサポートします。PAM 設定ファイルのオプションは、pam_winbind.conf のオプションより優先されます。</p>

<dl><dt>debug = yes|no</dt><dd><p>デバッグ出力を syslog へ送ります。既定値は &quot;no&quot; です。</p></dd><dt>debug_state = yes|no</dt><dd><p>PAM の状態についての詳細なデバッグ出力を syslog へ送ります。既定値は &quot;no&quot; です。</p></dd><dt>require_membership_of = [SID or NAME]</dt><dd><p>このオプションを設定すると、ユーザーが指定した SID または NAME のメンバーである場合だけ pam_winbind は成功します。SID にはグループ SID、エイリアス SID、さらにはユーザー SID も指定できます。SID の代わりに NAME も指定できます。名前の形式は <em><code>MYDOMAIN\mygroup</code></em> または <em><code>MYDOMAIN\myuser</code></em> でなければなりません（&#39;\&#39; 文字は <em><code>winbind separator</code></em> パラメーターの値に対応します）。<em><code>user@REALM</code></em> または <em><code>group@REALM</code></em> 形式の UPN も使えます。この場合、pam_winbind は内部で SID を検索します。NAME には空白を含められないため、SID だけを使うことを推奨します。ユーザーが所属する SID の一覧は <code>wbinfo --user-sids=SID</code> で確認できます。既定では空です。</p>
<p>このオプションはパスワード認証時だけ動作し、何らかの理由でパスワードが不要な場合（SSH 鍵によるログインなど）はアクセスを制限しません。</p></dd><dt>try_first_pass = yes|no</dt><dd><p>既定では、pam_winbind は前のモジュールから認証トークンを取得しようとします。トークンを取得できない場合は、ユーザーに古いパスワードを尋ねます。このオプションを使うと、前のモジュールから認証トークンを取得できない場合はエラーで中止します。最初のパスワードが無効な場合、PAM はパスワードを求めます。既定値は &quot;no&quot; です。</p></dd><dt>krb5_auth = yes|no</dt><dd><p>winbindd が Active Directory ドメインコントローラーと通信している場合、pam_winbind は Kerberos を使って認証できます。このパラメーターで Kerberos 認証を有効にする必要があります。Kerberos 認証が成功できない場合（時計のずれなど）、winbindd は MSRPC 経由の samlogon 認証へ切り替えます。このパラメーターを <em><code>winbind refresh tickets</code></em> と組み合わせると、winbind は必要に応じてチケット交付チケット（TGT）を更新し、最新の状態に保ちます。既定値は &quot;no&quot; です。</p></dd><dt>krb5_ccache_type = [type]</dt><dd><p><em><code>krb5_auth</code></em> オプションを有効にして Kerberos 認証を試みるよう pam_winbind を設定すると、取得したチケット交付チケット（TGT）を資格情報キャッシュに保存できます。このオプションで資格情報キャッシュの種類を制御できます。</p>
<p>次の単純なタイプ名を使用できます（ユーザーの UID を使って既定のパスを生成します）。</p>
<dl><dt>DEFAULT</dt><dd><p>システムの <code>krb5.conf</code> 設定ファイル（“default_ccache_name”）で指定した既定の資格情報キャッシュの場所を使用します。このオプションにより、Kerberos の設定で資格情報キャッシュの場所を一元管理できます。<code>krb5.conf</code> 内の “%{uid}” パターンはユーザーの UID に置換されます。</p></dd><dt>KCM</dt><dd><p>Kerberos Credential Manager を使います（“KCM:&lt;UID&gt;” を生成します）。Kerberos Credential Manager を提供する最近の Linux ディストリビューションでは、この選択を推奨します。</p></dd><dt>KEYRING</dt><dd><p>Linux カーネルのキーリングを使います（“KEYRING:persistent:&lt;UID&gt;” を生成します）。KEYRING には制約があります。安全なカーネルメモリーを使うため、たとえば大量の資格情報は保存できません。KCM が使えない場合の適切な代替です。</p></dd><dt>FILE</dt><dd><p>ファイルベースの資格情報キャッシュを使います（“FILE:/tmp/krb5cc_&lt;UID&gt;” を生成します）。</p></dd><dt>WRFILE</dt><dd><p>書き込み専用モードのファイルベースの資格情報キャッシュを使います（“WRFILE:/tmp/krb5cc_&lt;UID&gt;” を生成します）。</p></dd></dl>
<p>明示的な接頭辞付きの独自パスも指定できます。認識する接頭辞は <em><code>KEYRING:type</code></em>、<em><code>DIR:/path</code></em>、<em><code>FILE:/path</code></em>、<em><code>WRFILE:/path</code></em> です。“<code>%u</code>” または “%{uid}” パターンで数値のユーザーIDを埋め込めます。例:</p>
<dl><dt>krb5_ccache_type = KEYRING:session:<code>%u</code></dt><dd><p>資格情報キャッシュにセッションキーリングを使用します。</p></dd><dt>krb5_ccache_type = DIR:/run/user/<code>%u</code>/krb5cc</dt><dd><p>指定したディレクトリに資格情報キャッシュファイルを作成します。</p></dd><dt>krb5_ccache_type = FILE:/tmp/krb5cc_<code>%u</code></dt><dd><p>資格情報キャッシュファイルを作成します。</p></dd><dt>krb5_ccache_type = WRFILE:/var/lib/sss/ccache/ccache_<code>%u</code></dt><dd><p>書き込み専用の資格情報キャッシュファイルを作成します。</p></dd></dl>
<p>Kerberos 認証だけを行い、ログオン成功後にチケットキャッシュを残さない場合は空にします。既定では空です。</p></dd><dt>cached_login = yes|no</dt><dd><p><em><code>winbind offline logon</code></em> を有効にすると、Winbind はキャッシュ済みの資格情報を使ったログオンを許可します。PAM モジュールからこの機能を使うには、このオプションを設定する必要があります。既定値は &quot;no&quot; です。</p></dd><dt>silent = yes|no</dt><dd><p>メッセージを一切出力しません。既定値は &quot;no&quot; です。</p></dd><dt>mkhomedir = yes|no</dt><dd><p>ユーザーのホームディレクトリを必要に応じてその場で作成します。PAM の session ブロックで有効です。既定値は &quot;no&quot; です。</p></dd><dt>warn_pwd_expire = days</dt><dd><p>パスワードの期限が切れる何日前から pam_winbind が警告を開始するかを指定します。既定値は14日です。</p></dd><dt>pwd_change_prompt = yes|no</dt><dd><p>期限切れパスワードの変更を求めるプロンプトを表示します。既定値は &quot;no&quot; です。</p></dd></dl>
