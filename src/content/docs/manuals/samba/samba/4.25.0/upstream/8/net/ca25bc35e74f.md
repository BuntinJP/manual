### 説明 {#DESCRIPTION}


<p>このツールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p>Samba の net ユーティリティーは、Windows や DOS の net と同じように動作することを意図しています。最初の引数でコマンドの実行に使うプロトコルを指定します。ADS は Active Directory、RAP は古い Win9x/NT3 クライアント、RPC は NT4 と Windows 2000 用です。省略した場合は自動判定を試みます。すべてのプロトコルで、すべてのコマンドを使えるわけではありません。</p>

<p>ここでこのパラメーターを指定すると、<code>${prefix}/etc/smb.conf</code> ファイルの <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#REALM">realm</a> パラメーターを上書きします。</p></dd><dt><code>-U</code>|<code>--user</code>=[DOMAIN\]USERNAME[<code>%P</code>ASSWORD]</dt><dd><p>SMB ユーザー名、またはユーザー名とパスワードを設定します。</p>
<p><code>%P</code>ASSWORD を指定しない場合、ユーザーに入力を求めます。クライアントは最初に <code>USER</code> 環境変数（% で区切ったパスワードを含めることも可能）、次に <code>LOGNAME</code> 変数（パスワードを含めることは不可）を調べ、どちらかがあればその値を使います。これらの環境変数がない場合、Kerberos 資格情報キャッシュにあるユーザー名を使うことがあります。</p>
<p>3つ目の方法は、ユーザー名とパスワードを平文で含む資格情報ファイルを使うことです。主に、管理者がコマンドラインや環境変数で資格情報を渡したくないスクリプト向けです。この方法を使う場合、ファイルのアクセス権で、意図しないユーザーからのアクセスを確実に制限してください。詳しくは <em><code>-A</code></em> を参照してください。</p>
<p>スクリプトにパスワードを含めたり、ユーザーが入力した値をコマンドラインへ渡したりする際は注意してください。安全性のため、必要に応じて Samba クライアントツールにパスワードを尋ねさせるか、<code>kinit</code> で一度パスワードを取得する方が適切です。</p>
<p>Samba はプロセスタイトル（ps に表示されるもの）からパスワードを消去しようとしますが、起動後に行うため競合状態が生じます。</p></dd><dt><code>-N</code>|<code>--no-pass</code></dt><dd><p>指定すると、クライアントが通常ユーザーに表示するパスワード入力要求を抑止します。パスワードを必要としないサービスへのアクセスに役立ちます。</p>
<p>コマンドラインでパスワードを指定せず、このパラメーターも指定していない場合、クライアントはパスワードを要求します。</p>
<p>コマンドラインでパスワードを指定し、このオプションも指定した場合、コマンドラインのパスワードは通知なく無視され、パスワードは使用されません。</p></dd><dt><code>--password</code></dt><dd><p>コマンドラインでパスワードを指定します。</p>
<p>スクリプトにパスワードを含めたり、ユーザーが入力した値をコマンドラインへ渡したりする際は注意してください。安全性のため、必要に応じて Samba クライアントツールにパスワードを尋ねさせるか、<code>kinit</code> で一度パスワードを取得する方が適切です。</p>
<p><code>--password</code> を指定しない場合、ツールは <code>PASSWD</code> 環境変数を調べ、次に、開いたファイル記述子（FD）の番号を含むはずの <code>PASSWD_FD</code> を調べます。</p>
<p>最後に、開くファイルのパスを含む <code>PASSWD_FILE</code> を調べます。そのファイルにはパスワードだけを含めてください。ファイルのアクセス権で、意図しないユーザーからのアクセスを確実に制限してください。</p>
<p>Samba はプロセスタイトル（ps に表示されるもの）からパスワードを消去しようとしますが、起動後に行うため競合状態が生じます。</p></dd><dt><code>--pw-nt-hash</code></dt><dd><p>指定したパスワードは NT ハッシュです。</p></dd><dt><code>-A</code>|<code>--authentication-file</code>=filename</dt><dd><p>接続に使うユーザー名とパスワードを読み取るファイルを指定できます。ファイルの形式は次のとおりです。</p>
<pre><code>				username = &lt;value&gt;&#10;				password = &lt;value&gt;&#10;				domain   = &lt;value&gt;&#10;			</code></pre>
<p>ファイルのアクセス権で、意図しないユーザーからのアクセスを確実に制限してください。</p></dd><dt><code>-P</code>|<code>--machine-pass</code></dt><dd><p>保存済みのマシンアカウントのパスワードを使います。</p></dd><dt><code>--simple-bind-dn</code>=DN</dt><dd><p>単純バインドに使う DN です。</p></dd><dt><code>--use-kerberos</code>=desired|required|off</dt><dd><p>Samba クライアントツールが Kerberos 認証を試みるかどうかを指定します。Kerberos 認証では、サービスへの接続時に IP アドレスではなく DNS 名を使ってください。既定では、Samba クライアントツールは既定の Kerberos 資格情報キャッシュ（ccache）を使おうとします。ccache がない場合、または <code>-U</code>|<code>--user</code> オプションを指定した場合、クライアントはパスワード入力を求め、Kerberos チケットを取得します（kinit）。別の Kerberos 資格情報キャッシュを使う場合は <code>--use-krb5-ccache</code> オプションを指定してください。</p>
<p>ここでこのパラメーターを指定すると、<code>${prefix}/etc/smb.conf</code> ファイルの <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#CLIENTUSEKERBEROS">client use kerberos</a> パラメーターを上書きします。</p></dd><dt><code>--use-krb5-ccache</code>=CCACHE</dt><dd><p>Kerberos 認証の資格情報キャッシュの場所を指定します。</p>
<p><code>--use-kerberos</code>=required を強制します。</p></dd><dt><code>--use-winbind-ccache</code></dt><dd><p>winbind の資格情報キャッシュを使おうとします。</p></dd><dt><code>--client-protection</code>=sign|encrypt|off</dt><dd><p>クライアントツールが使う接続保護を設定します。</p>
<p>ここでこのパラメーターを指定すると、<code>${prefix}/etc/smb.conf</code> ファイルの <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#CLIENTPROTECTION">client protection</a> パラメーターを上書きします。</p>
<p>より細かな制御が必要な場合は、<code>--option=clientsmbencrypt=OPTION</code>、<code>--option=clientipcsigning=OPTION</code>、<code>--option=clientsigning=OPTION</code> を使えます。</p></dd></dl>

#### \[RPC\|ADS\] JOIN \[TYPE\] \[--no-dns-updates\] \[-U username\[%password\]\] \[dnshostname=FQDN\] \[createupn=UPN\] \[createcomputer=OU\] \[machinepass=PASS\] \[osName=string osVer=string\] \[DOMAIN\] \[options\] {#RPC-ADS--JOIN--TYPE-----no-dns-updates----U-username--password----dnshostname-FQDN---createupn-UPN---createcomputer-OU---machinepass-PASS---osName-string-osVer-string---DOMAIN---options}


<p>ドメインに参加します。サーバーにアカウントがすでに存在し、[TYPE] が MEMBER なら、自動参加を試みます（サーバーマネージャーでマシンを作成済みと仮定します）。それ以外はパスワードを求め、新規アカウントを作成する場合があります。</p>

<p>[FQDN]（ADS のみ）は、参加時に dnsHostName 属性を設定します。既定の形式は netbiosname.dnsdomain です。</p>

<p>[UPN]（ADS のみ）は、参加時に principalname 属性を設定します。既定の形式は host/netbiosname@REALM です。</p>

#### ADS KEYTAB CREATE {#ADS-KEYTAB-CREATE}


<p>Samba 4.21.0以降、keytab ファイルは <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#SYNCMACHINEPASSWORDTOKEYTAB">sync machine password to keytab</a> の指定に従って作成します。secrets.tdb にマシンパスワードがある場合、すなわち <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#KERBEROSMETHOD">kerberos method = secrets only</a> と <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#KERBEROSMETHOD">kerberos method = secrets and keytab</a> の場合だけ作成できます。<a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#KERBEROSMETHOD">kerberos method = secrets only</a> と <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#SYNCMACHINEPASSWORDTOKEYTAB">sync machine password to keytab</a>（既定では空）が smb.conf の既定値の場合、keytab はまったく生成しません。<a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#KERBEROSMETHOD">kerberos method = secrets and keytab</a> で <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#SYNCMACHINEPASSWORDTOKEYTAB">sync machine password to keytab</a> がない場合、AD から同期した SPN、アカウント名 COMPUTER$、プリンシパル host/dns_hostname を含む既定名の keytab を作成します。</p>

<p>Samba 4.20までは、アカウント名 COMPUTER$、&#39;host&#39; プリンシパル、AD から同期した SPN を既定で作成していました。次の例は、そのような keytab を生成します。</p>

<pre><code>sync machine password to keytab = /etc/krb5.keytab:spn_prefixes=host:account_name:sync_spns:sync_kvno:machine_password</code></pre>

<p>コンピューターの AD アカウントは変更しません。</p>

#### （削除済み）ADS KEYTAB ADD \(principal \| machine \| serviceclass \| windows SPN\) {#Removed---ADS-KEYTAB-ADD--principal---machine---serviceclass---windows-SPN}


<p>Samba 4.21.0以降では、このコマンドは利用できません。代替は <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#SYNCMACHINEPASSWORDTOKEYTAB">sync machine password to keytab</a> を参照してください。</p>

<p>たとえば次の呼び出しを置き換えるには:</p>

<pre><code>net ads keytab add wurst/brot@REALM</code></pre>

<p>smb.conf に追加します:</p>

<pre><code>sync machine password to keytab = /path/to/keytab1:spns=wurst/brot@REALM:machine_password</code></pre>

<p>その後、次を実行します:</p>

<pre><code>net ads keytab create</code></pre>

<p>このコマンドの元の説明:</p>

<p>新しい keytab エントリーを追加します。エントリーは次のいずれかです。</p>

<dl><dt>Kerberos プリンシパル</dt><dd><p>Kerberos プリンシパル（&#39;@&#39; の存在で識別）は、そのまま keytab ファイルに追加します。</p></dd><dt>machinename</dt><dd><p>マシン名（末尾の &#39;$&#39; で識別）から Kerberos プリンシパル &#39;machinename@realm&#39; を作成し、keytab ファイルへ追加します。</p></dd><dt>serviceclass</dt><dd><p>サービスクラス（&#39;cifs&#39;、&#39;html&#39; など）から &#39;serviceclass/fully_qualified_dns_name@realm&#39; と &#39;serviceclass/netbios_name@realm&#39; の2つの Kerberos プリンシパルを作成し、keytab ファイルへ追加します。</p></dd><dt>Windows SPN</dt><dd><p>Windows SPN は &#39;serviceclass/host:port&#39; 形式で、これから Kerberos プリンシパル &#39;serviceclass/host@realm&#39; を作成し、keytab ファイルへ書き込みます。</p></dd></dl>

<p>古いバージョンとは異なり、このコマンドはコンピューターの AD オブジェクトを変更しません。従来クライアントの動作を維持するため &#39;net ads keytab ad_update_ads&#39; が用意されています。</p>

#### USERSHARE {#USERSHARE}


<p>バージョン3.0.23以降、Samba サーバーは root 以外のユーザーが &quot;net usershare&quot; コマンドでユーザー定義共有を追加・公開する機能に対応しています。</p>

<p>まず <code>${prefix}/etc/smb.conf</code> の [global] セクションに usershare path = /usr/local/samba/lib/usershares を追加します。次にそのディレクトリを作成し、所有者を root、所有グループをユーザー定義共有を作成できる UNIX グループ（例: &quot;serverops&quot;）にします。アクセス権は01770に設定します（所有者とグループはすべて許可、他は不許可、さらにスティッキービットを付け、ファイルの名前変更や削除をその所有者だけに制限）。最後に <code>${prefix}/etc/smb.conf</code> の [global] セクションへ、たとえば usershare max shares = 100 を追加し、100個の共有定義を許可します。これで &quot;serverops&quot; のメンバーは次のコマンドで必要に応じて共有を作成できます。</p>

<p>usershare コマンドは次のとおりです。</p>

<div class="manual-table"><table><tbody><tr><td><p>net usershare add sharename path [comment [acl] [guest_ok=[y|n]]] - ユーザー定義共有を追加または変更します。</p></td></tr><tr><td><p>net usershare delete sharename - ユーザー定義共有を削除します。</p></td></tr><tr><td><p>net usershare info [<code>--long</code>] [wildcard sharename] - ユーザー定義共有の情報を表示します。</p></td></tr><tr><td><p>net usershare list [<code>--long</code>] [wildcard sharename] - ユーザー定義共有を一覧表示します。</p></td></tr></tbody></table></div>

##### USERSHARE ADD sharename path \[comment\] \[acl\] \[guest\_ok=\[y\|n\]\] {#USERSHARE-ADD-sharename-path--comment---acl---guest_ok--y-n}


<p>&quot;sharename&quot; という新しいユーザー定義共有を追加または置き換えます。</p>

<p>&quot;path&quot; は公開するシステム上の絶対パス名です。制限を設けることもできます。<code>${prefix}/etc/smb.conf</code> のグローバルパラメーター &quot;usershare owner only&quot;、&quot;usershare prefix allow list&quot;、&quot;usershare prefix deny list&quot; を参照してください。</p>

<p>任意の &quot;comment&quot; は、クライアントが共有を参照した際に表示するコメントです。</p>

<p>任意の &quot;acl&quot; は、共有全体への読み書き権限を持つユーザーを指定します。<code>${prefix}/etc/smb.conf</code> の &quot;usershare allow guests&quot; を設定しなければゲスト接続は許可しません。ACL の形式は &quot;user:permission&quot; で、user はシステム上の有効なユーザー名、permission は &quot;F&quot;、&quot;R&quot;、&quot;D&quot; のいずれかです。F は読み書き可能な完全な権限、D はそのユーザーのアクセス拒否、R は読み取り専用（ファイルやディレクトリの新規作成、ファイル書き込みは不可）です。</p>

<p>acl を指定しない場合の既定値は &quot;Everyone:R&quot; で、認証済みユーザー全員に読み取り専用アクセスを許可します。</p>

<p>任意の &quot;guest_ok&quot; は <code>${prefix}/etc/smb.conf</code> の同名パラメーターと同じ効果で、この共有へのゲストアクセスを許可します。<code>${prefix}/etc/smb.conf</code> のグローバルパラメーター &quot;usershare allow guests&quot; が true の場合だけ指定できます。</p>

<p>既存のユーザー定義共有を変更する専用コマンドはありません。&quot;net usershare add [sharename]&quot; に変更対象と同じ共有名と新しいオプションを指定します。smbd は接続時に変更を認識するため、追加・削除・変更の際に再起動する必要はありません。</p>

##### USERSHARE DELETE sharename {#USERSHARE-DELETE-sharename}


<p>指定名のユーザー定義共有を削除します。smbd は直ちに変更を認識しますが、その共有に現在接続しているユーザーは切断しません。</p>

##### USERSHARE INFO \[--long\] \[wildcard sharename\] {#USERSHARE-INFO----long---wildcard-sharename}


<p>指定パターンに一致する、現在のユーザー所有の共有、または全ユーザーの共有の情報を取得します。</p>

<p>net usershare info 単独では、現在のユーザーが作成した共有の情報を出力します。ワイルドカードパターンを指定すると一致する共有名に限定します（&#39;*&#39; は1文字以上、&#39;?&#39; は1文字だけに一致）。&#39;<code>--long</code>&#39; オプションを付けると、他ユーザーが作成した共有の情報も表示します。</p>

<p>共有の情報は [foobar] path=/home/jeremy comment=testme usershare_acl=Everyone:F guest_ok=n のように表示されます。&quot;net usershare add&quot; で変更できる現在の設定の一覧です。</p>

##### USERSHARE LIST \[--long\] wildcard sharename {#USERSHARE-LIST----long--wildcard-sharename}

##### \[RPC\] CONF GETINCLUDES section {#RPC--CONF-GETINCLUDES-section}


<p>指定したセクション（global または共有）の include 一覧を取得します。</p>

<p>レジストリデータベースと include 指示の性質上、include は特別扱いが必要です。パラメーター名を値名として保存するため、共有ごとに同じパラメーターは1つしかなく、テキストファイルのような順序も保証されません。通常のパラメーターには問題ありませんが、include はメタパラメーターであり、smb.conf で他のパラメーターの間のどこに置くかが重要です。単純なレジストリ smbconf モデルでは表現できないため、共有ごとに順序付きの include 一覧を持ち、その共有の全パラメーターの後に評価します。</p>

<p>現在、レジストリ設定から include できるのはファイルだけです。将来は他のレジストリキーの設定データを取り込めるようになる予定です。</p>

#### DOM {#DOM}


<p>バージョン3.2.0以降、Samba はクライアント側とサーバー側の両方で、リモート参加・離脱 API に対応しています。Windows は Windows 2000以降でリモート参加に対応しています。</p>

<p>Samba をリモートから参加・離脱させるには、Domain Admins グループ、ローカル Administrators グループ、または SeMachineAccountPrivilege を付与されたユーザーのアカウントを使う必要があります。</p>

<p>クライアント側のリモート参加は、次の net dom コマンドで実装されています。</p>

<div class="manual-table"><table><tbody><tr><td><p>net dom join - リモートコンピューターをドメインに参加させます。</p></td></tr><tr><td><p>net dom unjoin - リモートコンピューターをドメインから離脱させます。</p></td></tr><tr><td><p>net dom renamecomputer - ドメイン参加済みリモートコンピューターの名前を変更します。</p></td></tr></tbody></table></div>

##### DOM JOIN domain=DOMAIN ou=OU account=ACCOUNT password=PASSWORD reboot {#DOM-JOIN-domain-DOMAIN-ou-OU-account-ACCOUNT-password-PASSWORD-reboot}


<p>コンピューターをドメインに参加させます。次の追加パラメーターを使用できます。</p>

<ul><li><p><em><code>DOMAIN</code></em> は NetBIOS ドメイン名（短いドメイン名）または Active Directory の DNS ドメイン名です。Windows と同様、使うドメインコントローラーも指定できます。区切り文字 \ で DC 名を付加します。例: MYDOM\MYDC。<em><code>DOMAIN</code></em> は NULL にできません。</p></li><li><p><em><code>OU</code></em> に <em>ou=mymachines,cn=Users,dc=example,dc=com</em> のような RFC 1779 LDAP DN を設定すると、既定以外の LDAP コンテナーにマシンアカウントを作成できます。この任意パラメーターは Active Directory ドメインへの参加時だけ使えます。</p></li><li><p><em><code>ACCOUNT</code></em> は参加に使うドメインアカウントです。マシンを参加させる十分な権限が必要です。</p></li><li><p><em><code>PASSWORD</code></em> は、<em><code>ACCOUNT</code></em> で指定したドメインアカウントのパスワードです。</p></li><li><p><em><code>REBOOT</code></em> は、ドメイン参加に成功した後にリモートマシンを再起動させる任意パラメーターです。</p></li></ul>

<p>参加させたいリモートマシンへの接続と認証には、標準の net パラメーターも必要です。<code>-S</code> computer や <code>-U</code> user などが該当します。</p>

<p>例: net dom join <code>-S</code> xp <code>-U</code> XP\\administrator<code>%s</code>ecret domain=MYDOM account=MYDOM\\administrator password=topsecret reboot.</p>

<p>この例は、パスワード secret のローカル管理者として XP に接続し、MYDOM のドメイン管理者アカウントとパスワード topsecret で MYDOM ドメインに参加させます。参加成功後にコンピューターを再起動します。</p>

##### DOM UNJOIN account=ACCOUNT password=PASSWORD reboot {#DOM-UNJOIN-account-ACCOUNT-password-PASSWORD-reboot}


<p>コンピューターをドメインから離脱させます。次の追加パラメーターを使用できます。</p>

<ul><li><p><em><code>ACCOUNT</code></em> は離脱に使うドメインアカウントです。マシンを離脱させる十分な権限が必要です。</p></li><li><p><em><code>PASSWORD</code></em> は、<em><code>ACCOUNT</code></em> で指定したドメインアカウントのパスワードです。</p></li><li><p><em><code>REBOOT</code></em> は、ドメイン離脱に成功した後にリモートマシンを再起動させる任意パラメーターです。</p></li></ul>

<p>離脱させたいリモートマシンへの接続と認証には、標準の net パラメーターも必要です。<code>-S</code> computer や <code>-U</code> user などが該当します。</p>

<p>例: net dom unjoin <code>-S</code> xp <code>-U</code> XP\\administrator<code>%s</code>ecret account=MYDOM\\administrator password=topsecret reboot.</p>

<p>AD にマシンアカウントを準備します。成功にはドメインコントローラーへのネットワーク接続が必要です。次の追加パラメーターを使えます。</p>

<p>バージョン4.25以降、Samba はクラスター機能レベルに対応しています。</p>

<div class="manual-table"><table><tbody><tr><td><p>net clusterlevel features - 対応する機能を一覧表示します。</p></td></tr><tr><td><p>net clusterlevel show - 現在有効なクラスター機能レベルを表示します。</p></td></tr><tr><td><p>net clusterlevel showall - クラスター全体の詳細を表示します。</p></td></tr><tr><td><p>net clusterlevel upgrade - サポートされる最高のクラスター機能レベルへ上げます。</p></td></tr></tbody></table></div>

##### clusterlevel features {#clusterlevel-features}


<p>コンパイル時に対応しているクラスター機能を一覧表示します。</p>

<p>注: clustering=yes の場合だけサポートします。</p>

##### clusterlevel show {#clusterlevel-show}


<p>現在有効なクラスター機能レベルを表示します。</p>

<p>注: clustering=yes の場合だけサポートします。</p>

##### clusterlevel showall {#clusterlevel-showall}


<p>クラスター全体の詳細として、各ノードが対応する機能レベルの範囲、現在有効なレベル、サポートされる最高のレベルを表示します。</p>

<p>注: clustering=yes の場合だけサポートします。</p>

##### clusterlevel upgrade \[--test\] \[--apply\] {#clusterlevel-upgrade----test-----apply}


<p>全ノードが合意する、サポートされる最高のクラスター機能レベルへ上げます。現在のコードは厳格で、全ノードがまったく同じレベル範囲を提供する場合だけ許可します。</p>

<p>アップグレードのオプション:</p>

<p><code>--test</code></p>

<p>アップグレード可能かの確認だけを行います。</p>

<p><code>--apply</code></p>

<p>実際のアップグレードを行います。変更は永続的で、元に戻せません。</p>

<p>注: 引数がない場合の既定値は <code>--test</code> です。</p>

<p>注: <code>--test</code> と <code>--apply</code> のうち、1つだけ指定できます。</p>

<p>注: clustering=yes の場合だけサポートします。</p>

#### serverid {#serverid}


<p>serverid の存在を確認し、ファイルサーバーの状態データベースから古いエントリーを削除します。</p>

<p>次のコマンドが実装されています。</p>

<div class="manual-table"><table><tbody><tr><td><p>net serverid exists - serverid の存在を確認します。</p></td></tr><tr><td><p>net serverid wipedbs - ファイルサーバーの状態データベースから古いエントリーを削除します。</p></td></tr></tbody></table></div>

##### serverid exists &lt;serverid&gt; {#serverid-exists--serverid}


<p>serverid が存在するか確認します。</p>

##### serverid wipedbs {#serverid-wipedbs}


<p>ファイルサーバーの状態データベースから古いエントリーを削除します。</p>

<p>wipedbs のオプション:</p>

<p><code>--test</code></p>

<p>古いエントリーの確認とログ記録だけを行います。</p>

<p><code>--verbose</code></p>

<p>詳細なログを生成します。</p>

<p><code>--persistent</code></p>

<p>永続的なバックアップデータベースを消去します。</p>

#### HELP \[COMMAND\] {#HELP--COMMAND}


<p>指定したコマンドの使用方法を表示します。</p>
