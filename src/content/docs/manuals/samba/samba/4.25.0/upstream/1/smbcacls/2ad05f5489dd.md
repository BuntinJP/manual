### 説明 {#DESCRIPTION}


<p>このツールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p><code>smbcacls</code> プログラムは、SMB ファイル共有の NT アクセス制御リスト（ACL）を操作します。ACL は0個以上のアクセス制御エントリー（ACE）からなり、各 ACE は特定のユーザーまたはグループのアクセス制限を定義します。</p>

<p>スクリプトにパスワードを含めたり、ユーザーが入力した値をコマンドラインへ渡したりする際は注意してください。安全性のため、必要に応じて Samba クライアントツールにパスワードを尋ねさせるか、<code>kinit</code> で一度パスワードを取得する方が適切です。</p>

				domain   = &lt;value&gt;
			</code></pre>
<p>ファイルのアクセス権で、意図しないユーザーからのアクセスを確実に制限してください。</p></dd><dt><code>-P</code>|<code>--machine-pass</code></dt><dd><p>保存済みのマシンアカウントのパスワードを使います。</p></dd><dt><code>--simple-bind-dn</code>=DN</dt><dd><p>単純バインドに使う DN です。</p></dd><dt><code>--use-kerberos</code>=desired|required|off</dt><dd><p>Samba クライアントツールが Kerberos 認証を試みるかどうかを指定します。Kerberos 認証では、サービスへの接続時に IP アドレスではなく DNS 名を使ってください。既定では、Samba クライアントツールは既定の Kerberos 資格情報キャッシュ（ccache）を使おうとします。ccache がない場合、または <code>-U</code>|<code>--user</code> オプションを指定した場合、クライアントはパスワード入力を求め、Kerberos チケットを取得します（kinit）。別の Kerberos 資格情報キャッシュを使う場合は <code>--use-krb5-ccache</code> オプションを指定してください。</p>
<p>ここでこのパラメーターを指定すると、<code>${prefix}/etc/smb.conf</code> ファイルの <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#CLIENTUSEKERBEROS">client use kerberos</a> パラメーターを上書きします。</p></dd><dt><code>--use-krb5-ccache</code>=CCACHE</dt><dd><p>Kerberos 認証の資格情報キャッシュの場所を指定します。</p>
<p><code>--use-kerberos</code>=required を強制します。</p></dd><dt><code>--use-winbind-ccache</code></dt><dd><p>winbind の資格情報キャッシュを使おうとします。</p></dd><dt><code>--client-protection</code>=sign|encrypt|off</dt><dd><p>クライアントツールが使う接続保護を設定します。</p>
<p>ここでこのパラメーターを指定すると、<code>${prefix}/etc/smb.conf</code> ファイルの <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#CLIENTPROTECTION">client protection</a> パラメーターを上書きします。</p>
<p>より細かな制御が必要な場合は、<code>--option=clientsmbencrypt=OPTION</code>、<code>--option=clientipcsigning=OPTION</code>、<code>--option=clientsigning=OPTION</code> を使えます。</p></dd></dl>

### ACL の形式 {#ACL-FORMAT}


<p>ACL の形式は、カンマまたは改行で区切った1個以上のエントリーです。ACL エントリーは次のいずれかです。</p>

<pre><code> 
REVISION:&lt;revision number&gt;
OWNER:&lt;sid or name&gt;
GROUP:&lt;sid or name&gt;
ACL:&lt;sid or name&gt;:&lt;type&gt;/&lt;flags&gt;/&lt;mask&gt;</code></pre>

<p>自動継承に関係する制御ビット</p>

<ul><li><p><em>OD</em> - &quot;Owner Defaulted&quot;（既定の所有者）- セキュリティー記述子の所有者 SID が、既定の仕組みによって提供されたことを示します。</p></li><li><p><em>GD</em> - &quot;Group Defaulted&quot;（既定のグループ）- セキュリティー記述子のグループ SID が、既定の仕組みによって提供されたことを示します。</p></li><li><p><em>DP</em> - &quot;DACL Present&quot;（DACL あり）- 随意アクセス制御リスト（DACL）を持つセキュリティー記述子を示します。</p></li><li><p><em>DD</em> - &quot;DACL Defaulted&quot;（既定の DACL）- 既定の DACL を持つセキュリティー記述子を示します。</p></li><li><p><em>SP</em> - &quot;SACL Present&quot;（SACL あり）- システムアクセス制御リスト（SACL）を持つセキュリティー記述子を示します。</p></li><li><p><em>SD</em> - &quot;SACL Defaulted&quot;（既定の SACL）- セキュリティー記述子の元の提供者ではなく、既定の仕組みが SACL を提供したことを示します。</p></li><li><p><em>DT</em> - &quot;DACL Trusted&quot;（信頼された DACL）</p></li><li><p><em>SS</em> - &quot;Server Security&quot;（サーバーセキュリティー）</p></li><li><p><em>DR</em> - &quot;DACL Inheritance Required&quot;（DACL 継承が必要）- 継承可能なアクセス制御エントリー（ACE）を既存の子オブジェクトへ自動伝播できるよう DACL が設定された、必要なセキュリティー記述子を示します。</p></li><li><p><em>SR</em> - &quot;SACL Inheritance Required&quot;（SACL 継承が必要）- 継承可能な ACE を既存の子オブジェクトへ自動伝播できるよう SACL が設定された、必要なセキュリティー記述子を示します。</p></li><li><p><em>DI</em> - &quot;DACL Auto Inherited&quot;（DACL 自動継承済み）- 継承可能なアクセス制御エントリー（ACE）を既存の子オブジェクトへ自動伝播できるよう DACL が設定されたセキュリティー記述子を示します。</p></li><li><p><em>SI</em> - &quot;SACL Auto Inherited&quot;（SACL 自動継承済み）- 継承可能な ACE を既存の子オブジェクトへ自動伝播できるよう SACL が設定されたセキュリティー記述子を示します。</p></li><li><p><em>PD</em> - &quot;DACL Protected&quot;（DACL 保護）- 継承可能な ACE によってセキュリティー記述子の DACL が変更されるのを防ぎます。</p></li><li><p><em>PS</em> - &quot;SACL Protected&quot;（SACL 保護）- 継承可能な ACE によってセキュリティー記述子の SACL が変更されるのを防ぎます。</p></li><li><p><em>RM</em> - &quot;RM Control Valid&quot;（RM 制御が有効）- リソースマネージャー制御が有効であることを示します。</p></li><li><p><em>SR</em> - &quot;Self Relative&quot;（自己相対）- 自己相対セキュリティー記述子を示します。</p></li></ul>

<p>ACL のリビジョンは、セキュリティ記述子の内部 Windows NT ACL リビジョンを指定します。省略時は1です。1以外の値は予期しない動作を引き起こす可能性があります。</p>

<p>owner と group は、オブジェクトの所有者とグループの SID を指定します。S-1-x-y-z 形式の SID を指定すると、その値を使います。それ以外の場合は、ファイルまたはディレクトリが存在するサーバーを使って、指定した名前を解決します。</p>

<p>ACE は &quot;ACL:&quot; 接頭辞付きで指定し、SID に付与するアクセス権を定義します。SID は S-1-x-y-z 形式、または名前で指定できます。名前の場合は、ファイルまたはディレクトリが存在するサーバーで解決します。type、flags、mask の各値が、SID に許可するアクセスの種類を決めます。</p>

<p>type は ALLOWED または DENIED で、それぞれ SID へのアクセスを許可または拒否します。</p>

<p>flags フィールドは、継承を行う際に ACE をどう扱うかを定義します。<code>smbcacls</code> は、<em><code>--propagate-inheritance</code></em> を指定して実行するときに、これらのフラグを使います。</p>

<p>フラグは10進数または16進数の値、または対応する (XX) エイリアスで指定でき、縦棒 &quot;|&quot; で区切ります。</p>

<ul><li><p><em>(OI)</em> オブジェクト継承 0x1</p></li><li><p><em>(CI)</em> コンテナー継承 0x2</p></li><li><p><em>(NP)</em> 継承を伝播しない 0x4</p></li><li><p><em>(IO)</em> 継承のみ 0x8</p></li><li><p><em>(I)</em> 継承された ACE 0x10</p></li></ul>

<p>mask は SID に付与するアクセス権を表す値です。10進数、16進数、または同名の NT ファイルアクセス権に対応する次の文字列で指定できます。</p>

<ul><li><p><em>R</em> - 読み取りアクセスを許可します。</p></li><li><p><em>W</em> - 書き込みアクセスを許可します。</p></li><li><p><em>X</em> - オブジェクトの実行権限。</p></li><li><p><em>D</em> - オブジェクトを削除します。</p></li><li><p><em>P</em> - アクセス権を変更します。</p></li><li><p><em>O</em> - 所有権を取得します。</p></li></ul>

<p>次の組み合わせのアクセス権を指定できます。</p>

<ul><li><p><em>READ</em> - RX アクセス権と同等です。</p></li><li><p><em>CHANGE</em> - RXWD アクセス権と同等です。</p></li><li><p><em>FULL</em> - RWXDPO アクセス権と同等です。</p></li></ul>

### 継承 {#INHERITANCE}


<p>ACE ごとの継承フラグは、ACE の flags フィールドで設定できます。既定では、オブジェクト継承 (OI) やコンテナー継承 (CI) が付いた ACE など、継承可能な ACE は配下のファイルやフォルダーへ伝播しません。ただし、<em><code>--propagate-inheritance</code></em> 引数を指定すると、継承規則に従って自動的に伝播します。</p>

<ul><li><p>継承可能な (OI)(OI) ACE フラグは、フォルダーにだけ適用できます。</p></li><li><p>配下のファイルやフォルダーに適用された継承可能な ACE には、継承済み (I) フラグが付きます。伝播なし (NP) フラグが設定されていない限り、継承可能な ACE はフォルダーに適用されます。</p></li><li><p>(OI) フラグだけを持つ ACE が子フォルダーに伝播すると、継承のみを示す (IO) フラグも適用されます。これは、その ACE に対応するアクセス権が、フォルダー自身には適用されず、その子ファイルだけに適用されることを示します。子ファイルに ACE を適用する場合は、通常どおり継承されます。</p></li><li><p>(CI) フラグだけを持つ ACE は、子ファイルに伝播しても効果がなく、子フォルダーに伝播すると通常どおり継承されます。</p></li><li><p>(OI) と (CI) の両方のフラグを持つ ACE は、フォルダーとファイルの両方に通常どおり継承されます。</p></li></ul>

<p>親フォルダーに (OI)(READ) を追加</p>

<pre><code>+-parent/        (OI)(READ)
| +-file.1       (I)(READ)
| +-nested/      (OI)(IO)(I)(READ)
  |   +-file.2   (I)(READ)</code></pre>

<p>親フォルダーに (CI)(READ) を追加</p>

<pre><code>+-parent/        (CI)(READ)
| +-file.1
| +-nested/      (CI)(I)(READ)
  |   +-file.2</code></pre>

<p>親フォルダーに (OI)(CI)(READ) を追加</p>

<pre><code>+-parent/        (OI)(CI)(READ)
| +-file.1       (I)(READ)
| +-nested/      (OI)(CI)(I)(READ)
  |   +-file.2   (I)(READ)</code></pre>

<p>親フォルダーに (OI)(NP)(READ) を追加</p>

<pre><code>+-oi_dir/        (OI)(NP)(READ)
| +-file.1       (I)(READ)
| +-nested/
|   +-file.2</code></pre>

<p>親フォルダーに (CI)(NP)(READ) を追加</p>

<pre><code>+-oi_dir/        (CI)(NP)(READ)
| +-file.1
| +-nested/      (I)(READ)
|   +-file.2</code></pre>

<p>親フォルダーに (OI)(CI)(NP)(READ) を追加</p>

<pre><code>+-parent/        (CI)(OI)(NP)(READ)
| +-file.1       (I)(READ)
| +-nested/      (I)(READ)
|   +-file.2</code></pre>

<p>保護された ACL を持つファイルとフォルダーは、継承可能なアクセス権を許可しません（<em><code>-I</code></em> で設定）。このようなオブジェクトは、(CI) または (OI) による継承フラグの付いた ACE を受け取りません。</p>

### 終了状態 {#EXIT-STATUS}


<p><code>smbcacls</code> プログラムは、実行した操作の成否に応じて終了状態を設定します。終了状態は次のいずれかの値になります。</p>

<p>操作が成功すると、smbcacls は終了状態0を返します。<code>smbcacls</code> が指定したサーバーに接続できなかった場合、または ACL の取得や設定でエラーが起きた場合は、終了状態1を返します。コマンドライン引数の解析でエラーが起きた場合は、終了状態2を返します。</p>
