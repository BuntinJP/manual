### 名前 {#Name}


<p>vfs_aio_ratelimit — クラスター全体で連携する Samba の非同期 I/O レート制限</p>

### 書式 {#Synopsis}


<p><code>vfs objects = aio_ratelimit</code></p>

### 説明 {#DESCRIPTION}


<p>この VFS モジュールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p><code>aio_ratelimit</code> VFS モジュールは、非同期 I/O 操作に上限を設け、特定の共有で実行時のレート制限を可能にします。管理者は、1秒あたりの操作回数またはバイト数として上限を定義できます。いずれかの上限を超えると、現在の I/O 負荷に基づいて遅延時間（マイクロ秒）を計算し、非同期 I/O 操作に追加することで、結果的にスループットの上限を設けます。</p>

<p>バースト倍率によって許容バースト量を設定でき、長期的な上限を維持しながら、短時間は定常レートを超えられます。レート制限の状態を定期的にローカル TDB へ保存するため、クライアントの再接続や smbd の再起動をまたいでも一貫して制限を適用できます。</p>

<p><strong>クラスター対応:</strong> Samba でクラスタリングを有効にすると、既定でクラスター全体のレート制限が自動的に有効になります。各共有に設定した制限は、クラスター全体のその共有に適用されます。異なる共有の制限は、互いに独立して追跡・適用されます。</p>

<p>このモジュールは、非同期 VFS READ/WRITE 操作だけに作用します。</p>

<p>このモジュールは他のモジュールと積み重ねて使用できます。</p>

### 設定 {#CONFIGURATION}


<p>基本的な使用方法:</p>

<pre><code>	[share]
	path = /path/to/share
	vfs objects = aio_ratelimit</code></pre>

<p>クラスター構成例（クラスター全体の制限）:</p>

<pre><code>	[global]
	clustering = yes

	[shared-storage]
	path = /mnt/shared
	vfs objects = aio_ratelimit
	aio_ratelimit:read_iops_limit = 10000
	aio_ratelimit:write_bw_limit = 1G</code></pre>

<p>10000 IOPS と帯域幅1Gの制限は、クラスター全体に適用されます。</p>

<p>ノードごとに制限するクラスター構成:</p>

<pre><code>	[global]
	clustering = yes

	[shared-storage]
	path = /mnt/shared
	vfs objects = aio_ratelimit
	aio_ratelimit:read_iops_limit = 10000</code></pre>

<p>各ノードが独立して10000 IOPSの制限を適用します。</p>

### クラスターでの動作 {#CLUSTER-BEHAVIOR}


<p>Samba のクラスタリングを有効にすると、既定でクラスター全体のレート制限が自動的に有効になります。設定した制限は個々のノードではなく、<em>クラスター全体</em>に適用されます。これには <code>ratelimitd</code> デーモンが必要で、ビルド時に <code>--with-ratelimitd</code> で有効にする必要があります。</p>

<pre><code>	[share]
	aio_ratelimit:read_iops_limit = 1000</code></pre>

<p>クラスターモードを有効にすると（クラスタリングが有効な場合の既定）、その共有の稼働中の接続間で帯域幅を自動配分します。たとえば上限が1000 IOPSの場合:</p>

<ul><li><p>稼働中の接続が4つ → 各接続は約250 IOPS</p></li><li><p>稼働中の接続が10個 → 各接続は約100 IOPS</p></li><li><p>クラスター全体のスループット: 常に1000 IOPSに制限</p></li></ul>

<p>接続の確立と終了に応じて、自動的に配分します。</p>

#### 注 {#Note}


<p>稼働中の接続が多いノードは、全体の帯域幅をより多く使用します。これにより、クラスター全体で接続ごとの公平な割り当てを実現します。</p>

### バースト時の動作 {#BURST-BEHAVIOR}


<p><code>read_burst_mult</code> と <code>write_burst_mult</code> パラメーターは、設定したレート上限に対するレート制限器の最大バースト容量を制御します。実効バースト容量の計算式は <em>rate_limit * (burst_mult / 10)</em> です。</p>

<p>たとえば <code>read_iops_limit = 1000</code> と <code>read_burst_mult = 15</code> の場合、バースト容量は1000 * 1.5 = 1500 IOPSです。</p>

<p>これにより、設定した長期的な上限を維持しながら、短時間の I/O バーストでは定常レートを超えられます。</p>

<p>適切なバースト倍率はワークロードの特性によって異なります。非同期 I/O 要求が大きい、または変動が大きいワークロードでは、早すぎる抑制を避けるために高いバースト値が必要になる場合があります。一方、小規模なワークロードや遅延に敏感なワークロードでは、低い値が適する場合があります。</p>

#### 注 {#Note-2}


<p><code>read_burst_mult</code> と <code>write_burst_mult</code> パラメーターは長期平均スループットを変えません。これは引き続き、それぞれ <code>read_iops_limit</code>/<code>read_bw_limit</code> と <code>write_iops_limit</code>/<code>write_bw_limit</code> で制限されます。バースト値を高くしても、初期の加速とアイドル期間からの回復だけに影響します。</p>
