### 名前 {#Name}


<p>vfs_gpfs — ACL など GPFS 固有の Samba 拡張</p>

### 書式 {#Synopsis}


<p><code>vfs objects = gpfs</code></p>

### 説明 {#DESCRIPTION}


<p>この VFS モジュールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p><code>gpfs</code> VFS モジュールには、Samba が GPFS と適切に統合するために必要な GPFS 拡張がすべて含まれます。GPFS が提供する GPL ライブラリーインターフェースを使います。</p>

<p>現在、GPFS VFS モジュールは次の分野の拡張を提供します。</p>

<ul><li><p>GPFS 向けの設定可能なオプションを持つ NFSv4 ACL インターフェース</p></li><li><p>GPFS 上のカーネル oplock 対応</p></li><li><p>GPFS 上のリース対応</p></li></ul>

<p><code>NOTE:</code> このモジュールは POSIX ACL の動作に従うため、chown による権限の奪取を許します。chown の制限は Samba ではなく基盤のファイルシステムの責任ですが、将来的に Samba がこのモジュールを通じた制限を可能にするかもしれません。</p>

<p>このモジュールは smb.conf の <a href="https://www.samba.org/samba/docs/current/man-html/smb.conf.5.html#ACLMAPFULLCONTROL">acl map full control</a> パラメーターを使います。yes（既定値）の場合、FILE_DELETE と FILE_DELETE_CHILD 以外のすべてのファイル権限を既に含む、ファイル（ディレクトリではない）の ACE を返す際に、FILE_DELETE_CHILD ビットを追加します。これにより、NFSv4 互換 ACL を持つファイルシステムに対して動作する Windows アプリケーションが GENERIC_ALL アクセスを要求した際の ACCESS_DENIED エラーを防げます。</p>

<p>このモジュールは他のモジュールと積み重ねて使用できます。</p>

<p>Samba 4.0 以降、すべてのオプションは共有単位です。</p>

### オプション {#OPTIONS}


<p>nfs4:mode = [ simple | special ] NFS4 ACL での特殊 ID（OWNER@ と GROUP@）の置換を制御します。simple モードを推奨します。このモードでは、ファイルの所有者とグループに対する非継承 ACL エントリーだけを特殊 ID に対応付けます。このモジュールは次の MODE を認識します: <code>simple(default)</code> - 非継承 ACE だけに OWNER@ と GROUP@ 特殊 ID を使います。<code>special(deprecated)</code> - ファイルの所有者とグループに対するすべての ACE に OWNER@ と GROUP@ 特殊 ID を使います。nfs4:acedup = [dontcare|reject|ignore|merge] NFS4 ACL で重複した ACE を見つけた場合の Samba の処理方法を設定します。NFS4 ACL では同じ ID に異なるビットを持つ重複 ACE を作成できるため、Windows クライアントを混乱させる可能性があります。各値での動作は次のとおりです: <code>dontcare</code> - ACE をそのままコピーします。<code>reject (deprecated)</code> - ACL 設定操作を中止し、エラーで終了します。<code>ignore (deprecated)</code> - 2つ目の一致する ACE を含めません。<code>merge (default)</code> - 重複する2つの ACE の ace.flag フィールド同士、ace.mask フィールド同士のビット単位 OR を取り、1つの ACE にします。nfs4:chown = [yes|no] 基盤のファイルシステムが提供する chown を有効または無効にします。システムの安全性を損なう可能性があるため、有効化は慎重に行ってください。一部のファイルシステムは a) 譲渡と b) 奪取としての chown を許します。後者が危険とみなされます。各値での動作は次のとおりです: <code>yes</code> - 基盤のファイルシステムが対応する chown を有効にします。<code>no (default)</code> - chown を無効にします。</p>

### 例 {#EXAMPLES}


<p>GPFS マウントは次のように Samba 経由で公開できます。</p>

<pre><code>        [samba_gpfs_share]
	vfs objects = gpfs
	path = /test/gpfs_mount
	nfs4: mode = special
	nfs4: acedup = merge</code></pre>

### 注意事項 {#CAVEATS}


<p>GPFS のバージョンに応じて、<code>gpfs</code> VFS モジュールは実行時に <code>libgpfs_gpl</code> または <code>libgpfs</code> ライブラリーを必要とします。GPFS 3.2.1 PTF8 以降は、<code>libgpfs</code> 全体がオープンソースで利用でき、<code>libgpfs_gpl</code> は存在しなくなりました。それ以前の GPFS では、<code>libgpfs_gpl</code> ライブラリーだけがオープンソースで、実行時に利用できました。</p>

<p>ビルド時には <code>gpfs_gpl.h</code> ヘッダーファイルだけが必要です。GPFS 3.2.1 PTF8 より新しいバージョンでは、これは <code>gpfs.h</code> へのシンボリックリンクです。</p>
