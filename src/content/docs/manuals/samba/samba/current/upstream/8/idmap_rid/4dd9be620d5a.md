### 名前 {#Name}


<p>idmap_rid — Winbind用のSamba idmap_ridバックエンド</p>

### 説明 {#DESCRIPTION}


<p>idmap_ridバックエンドは、アルゴリズムによるマッピング方式でUID/GIDとSIDを対応付ける方法を提供します。マッピングは決定的であるため、この場合はデータベースが不要です。</p>

<p>現在、idmap_ridバックエンドを使用する各ドメインについて、互いに重ならない範囲を使った明示的なidmap設定が必要です。</p>

<p>注意: idmap_ridバックエンドは既定のバックエンドとして使用できません。通常は、BUILTINのSIDやその他のドメインをマッピングし、グループマッピングも作成できるように、Unix IDを生成できる <em><code>tdb</code></em> や <em><code>ldap</code></em> などのバックエンドを使い、書き込み可能な既定のidmap範囲を定義する必要があります。以下の例を参照してください。</p>

### IDMAPオプション {#IDMAP-OPTIONS}


<dl><dt>range = low - high</dt><dd><p>このバックエンドが管理する、対応付け可能なUIDとGIDの範囲を定義します。この範囲はフィルターとして機能します。アルゴリズムで決定したUIDまたはGIDが範囲外の場合、それらは無視され、対応するマッピングは破棄されます。これは、ローカルで定義したIDとリモートで定義したIDの間で、UID/GIDが意図せず重複するのを防ぐためのものです。</p></dd><dt>base_rid = INTEGER</dt><dd><p>UIDまたはGIDからSIDを構築し、SIDから取得するUIDまたはGIDの基準を調整するための基準整数を定義します。したがって、RIDがこの基準RIDより小さいSIDは除外されます。既定では許可するRIDを一切制限せず、base_ridの値は0です。</p>
<p>このパラメーターの使用は非推奨です。</p></dd></dl>

### マッピング式 {#THE-MAPPING-FORMULAS}


<p>RIDに対応するUnix IDは、次のように計算します。</p>

<pre><code>			ID = RID - BASE_RID + LOW_RANGE_ID.</code></pre>

<p>逆に、指定したUnix IDからRIDを計算する式は次のとおりです。</p>

<pre><code>			RID = ID + BASE_RID - LOW_RANGE_ID.</code></pre>

### 使用例 {#EXAMPLES}


<p>この例は、既定のIDマッピング方式をtdbのままとし、主要ドメインと信頼されたドメインの2つをidmap_ridで設定する方法を示します。また、信頼されたドメインにbase_ridパラメーターを使用する例も示しています。</p>

<pre><code>	[global]
	security = domain
	workgroup = MAIN

	idmap config * : backend        = tdb
	idmap config * : range          = 1000000-1999999

	idmap config MAIN : backend     = rid
	idmap config MAIN : range       = 10000 - 49999

	idmap config TRUSTED : backend  = rid
	idmap config TRUSTED : range    = 50000 - 99999
	idmap config TRUSTED : base_rid = 500000</code></pre>
