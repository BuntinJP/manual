### 名前 {#Name}


<p>idmap_script — Winbind用のSamba idmap_scriptバックエンド</p>

### 説明 {#DESCRIPTION}


<p>idmap_scriptプラグインは、SambaとCTDBを使用するクラスタ環境でSID/uid/gidの対応表を保存するためにwinbinddが使用する、idmap_tdb2バックエンドの代替です。スクリプトで対応付けを行う、読み取り専用バックエンドです。</p>

<p>idmap_tdb2バックエンドから派生して開発されました。提供された対応はwinbind_cache tdbに保存されるため、このバックエンド自体はSID/uid/gidの対応をTDBに保存しません。</p>

### IDMAPオプション {#IDMAP-OPTIONS}


<dl><dt>range = low - high</dt><dd><p>このバックエンドが管理する、対応付けに使用可能なuidとgidの範囲を定義します。</p></dd><dt>script</dt><dd><p>IDの対応付けを行う外部プログラムを、このオプションで設定できます。</p></dd></dl>

### IDMAPスクリプト {#IDMAP-SCRIPT}


<p>script idmapバックエンドは、<code>${prefix}/etc/smb.conf</code> の <em><code>idmap config * : script</code></em> オプション、または非推奨の旧形式 <em><code>idmap : script</code></em> により、IDの対応付けを行う外部プログラムをサポートします。</p>

<p>スクリプトは、次のコマンドラインオプションを受け付ける必要があります。</p>

<pre><code>	SIDTOID S-1-xxxx
	IDTOSID UID xxxx
	IDTOSID GID xxxx
	IDTOSID XID xxxx</code></pre>

<p>また、次の応答のいずれかを、1行のテキストとして返す必要があります。</p>

<pre><code>	UID:yyyy
	GID:yyyy
	XID:yyyy
	SID:ssss
	ERR:yyyy</code></pre>

<p>XIDは、返されるIDがUIDとGIDの両方であるべきことを示します。つまり、ID_TYPE_BOTHを要求しますが、その要求に応えられるかどうかは、最終的にはスクリプト次第です。UIDまたはGIDのどちらか一方の対応だけを返すこともできます。</p>

### 使用例 {#EXAMPLES}


<p>次の例は、scriptパラメーター経由で外部プログラムを使用し、scriptを既定のidmapバックエンドとする方法を示します。</p>

<pre><code>	[global]
	idmap config * : backend = script
	idmap config * : range = 1000000-2000000
	idmap config * : script = /usr/local/samba/bin/idmap_script.sh</code></pre>

<p>次に、処理の一部を行う単純なスクリプトを示します。</p>

<pre><code>	#!/bin/sh
	#
	# Uncomment this if you want some logging
	#echo $@ &gt;&gt; /tmp/idmap.sh.log
	if [ &quot;$1&quot; == &quot;SIDTOID&quot; ]
	then
		# Note. The number returned has to be within the range defined
		#echo &quot;Sending UID:1000005&quot; &gt;&gt; /tmp/idmap.sh.log
		echo &quot;UID:1000005&quot;
		exit 0
	else
		#echo &quot;Sending ERR: No idea what to do&quot; &gt;&gt; /tmp/idmap.sh.log
		echo &quot;ERR: No idea what to do&quot;
		exit 1
	fi</code></pre>

<p>もちろん、このスクリプトだけでは不十分です。おそらくwbinfoを使って入力されたSIDがユーザーのSIDかグループのSIDかを判定し、対応表を検索するか、別の仕組みを使ってSIDをUIDなどに対応付ける必要があります。</p>

<p>スクリプトは、環境変数_NO_WINBINDDを1に設定して呼び出される点に注意してください。これにより、wbinfoの明示的な呼び出しと、nss_winbind経由の暗黙的な呼び出しの両方について、スクリプトからwinbindへの再帰呼び出しを防ぎます。たとえば <code>ls -l</code> の呼び出しでも、そのような無限再帰を引き起こす可能性があります。</p>

<p>idmapスクリプト内から <code>wbinfo -n</code> と <code>wbinfo -s</code> を呼び出すことは安全です。その際、再帰を防ぐため、スクリプトは <code>wbinfo</code> 呼び出しの直前に環境変数_NO_WINBINDDを解除し、<code>wbinfo</code> から戻った直後に再び1に設定しなければなりません。</p>
