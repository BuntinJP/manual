### 名前 {#Name}


<p>idmap_autorid — Winbind 用の Samba idmap_autorid バックエンド</p>

### 説明 {#DESCRIPTION}


<p>idmap_autorid バックエンドは、idmap_tdb より決定性が高く、idmap_rid より設定しやすいアルゴリズムによって UID/GID と SID を対応付けます。</p>

<p>このモジュールは idmap_rid と似た動作をしますが、各ドメインに使う範囲を自動設定するため、フォレスト内のドメインごとに範囲を指定する必要はありません。必要なのは、ユーザー/グループの対応付けに使う UID/GID の範囲と、任意で各範囲のサイズを設定することだけです。</p>

<p>どのドメインをどの範囲に対応付けるかは autorid.tdb に保存されるため、このデータベースを定期的にバックアップしてください。</p>

<p>使用するアルゴリズムにより、最小限の設定だけで済むため、最も使いやすいモジュールです。</p>

### IDMAP オプション {#IDMAP-OPTIONS}


<dl><dt>range = low - high</dt><dd><p>このバックエンドが管理する、対応付け可能な UID/GID の範囲を定義します。この範囲はフィルターとして働きます。アルゴリズムで求めた UID または GID が範囲外の場合は無視し、対応付けを破棄します。ローカルとリモートで定義された ID の意図しない重複を防ぐためのものです。範囲は rangesize の倍数で、必須の BUILTIN ドメインに十分な ID 範囲を確保するため、少なくともその2倍の大きさが必要です。既定の rangesize が100000なら、範囲には少なくとも200000個の ID が必要です。たとえば range = 100000 - 299999 となります。</p></dd><dt>rangesize = numberofidsperrange</dt><dd><p>ドメイン範囲ごとに使える UID/GID 数を定義します。最小値は2000です。この値より大きい RID を持つ SID は、利用できる範囲数に応じて拡張範囲へ対応付けます。autorid バックエンドが利用可能な範囲を使い切ると、新しいドメイン（または既知のドメインの新しい拡張範囲）への対応付け要求は無視され、対応付けは破棄されます。</p>
<p>例: rangesize が10000の場合、RID が10000までのユーザー/グループはドメインの最初の範囲に入ります。RID が25000のオブジェクトを対応付けようとすると、20000–29999のすべての RID に使う拡張範囲を割り当てます。</p>
<p>1つの範囲をローカルユーザーとグループ、および Everyone（S-1-1-0）や Creator Owner（S-1-3-0）などのドメイン外の既知 SID に使います。選ばれた既知 SID の一覧は、決定的な対応付けを作るため初回起動時に事前割り当てされます。</p>
<p>したがって、このオプションは作成できるローカルユーザーとグループの数も制限します。多数を作成する予定なら、それに応じてこのパラメーターを設定する必要があります。</p>
<p>既定値は100000です。</p></dd><dt>read only = [ yes | no ]</dt><dd><p>モジュールを読み取り専用モードにします。新しい範囲は割り当てず、idmap プール内に新しい対応付けも作成しません。既定値は no です。</p></dd><dt>ignore builtin = [ yes | no ]</dt><dd><p>BUILTIN ドメインの対応付け要求をすべて無視します。既定値は no です。</p></dd></dl>

### 対応付けの式 {#THE-MAPPING-FORMULAS}


<p>RID に対応する Unix ID は次のように計算します。</p>

<pre><code>			ID =  REDUCED RID + IDMAP RANGE LOW VALUE + RANGE NUMBER * RANGE SIZE</code></pre>

<p>ここで REDUCED RID = RID % RANGE_SIZE です。また DOMAIN RANGE INDEX = RID / RANGE_SIZE をドメイン SID とともに使い、RANGE NUMBER（データベースに保存）を決めます。</p>

<p>逆に、指定した Unix ID から RID を計算する式は次のとおりです。</p>

<pre><code>			RID = (ID - LOW ID) % RANGE SIZE + DOMAIN RANGE INDEX * RANGE SIZE</code></pre>

<p>ここで DOMAIN RANGE INDEX は、RANGE NUMBER = (ID - LOW ID) / RANGE SIZE を使って、ドメイン SID とともにデータベースから取得します。</p>

### 例 {#EXAMPLES}


<p>この例は、主ドメインと19個の信頼ドメイン/範囲拡張で動作する最小限の設定です。</p>

<pre><code>	[global]
	security = ads
	workgroup = CUSTOMER
	realm = CUSTOMER.COM

	idmap config * : backend = autorid
	idmap config * : range = 1000000-1999999
</code></pre>

<p>この例は、多数のユーザーが存在し得るすべてのドメインの既定として idmap_autorid を設定し、SFU 対応付け方式を使う信頼ドメインには個別の設定を与える方法を示します。idmap 範囲と sfu 範囲は重複できないことに注意してください。</p>

<pre><code>	[global]
	security = ads
	workgroup = CUSTOMER
	realm = CUSTOMER.COM

	idmap config * : backend = autorid
	idmap config * : range = 1000000-19999999
	idmap config * : rangesize = 1000000

	idmap config TRUSTED : backend  = ad
	idmap config TRUSTED : range    = 50000 - 99999
	idmap config TRUSTED : schema_mode = sfu</code></pre>
