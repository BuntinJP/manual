### 名前 {#Name}


<p>idmap_ad — Winbind 用の Samba idmap_ad バックエンド</p>

### 説明 {#DESCRIPTION}


<p>idmap_ad プラグインは、RFC2307/SFU スキーマ拡張を使う AD サーバーから Winbind が ID 対応付けを読み取れるようにします。このモジュールは &quot;idmap&quot; API だけを実装し、読み取り専用です。管理者は事前に、AD のユーザーに uidNumber 属性、グループに gidNumber 属性を追加して対応付けを用意する必要があります。Winbind は uidNumber を持ち、プライマリーグループに gidNumber 属性が設定されているユーザーだけを対応付けます。ただし、使用するすべてのグループに gidNumber 属性を割り当てることを推奨します。割り当てないグループは動作しません。</p>

<p>現在、<em><code>ad</code></em> バックエンドは既定の idmap バックエンドとしては動作せず、利用する各ドメインに、互いに重ならない範囲を使って個別に設定する必要があります。BUILTIN の SID やその他の信頼ドメインを対応付けるため、通常は <em><code>tdb</code></em> または <em><code>ldap</code></em> などのバックエンドで、書き込み可能な既定 idmap 範囲を設定する必要があります。グループの対応付けを作成するためにも書き込み可能な既定設定が必要です。この包括的な既定 idmap 設定の範囲は、<em><code>ad</code></em> バックエンドを明示的に設定したどのドメインとも重複してはいけません。後述の例を参照してください。</p>

### IDMAP オプション {#IDMAP-OPTIONS}


<dl><dt>range = low - high</dt><dd><p>このバックエンドが管理する、対応付け可能な UID/GID の範囲を定義します。この範囲はフィルターとして働きます。指定した場合、AD 内の UID/GID が範囲外なら無視し、その対応付けを破棄します。ローカルとリモートで定義された ID の意図しない重複を防ぐためのものです。</p></dd><dt>schema_mode = &lt;rfc2307 | sfu | sfu20&gt;</dt><dd><p>ユーザーとグループの情報を Active Directory に問い合わせる際に idmap_ad が使うスキーマを定義します。Windows Server 2003 R2 以降の RFC2307 スキーマ、またはそれ以前の Service for Unix（SFU）スキーマを使えます。SFU 3.0/3.5 は &quot;sfu&quot;、SFU 2.0 は &quot;sfu20&quot; を選んでください。プライマリーグループへの所属の動作は <em>unix_primary_group</em> オプションで制御することに注意してください。</p>
<p>既定値: rfc2307</p></dd><dt>unix_primary_group = yes/no</dt><dd><p>ユーザーのプライマリーグループを SFU 属性から取得するか、AD のプライマリーグループから取得するかを定義します。<em><code>yes</code></em> の場合は LDAP 属性（gidNumber）から取得し、<em><code>no</code></em> の場合は &quot;primaryGroupID&quot; LDAP 属性から計算します。</p>
<p>既定値: no</p></dd><dt>unix_nss_info = yes/no</dt><dd><p><em><code>yes</code></em> の場合、winbind はログインシェルとホームディレクトリを LDAP 属性から取得します。<em><code>no</code></em> の場合、または AD の LDAP エントリーに SFU 属性がない場合は、<em>template shell</em> と <em>template homedir</em> オプションを使います。</p>
<p>既定値: no</p></dd><dt>all_groupmem = yes/no</dt><dd><p><em><code>yes</code></em> の場合、winbind は getgrnam(3)、getgrgid(3)、getgrent(3) 呼び出しに対して、uidNumber がないものも含め、すべてのグループメンバーを取得します。</p>
<p>既定値: no</p></dd><dt>deny ous</dt><dd><p>このパラメーターは、ad idmap モジュールでオブジェクトを対応付けない OU の一覧です。<em><code>deny ous</code></em> を設定し、<em><code>allow ous</code></em> を設定しない場合、<em><code>deny ous</code></em> に列挙した OU の外にあるすべてのオブジェクトを許可します。</p>
<p>既定値: なし</p></dd><dt>allow ous</dt><dd><p>このパラメーターは、ad idmap モジュールでオブジェクトを対応付ける OU の一覧です。<em><code>allow ous</code></em> を設定し、<em><code>deny ous</code></em> を設定しない場合、<em><code>allow ous</code></em> の OU の外にあるすべてのオブジェクトを拒否します。</p>
<p><em><code>allow ous</code></em> と <em><code>deny ous</code></em> の両方を設定した場合は、最初に <em><code>deny ous</code></em> を評価し、次に <em><code>allow ous</code></em> を調べます。AD オブジェクトがどちらにも一致しない場合は拒否します。</p>
<p>既定値: なし</p></dd></dl>

### 例 {#EXAMPLES}


<p>次の例は、主 AD ドメインと信頼 AD ドメインから ID 対応付けを取得する方法を示します。信頼ドメインがある場合は、ID の競合を事前に解決する必要があります。この時点では競合する対応付けを解決する順序は保証されません。また、BUILTIN などの内部バックエンドで使えるローカル ID 割り当て用に、競合しない小さな範囲を残す方法も示します。</p>

<pre><code>	[global]
	workgroup = CORP

	idmap config * : backend = tdb
	idmap config * : range = 1000000-1999999

	idmap config CORP : backend  = ad
	idmap config CORP : range = 1000-999999</code></pre>
