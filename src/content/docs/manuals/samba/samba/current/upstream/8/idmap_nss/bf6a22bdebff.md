### 名前 {#Name}


<p>idmap_nss — Winbind 用の Samba idmap_nss バックエンド</p>

### 説明 {#DESCRIPTION}


<p>idmap_nss プラグインは、Unix のユーザーとグループを Windows アカウントに対応付ける手段を提供します。これにより、jsmith という Unix ユーザーの SID が、DOMAIN\jsmith に割り当てられた SID として報告されるよう簡単にできます。これは、Samba メンバーサーバーに格納されたファイルとプリンターの ACL を報告するために必要です。</p>

### IDMAP オプション {#IDMAP-OPTIONS}


<dl><dt>range = low - high</dt><dd><p>このバックエンドが管理を担当する、利用可能な UID と GID の対応付け範囲を定義します。この範囲はフィルターとして働く点に注意してください。NSS モジュールが返した UID または GID が範囲外の場合は無視され、対応するマッピングは破棄されます。これは、ローカルで定義された ID とリモートで定義された ID の間で UID/GID が誤って重複することを避けるための仕組みです。</p></dd><dt>use_upn = &lt;yes | no&gt;</dt><dd><p>一部の NSS モジュールは、UPN やダウンレベルのログオン名（DOMAIN\user や user@REALM など）を返して処理できます。</p>
<p>このパラメーターを有効にすると、NSS が返す名前を解析し、得られた名前空間を IDMAP のドメイン名の代わりに正式な名前空間として使用します。また、NSS モジュールへユーザーの正しいドメインの手掛かりを渡すため、単純なユーザー名の代わりにダウンレベルのログオン名を NSS に送ります。</p>
<p>既定値: no</p></dd></dl>

### 使用例 {#EXAMPLES}


<p>この例では、既定のドメイン（*）と信頼された各ドメインには新しいマッピングを割り当てつつ、idmap_nss を使用して自ドメイン（SAMBA）のローカルアカウント ID を NSS から取得する方法を示します。</p>

<pre><code>	[global]
	idmap config * : backend = tdb
	idmap config * : range = 1000000-1999999

	idmap config SAMBA : backend  = nss
	idmap config SAMBA : range = 1000-999999</code></pre>
