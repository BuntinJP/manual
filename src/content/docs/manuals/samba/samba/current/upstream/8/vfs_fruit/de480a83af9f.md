### 名前 {#Name}


<p>vfs_fruit — OS X と Netatalk との相互運用性を強化する</p>

### 書式 {#Synopsis}


<p><code>vfs objects = fruit</code></p>

### 説明 {#DESCRIPTION}


<p>この VFS モジュールは <a href="https://www.samba.org/samba/docs/current/man-html/samba.7.html">samba(7)</a> スイートの一部です。</p>

<p><code>vfs_fruit</code> モジュールは Apple SMB クライアントとの互換性、および Netatalk 3 AFP ファイルサーバーとの相互運用性を強化します。</p>

<p>文字変換を有効にする場合は <code>vfs_catia</code> と重ねて使用してください。また、<code>vfs_streams_xattr</code> と重ねて使用することは必須です。正しい設定は使用例の節を参照してください。</p>

<p>このモジュールは共有の代替データストリーム (ADS) を有効にし、OS X 固有のストリーム &quot;AFP_AfpInfo&quot; と &quot;AFP_Resource&quot; を捕捉して特別に処理します。ほかの名前付きストリームはすべて <code>vfs_streams_xattr</code> に委ねます。このモジュールは <code>vfs_fruit</code> とともに読み込む必要があります。</p>

<p>vfs_fruit を使用する共有と使用しない共有を混在させる場合は注意してください。OS X クライアントは最初の tcon で SMB2 AAPL プロトコル拡張をネゴシエートするため、混在時に最初の tcon が fruit を使用しないと、AAPL が全体で無効になります。</p>

<p>OS X クライアント用の共有で ADS を有効にすることは有益です。Apple 自身の SMB サーバー実装の動作に似ており、Samba の大文字と小文字を区別するセマンティクスによる深刻な性能低下を避けられるためです。</p>

<p><code>fruit:resource = file</code> と <code>fruit:metadata = netatalk</code> を設定すると、OS X メタデータとリソースフォークストリームを Netatalk 3 と互換性のある方法で保存できます。</p>

<p>OS X は SMB 要求内で、NTFS で不正な文字を Unicode 私用領域に対応付けます。<code>fruit:encoding = native</code> を設定すると、対応付けられた文字をすべて本来の ASCII 文字に変換します。</p>

<p>さらに、<code>fruit:locking = netatalk</code> を設定すれば、共有アクセスモードを Netatalk AFP の共有モードに照らして確認できます。</p>

<p>このマニュアルページで説明した組み合わせ以外では、このモジュールを重ねて使用できません。</p>

### グローバルオプション {#GLOBAL-OPTIONS}


<p>次のオプションは smb.conf の global セクションに設定する必要があります。共有単位で設定しても効果はありません。</p>

<dl><dt>fruit:aapl = yes | no</dt><dd><p>AAPL というコード名の Apple SMB2+ 拡張を有効にするかどうかを指定する<em>グローバル</em>オプションです。既定値は <em>yes</em> です。この拡張は Mac から接続するときの次の不足を改善します。</p>
<ul><li><p>ディレクトリー列挙に Mac 関連のファイルシステムメタデータ（UNIX モード、FinderInfo、リソースフォークのサイズ、実効権限）が追加されます。Mac クライアントが各ディレクトリーエントリーについて個別に取得する必要がなくなり、多くの場合、大幅に性能が向上します。</p></li><li><p>ディレクトリーエントリーの UNIX モードを照会・変更できます。</p></li></ul>
<p><em>fruit:aapl</em> が有効な場合に作用する、共有単位のオプション群があります。以下のオプションで、ディレクトリー列挙時の特定の Mac メタデータの計算を無効にできます。いずれも既定で有効です。</p>
<ul><li><p>readdir_attr:aapl_rsize = yes | no</p></li><li><p>readdir_attr:aapl_finder_info = yes | no</p></li><li><p>readdir_attr:aapl_max_access = yes | no</p></li></ul>
<p>これらのオプションの説明は後述します。</p></dd><dt>fruit:nfs_aces = yes | no</dt><dd><p>NFS ACE を介したディレクトリーエントリーの UNIX モードの照会・変更をサポートするかどうかを指定する<em>グローバル</em>オプションです。既定値は <em>yes</em> です。</p></dd><dt>fruit:copyfile = yes | no</dt><dd><p>付随するすべてのメタデータとともにファイル全体のコピーを要求する、OS X 固有の copychunk ioctl を有効にするかどうかを指定する<em>グローバル</em>オプションです。</p>
<p>警告: copyfile 要求は、サーバーがコピーを行っている間クライアントをブロックします。</p>
<p>既定値は <em>no</em> です。</p></dd><dt>fruit:model = MacSamba</dt><dd><p>AAPL 拡張内のモデル文字列を定義し、Finder ウィンドウで Samba サーバーを表すアイコンの外観を決定します。</p>
<p>既定値は <em>MacSamba</em> です。</p></dd></dl>

### オプション {#OPTIONS}


<p>次のオプションは smb.conf の global セクションでも共有単位でも設定できます。</p>

<dl><dt>fruit:resource = [ file | xattr | stream ]</dt><dd><p>OS X リソースフォークの保存場所を制御します。</p>
<p>4.6.0 より前のすべての Samba バージョンにあったスペルのバグにより、このオプションは s を 2 個含む <em>fruit:ressource</em> とも指定できます。</p>
<p>設定値:</p>
<ul><li><p><code>file (default)</code> - OS X と Netatalk に互換性のある ._ AppleDouble ファイルを使用します。</p></li><li><p><code>xattr</code> - xattr を使用します。大きな xattr をサポートするファイルシステムと、xattr に対応するファイル I/O API が必要です。該当するのは Solaris とその派生プラットフォーム、および ZFS です。</p></li><li><p><code>stream (experimental)</code> - VFS スタック内の次のモジュールにストリームを渡します。<em>警告:</em> ほとんどのファイルシステムには拡張属性のサイズ制限があるため、<em>streams_xattr</em> モジュールとこのオプションを併用しないでください。</p></li></ul></dd><dt>fruit:time machine = [ yes | no ]</dt><dd><p>FULLSYNC ボリューム機能を介して Time Machine サポートをクライアントに通知するかどうかを制御します。</p>
<ul><li><p><code>yes</code> - この共有の Time Machine サポートを有効にします。Samba が mDNS サポート付きでビルドされている場合、共有を mDNS にも登録します。</p></li><li><p><code>no (default)</code> Time Machine サポートの通知を無効にします。</p></li></ul>
<p>このオプションは、共有ごとに次の設定を強制します（グローバルで有効にした場合は全共有）。</p>
<ul><li><p><code>durable handles = yes</code></p></li><li><p><code>kernel oplocks = no</code></p></li><li><p><code>kernel share modes = no</code></p></li><li><p><code>posix locking = no</code></p></li></ul></dd><dt>fruit:time machine max size = SIZE [K|M|G|T|P]</dt><dd><p>Time Machine に便利な機能です。報告するディスクサイズを制限し、実際の全ディスク領域がバックアップに使われるのを防ぎます。数値と任意の単位を指定します。</p>
<p><em>重要</em>: これは Time Machine の sparsebundle イメージの内容だけを考慮する概算です。このオプションを使用するときは、ほかの内容をこのボリュームに保存しては<em>いけません</em>。計算に含まれないためです。</p>
<p>sparsebundle の Info.plist XML ファイルからバンドサイズを読み、bands/ ディレクトリー内のバンドファイル数を数え、両者を掛け合わせて計算します。</p></dd><dt>fruit:metadata = [ stream | netatalk ]</dt><dd><p>OS X メタデータストリームの保存場所を制御します。</p>
<ul><li><p><code>netatalk (default)</code> - Netatalk 互換の xattr を使用します。</p></li><li><p><code>stream</code> - VFS スタック内の次のモジュールにストリームを渡します。</p></li></ul></dd><dt>fruit:locking = [ netatalk | none ]</dt><dd><ul><li><p><code>none (default)</code> - プロトコル間のロックを行いません。</p></li><li><p><code>netatalk</code> - Netatalk とのプロトコル間ロックを使用します。</p></li></ul></dd><dt>fruit:encoding = [ native | private ]</dt><dd><p>OS X クライアントでよく使われる、NTFS では不正な ASCII 文字群をファイルシステムに保存する方法を制御します。</p>
<p><em>重要:</em> <em>fruit:metadata=stream</em> または <em>fruit:resource=stream</em> とは完全には動作しないことがわかっています。</p>
<ul><li><p><code>private (default)</code> - OS X クライアントがエンコードしたまま、Unicode 私用領域に対応付けた文字として保存します。</p></li><li><p><code>native</code> - 本来の ASCII 値で文字を保存します。<em>重要</em>: 使用例の節に示すように、VFS モジュールスタックで <em>vfs_catia</em> を使用する必要があります。</p></li></ul></dd><dt>fruit:veto_appledouble = yes | no</dt><dd><p><em>注記:</em> このオプションが適用されるのは、<em><code>fruit:resource</code></em> を <em><code>file</code></em>（既定値）に設定した場合だけです。</p>
<p><em><code>fruit:resource</code></em> を <em><code>file</code></em> に設定すると、vfs_fruit は ._ AppleDouble ファイルを作成することがあります。このオプションは、そのファイルを veto 対象にしてクライアントのアクセスを防ぐかどうかを制御します。</p>
<p>._ ファイルを veto 対象にすると、一部のアプリケーションが動作しなくなる可能性があります。たとえば Mac の ZIP アーカイブには ._ ファイルが含まれるため、Mac クライアントからの展開が失敗します。<code>rsync</code> も、アンダースコアで始まるファイルの同期に使う一時ファイルが ._ で始まり作成できなくなるため、それらを同期できません。</p>
<p>false にするとこの問題は解決しますが、内部的に作成した ._ ファイルを公開することで、ほかの未知の副作用が生じる可能性があります。</p>
<p>既定値は <em>yes</em> です。</p></dd><dt>readdir_attr:aapl_rsize = yes | no</dt><dd><p>SMB2 FIND 応答でリソースフォークのサイズを返します。</p>
<p>既定値は <em>yes</em> です。</p></dd><dt>readdir_attr:aapl_finder_info = yes | no</dt><dd><p>SMB2 FIND 応答で FinderInfo を返します。</p>
<p>既定値は <em>yes</em> です。</p></dd><dt>readdir_attr:aapl_max_access = yes | no</dt><dd><p>SMB2 FIND 応答でユーザーの実効最大権限を返します。これはコストの高い計算です。off にすると、ユーザーが最大の実効権限を持つものとして扱います。</p>
<p>既定値は <em>yes</em> です。</p></dd><dt>fruit:wipe_intentionally_left_blank_rfork = yes | no</dt><dd><p>macOS クライアントが時折作成する、286 バイトの特殊なプレースホルダー blob と一致するリソースフォークデータを消去するかどうかを指定します。この blob は “This resource fork intentionally left blank” という文字列を含み、残りのバイトの大部分はゼロです。このデータには用途がないので、おそらく破棄しても安全です。有効な場合、モジュールはリソースフォークストリームを 0 バイトに切り詰めます。</p>
<p>既定値は <em>no</em> です。</p></dd><dt>fruit:delete_empty_adfiles = yes | no</dt><dd><p>空の AppleDouble ファイルを削除するかどうかを指定します。空とは、AppleDouble ファイルのリソースフォークエントリーのサイズが 0、またはちょうど 286 バイトで、macOS が作成する特殊な定型リソースフォークと内容が一致することを意味します。</p>
<p>既定値は <em>no</em> です。</p></dd><dt>fruit:zero_file_id = yes | no</dt><dd><p>クライアントが AAPL をネゴシエートした場合、ディスク上のファイル識別子の照会にゼロを返すかどうかを指定します。</p>
<p>Mac アプリケーションや Mac SMB クライアントのコードは、ディスク上のファイル識別子に HFS+ Catalog Node Identifier (CNID) のセマンティクスを期待します。Samba の File-ID はファイルの inode 番号に基づいており、ファイル作成・削除の間で再利用されるため、Mac クライアントでは使用できません。識別子としてゼロを返すと、Mac クライアントはサーバーが返すファイル ID を使用・信頼しなくなります。</p>
<p>既定値は <em>yes</em> です。</p></dd><dt>fruit:convert_adouble = yes | no</dt><dd><p>._ AppleDouble の付随ファイルをネイティブストリーム（vfs_streams_xattr 使用時は xattr）に変換するかどうかを指定します。主な用途は、ストリーム非対応のサーバー構成で macOS クライアントが作成した付随ファイルを透過的に移行することです。</p>
<p>既定値は <em>yes</em> です。</p></dd><dt>fruit:validate_afpinfo = yes | no</dt><dd><p>Apple クライアントは AFP_AfpInfo ストリームに構造化されたファイルメタデータを保存します。ストリーム内のマーシャリング済みデータの先頭 8 バイトにはヘッダー情報が含まれます。Apple の SMB サーバーと Samba は、このストリームへのクライアントの書き込み要求を処理するときにヘッダーを検証し、検証に失敗すると書き込みを失敗させます。通常この検証は正しいものですが、サードパーティー SMB サーバーから Samba サーバーへのデータ移行では、何らかの理由でヘッダーが壊れたデータをクライアントが移行しようとする場合があります。そのような移行とヘッダー修復を可能にするため、このオプションを <em>no</em> にして検証を一時的に無効にできます。</p>
<p>既定値は <em>yes</em> です。</p></dd><dt>fruit:veto_localized = yes | no</dt><dd><p><em><code>fruit:veto_localized</code></em> を <em><code>yes</code></em> に設定すると、vfs_fruit は <em>.localized</em> ファイルまたはディレクトリーへのアクセスを自動的に veto します。これらは Mac OS がフォルダー名のローカライズ（通常は <em>Desktop</em>、<em>Music</em> など）を提供するために作成されます。非常に大きなディレクトリーの一覧表示時、Mac クライアントは各エントリーについて .localized ファイルの有無を問い合わせることがあります。クラスターファイルシステムとの組み合わせでは、一覧表示全体の性能に大きく影響する可能性があります。フォルダー名の翻訳が不要な場合、このオプションにより照会時にサーバーがファイルシステム層へ進まなくなり、追加のネットワーク負荷を避けられます。</p>
<p>既定値は <em>no</em> です。</p></dd><dt>fruit:posix_opens = yes | no</dt><dd><p><em><code>fruit:posix_opens</code></em> を <em><code>yes</code></em> に設定すると、vfs_fruit はすべてのファイルシステムのセマンティクスを内部的に変換し、Windows ではなく POSIX の動作を使用します。Mac はファイルシステムのセマンティクスに関して Windows より POSIX に近いため、多くの特殊な場合のアクセス動作が改善されます。</p>
<p>既定値は <em>yes</em> です。</p></dd><dt>fruit:ignore_zero_aces = yes | no</dt><dd><p><em><code>fruit:ignore_zero_aces</code></em> が有効な場合、ネットワーク経由で送信された ACL に ACE が一つも含まれていなければ、ファイルシステム権限の変更要求は失敗します。ACE を含めないこと自体は完全に有効なクライアント動作ですが、その結果、管理者が権限を修復しない限り、それ以降ファイルにアクセスできなくなります。</p>
<p>この問題のある動作は最新の macOS バージョンで報告されており、この新しいオプションで回避できます。</p>
<p>既定値は <em>yes</em> です。</p></dd></dl>
