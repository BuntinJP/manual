## cifs\.idmap {#cifs-idmap}


### Common Internet File System \(CIFS\) の ID を対応付けるユーザー空間ヘルパー {#Userspace-helper-for-mapping-ids-for-Common-Internet-File-System--CIFS}


<dl><dt>マニュアルセクション:</dt><dd><p>8</p></dd></dl>

#### 書式 {#SYNOPSIS}


<blockquote><p>cifs.idmap [<code>--help</code>|<code>-h</code>] [<code>--timeout</code>|<code>-t</code>] [<code>--version</code>|<code>-v</code>] {keyid}</p></blockquote>

#### 説明 {#DESCRIPTION}


<p>このツールは cifs-utils スイートの一部です。</p>

<p>cifs.idmap は Linux CIFS クライアントファイルシステム用のユーザー空間ヘルパープログラムです。カーネル自身では容易に実行できない処理がいくつかあります。このプログラムは、それらをカーネルに代わって実行し、結果を返すコールアウトプログラムです。</p>

<p>cifs.idmap は通常、カーネルが特定のキー型について request-key(8) を呼び出すときに実行されることを意図しています。コマンドラインから直接実行することもできますが、通常はそのような実行を意図していません。</p>

<p>このプログラムが呼び出されるのは、cifsacl マウントオプションを使用して共有をマウントした場合のみです。このマウントオプションが指定された場合に限り、カーネルはこの変換のためのアップコールを行います。</p>

<p>cifs.idmap は ID マッピングの処理をプラグインに依存しています。プラグインを見つけられないと正しく動作しません。プラグイン（またはそれへのシンボリックリンク）は @pluginpath@ に配置する必要があります。</p>

<p>cifs.idmap またはプラグインが利用できない場合、マウントされた共有内のファイルオブジェクトには、その共有をマウントしたプロセスの資格情報の uid と gid が割り当てられます。この場合、所有者 SID とグループ SID に対応付ける既定の uid と gid を、uid および gid マウントオプションで指定することを強く推奨します。</p>

#### オプション {#OPTIONS}


<dl><dt><code>--help</code>|<code>-h</code></dt><dd><p>使用方法のメッセージを表示して終了します。</p></dd><dt><code>--timeout</code>|<code>-t</code></dt><dd><p>キーの有効期限タイマーを秒単位で設定します。既定値は 600 秒（10 分）です。0 に設定するとキーは期限切れになりません。</p></dd><dt><code>--version</code>|<code>-v</code></dt><dd><p>バージョン番号を表示して終了します。</p></dd></dl>

#### KEYCTL の設定 {#CONFIGURATION-FOR-KEYCTL}


<p>cifs.idmap は、request-key コールアウトプログラムを介してカーネルから呼び出されるよう設計されています。そのため、request-key にこのプログラムの場所と呼び出し方を知らせる必要があります。現在 cifs.idmap は次のキー型を処理します。</p>

<pre><code>cifs.idmap</code></pre>

<p>このキー型は、SID を uid または gid に対応付けるためのものです。</p>

<p>このプログラムを CIFS で利用するには、request-key.conf(5) にエントリーを設定する必要があります。このキー型のエントリーの例を示します。</p>

<pre><code>#OPERATION  TYPE           D C PROGRAM ARG1 ARG2...
#=========  =============  = = ================================
create      cifs.idmap     * * @sbindir@/cifs.idmap %k</code></pre>

<p>各フィールドの詳細については request-key.conf(5) を参照してください。</p>
