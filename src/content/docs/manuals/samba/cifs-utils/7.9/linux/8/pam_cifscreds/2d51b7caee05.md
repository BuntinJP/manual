## pam\_cifscreds {#pam_cifscreds}


### カーネルキーリング内の NTLM 資格情報を管理する PAM モジュール {#PAM-module-to-manage-NTLM-credentials-in-kernel-keyring}


<dl><dt>マニュアルのセクション:</dt><dd><p>8</p></dd></dl>

#### 書式 {#SYNOPSIS}


<p>NTLM 資格情報を自動登録するシステムの PAM 設定ファイル（<em>/etc/pam.d/login</em> など）を編集し、次のように変更します。</p>

<pre><code>    ...
    auth       substack     system-auth
+++ auth       optional     pam_cifscreds.so
    auth       include      postlogin
    ...

    ...
    session    include      system-auth
+++ session    optional     pam_cifscreds.so domain=DOMAIN
    session    include      postlogin
    ...</code></pre>

<p>DOMAIN を Windows ドメイン名に置き換えるか、後述の host= を使います。</p>

#### 説明 {#DESCRIPTION}


<p>pam_cifscreds PAM モジュールは、マルチユーザーマウントでセッションを確立するための資格情報（ユーザー名とパスワード）を自動追加するツールです。</p>

<p>cifs ファイルシステムを &quot;multiuser&quot; オプションでマウントし、krb5 認証を使わない場合は、各ユーザーの資格情報をどこかから取得できる必要があります。pam_cifscreds モジュールを使うと、ログイン時にこれらの資格情報をカーネルへ自動的に提供できます。</p>

<p>PAM 設定ファイルの session セクションでは、モジュールに NT ドメイン名、またはホスト名やアドレスの一覧を指定できます。</p>

#### オプション {#OPTIONS}


<p>pam_cifscreds は PAM 設定ファイルで設定できるいくつかのオプションをサポートします。domain= または host= のいずれか一方だけを必ず指定します。</p>

<dl><dt>debug</dt><dd><p>追加のデバッグログを有効にします。</p></dd><dt>domain=&lt;NT ドメイン名&gt;</dt><dd><p>指定した NT ドメイン名の資格情報を追加します。</p></dd><dt>host=&lt;ホスト名または IP アドレス&gt;[,...]</dt><dd><p>指定したホスト名または IP アドレスの資格情報を追加します。</p></dd></dl>

#### 注記 {#NOTES}


<p>pam_cifscreds PAM モジュールには、login キータイプをサポートしてビルドされたカーネルが必要です。このキータイプはメインライン Linux カーネルの v3.3 で追加されました。</p>

<p>pam_cifscreds はセッションキーリングにキーを追加するため、ログイン時にセッションキーリングが確立されるよう pam_keyinit を使うことを強く推奨します。</p>
