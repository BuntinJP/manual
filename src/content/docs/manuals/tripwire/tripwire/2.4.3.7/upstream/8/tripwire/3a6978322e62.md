### 説明 {#DESCRIPTION}


#### データベース初期化モード {#Database_Initialization_Mode}


<p><strong>tripwire</strong>をデータベース初期化モードで実行することは、通常、<em>Tripwire</em>を日常運用できるよう設定する最初の手順の1つです。このモードは、<em>Tripwire</em>設定ファイルのDBFILE変数で指定した場所に、基準となるデータベースを作成します。データベースは、実質的にはシステム上のオブジェクトのスナップショットです。その後の<em>Tripwire</em>完全性検査で、比較の基準として使用します。</p>

<p>データベース初期化モードで実行すると、<strong>tripwire</strong>はポリシーファイルを読み、その内容に基づくデータベースを生成し、生成したデータベースに暗号学的署名を付けます。データベース作成に使用するポリシー、設定、鍵の各ファイルは、コマンドラインオプションで指定できます。データベースのファイル名も指定できます。オプションを指定しない場合、現在の設定ファイルの既定値を使用します。</p>

#### 完全性検査モード {#Integrity-Checking-Mode}


<p><em>Tripwire</em>データベースの構築後、通常は次に<strong>tripwire</strong>を完全性検査モードで実行します。このモードは、ポリシーファイルの指定に従ってシステムを走査し、違反を探します。<em>Tripwire</em>はポリシーファイルの規則を使い、現在のファイルシステムの状態と初期基準データベースを比較します。完全性検査レポートを<em>stdout</em>へ出力し、<em>Tripwire</em>設定ファイルのREPORTFILE設定で指定した場所に保存します。</p>

<p>生成するレポートは、対象のファイルシステムオブジェクトが追加、削除、変更されたかに応じて、各ポリシー違反を詳しく説明します。各項目には、ファイルシステム上の現在のオブジェクト属性と、該当する場合はデータベース内の以前の値を記載します。データベースと現在のシステムに差があれば、管理者は現在のファイルを正しいファイルへ置き換えて問題を解決するか（侵入者が<em>/bin/login</em>を置き換えた場合など）、新しいファイルを反映するようデータベースを更新できます（別の管理者が<em>/usr/local/bin/emacs</em>の新版をインストールした場合など）。（<strong>‐I</strong>または<strong>‐‐interactive</strong>）オプションは、データベースをすばやく更新できるエディターを起動します。<strong>tripwire</strong>のデータベース更新モードも使用できます。</p>

#### データベース更新モード {#Database_Update_Mode}


<p><strong>tripwire</strong>をデータベース更新モードで実行すると、データベースと現在のシステムの差異を調整できます。これにより、以降のレポートにその違反が表示されなくなります。報告された変更が予期せず、悪意による可能性がある場合、変更されたファイルを元の版に戻すべきです。変更に正当な理由がある場合は、現在のファイルに一致するようデータベースを変更する必要があります。</p>

<p>データベース更新モードでは、エディターで開くプレーンテキストのレポート内にある「選択欄」で変更項目を指定します。各ポリシー違反の横の「x」を残すことで、更新する項目を指定します。ユーザーがエディターを終了し、正しいローカルパスフレーズを入力すると、<strong>tripwire</strong>がデータベースを更新します。この動作を制御するオプションには、（<strong>‐Z</strong>または<strong>‐‐secure‐mode</strong>）および（<strong>‐a</strong>または<strong>‐‐accept‐all</strong>）フラグがあります。</p>

#### ポリシー更新モード {#Policy_Update_Mode}


<p><strong>tripwire</strong>はポリシー更新モードでポリシーファイルを変更・更新し、以前のデータベースを新しいポリシー情報と同期します。新しい平文ポリシーファイルの名前をコマンドラインで指定します。新旧のポリシーファイルを比較し、新しい規則に従ってデータベースを更新します。前回の完全性検査以降のデータベースの変更を検出し、報告します。これらの違反の扱いは、（<strong>‐Z</strong>または<strong>‐‐secure‐mode</strong>）オプションで指定するセキュリティーモードによって異なります。<strong>high</strong>モード（既定）では、<em>Tripwire</em>は違反の一覧を出力し、データベースを変更せず終了します。<strong>low</strong>モードでも違反を報告しますが、データベースは自動的に変更します。</p>

<p>ポリシーファイルとデータベースファイルはバイナリー形式に符号化され、暗号学的署名が付いているため、ポリシー設定を変更するときにはサイトとローカルのパスフレーズを要求します。データベースの更新に成功すると、データベースとポリシーファイルを再び符号化し、署名します。</p>

#### テストモード {#Test_Mode}


<p>テストモードは、<em>Tripwire</em>のメール通知システムの動作確認に使用します。このモードでは、<em>Tripwire</em>は設定ファイルのメール通知設定を使ってテストメールを送信します。MAILMETHODがSMTPなら、SMTPHOSTとSMTPPORTの値を使います。MAILMETHODがSENDMAILなら、MAILPROGRAMの値を使います。メール通知が正しく機能していれば、コマンドラインで指定したアドレスに次のメッセージが届きます。</p>

<pre><code>
To: user@domain.com 
From: user &lt;user@domain.com&gt; 
Subject: Test email message from Tripwire 
If you receive this message, email notification
from Tripwire is working correctly.</code></pre>

<p>テストモードは、コマンドラインで指定したアドレスへのメール通知だけをテストします。ポリシーファイルのemailto属性の構文エラーは確認しません。</p>
