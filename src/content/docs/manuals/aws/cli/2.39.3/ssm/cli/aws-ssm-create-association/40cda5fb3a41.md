## create-association¶ {#create-association}


### 説明¶ {#Description}


<p>State Manager の関連付けは、マネージドノードで維持する状態を定義します。例えば、ウイルス対策ソフトウェアがマネージドノードにインストールされて実行中でなければならないことや、特定のポートを閉じておく必要があることを指定できます。静的なターゲットでは、関連付けは設定を再適用するスケジュールを指定します。Amazon Web Services リソースグループや Amazon Web Services オートスケーリンググループなどの動的ターゲットでは、Amazon Web Services Systems Manager のツールである State Manager は、グループに新しいマネージドノードが追加されると設定を適用します。関連付けは、設定の適用時に実行するアクションも指定します。例えば、ウイルス対策ソフトウェアの関連付けを 1 日に 1 回実行するようにできます。ソフトウェアがインストールされていない場合、State Manager がインストールします。ソフトウェアはインストールされているもののサービスが実行されていない場合、関連付けは State Manager にサービスの開始を指示できます。</p>

<p>関連項目: <a href="https://docs.aws.amazon.com/goto/WebAPI/ssm-2014-11-06/CreateAssociation">AWS API Documentation</a></p>

<p><code>--max-errors</code> (string)</p>

<blockquote><p>システムが追加のターゲットで関連付けを実行するためのリクエスト送信を停止するまでに許容されるエラー数。10 などのエラーの絶対数、または 10% などのターゲット集合に対する割合を指定できます。例えば 3 を指定すると、4 番目のエラーを受け取った時点でシステムはリクエスト送信を停止します。0 を指定すると、最初のエラーが返された後にシステムはリクエスト送信を停止します。50 個のマネージドノードで関連付けを実行し、<code>MaxError</code> を 10% に設定すると、6 番目のエラーを受け取った時点でシステムはリクエスト送信を停止します。</p>
<p><code>MaxErrors</code> に達したときにすでに関連付けを実行中の実行は、完了するまで続行できますが、その一部も失敗する可能性があります。失敗した実行が max-errors を超えないことを確実にする必要がある場合は、<code>MaxConcurrency</code> を 1 に設定して、実行が 1 つずつ進むようにしてください。</p>
<p>制約:</p>
<ul><li><p>最小: <code>1</code></p></li><li><p>最大: <code>7</code></p></li><li><p>パターン: <code>^([1-9][0-9]*|[0]|[1-9][0-9]%|[0-9]%|100%)$</code></p></li></ul></blockquote>

<p><code>--max-concurrency</code> (string)</p>

<p>Systems Manager が <code>MaxConcurrency</code> 個の関連付けを実行している間に、新しいマネージドノードが起動して関連付けを実行しようとした場合、その関連付けの実行は許可されます。次の関連付けの実行間隔では、新しいマネージドノードは <code>MaxConcurrency</code> に指定された制限内で関連付けを処理します。</p>
<p>制約:</p>
<ul><li><p>最小: <code>1</code></p></li><li><p>最大: <code>7</code></p></li><li><p>パターン: <code>^([1-9][0-9]*|[1-9][0-9]%|[1-9]%|100%)$</code></p></li></ul></blockquote>

<p><code>--sync-compliance</code> (string)</p>

<p><code>MANUAL</code> モードでは、PutComplianceItems API オペレーションのパラメータとして <code>AssociationId</code> を指定する必要があります。この場合、コンプライアンスデータは State Manager によって管理されません。PutComplianceItems API オペレーションの直接呼び出しによって管理されます。</p>
<p>デフォルトでは、すべての関連付けは <code>AUTO</code> モードを使用します。</p>
<p>指定可能な値:</p>
<ul><li><p><code>AUTO</code></p></li><li><p><code>MANUAL</code></p></li></ul></blockquote>

<p><code>--apply-only-at-cron-interval</code> | <code>--no-apply-only-at-cron-interval</code> (boolean)</p>

<blockquote><p>デフォルトでは、新しい関連付けを作成すると、システムは作成直後に実行し、その後は指定したスケジュールに従うとともに、ターゲットの変更が検出されたときにも実行します。指定したスケジュールに従ってのみ関連付けを実行する場合は、<code>ApplyOnlyAtCronInterval</code> に <code>true</code> を指定します。</p>

<p><code>--cli-input-json</code> | <code>--cli-input-yaml</code> (string) 指定された JSON 文字列から引数を読み取ります。JSON 文字列は <code>--generate-cli-skeleton</code> が提供する形式に従います。コマンドラインでほかの引数を指定した場合、その値が JSON で指定した値を上書きします。文字列はそのまま解釈されるため、JSON で指定する値を使って任意のバイナリ値を渡すことはできません。<code>--cli-input-yaml</code> と同時には指定できません。</p>

<p><code>--generate-cli-skeleton</code> (string) API リクエストを送信せずに、JSON スケルトンを標準出力に表示します。値を指定しない場合、または値に <code>input</code> を指定した場合は、<code>--cli-input-json</code> の引数に使用できる入力 JSON のサンプルを表示します。同様に、<code>yaml-input</code> を指定した場合は、<code>--cli-input-yaml</code> で使用できる入力 YAML のサンプルを表示します。値に <code>output</code> を指定した場合は、コマンドの入力を検証し、そのコマンドの出力 JSON のサンプルを返します。生成される JSON スケルトンは AWS CLI のバージョン間で一定ではなく、生成される JSON スケルトンの後方互換性は保証されません。</p>

<h4 id="Note-9">注記</h4>
<p>メンテナンスウィンドウの Run Command タイプのタスクには、1 つ以上の対象を指定する必要があります。ほかのメンテナンスウィンドウのタスクタイプ (Automation、Lambda、Step Functions) では、タスクによって対象の指定は任意です。対象を指定しないタスクの実行については、<em>Amazon Web Services Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/maintenance-windows-targetless-tasks.html">Registering maintenance window tasks without targets</a> を参照してください。</p>
<p>サポートされる形式は次のとおりです。</p>
<blockquote><p><strong>すべての Systems Manager ツールの場合:</strong></p></blockquote>
<ul><li><p><code>Key=tag-key,Values=tag-value-1,tag-value-2</code></p></li></ul>
<blockquote><p><strong>Automation と Change Manager の場合:</strong></p></blockquote>
<ul><li><p><code>Key=tag:tag-key,Values=tag-value</code></p></li><li><p><code>Key=ResourceGroup,Values=resource-group-name</code></p></li><li><p><code>Key=ParameterValues,Values=value-1,value-2,value-3</code></p></li><li><p>Amazon Web Services リージョン内のすべてのインスタンスを対象とするには:</p>
<ul><li><p><code>Key=AWS::EC2::Instance,Values=*</code></p></li><li><p><code>Key=InstanceIds,Values=*</code></p></li></ul></li></ul>
<blockquote><p><strong>Run Command と Maintenance Windows の場合:</strong></p></blockquote>
<ul><li><p><code>Key=InstanceIds,Values=instance-id-1,instance-id-2,instance-id-3</code></p></li><li><p><code>Key=tag:tag-key,Values=tag-value-1,tag-value-2</code></p></li><li><p><code>Key=resource-groups:Name,Values=resource-group-name</code></p></li><li><p>また、Maintenance Windows はリソースタイプによる対象指定をサポートします。</p>
<ul><li><p><code>Key=resource-groups:ResourceTypeFilters,Values=resource-type-1,resource-type-2</code></p></li></ul></li></ul>
<blockquote><p><strong>State Manager の場合:</strong></p></blockquote>
<ul><li><p><code>Key=InstanceIds,Values=instance-id-1,instance-id-2,instance-id-3</code></p></li><li><p><code>Key=tag:tag-key,Values=tag-value-1,tag-value-2</code></p></li><li><p>Amazon Web Services リージョン内のすべてのインスタンスを対象とするには:</p>
<ul><li><p><code>Key=InstanceIds,Values=*</code></p></li></ul></li></ul>
<p><code>Key,Value</code> パラメーターを使ってマネージドノードを対象とするコマンドの送信方法については、<em>Amazon Web Services Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/send-commands-multiple.html#send-commands-targeting">Targeting multiple managed nodes</a> を参照してください。</p>
