## put-compliance-items¶ {#put-compliance-items}


### 説明¶ {#Description}


<p>指定したリソースにコンプライアンスタイプとその他のコンプライアンス詳細を登録します。この操作により、リソースにカスタムコンプライアンスの詳細を登録できます。この呼び出しはリソースの既存のコンプライアンス情報を上書きするため、リクエストを送信するたびにコンプライアンス項目の完全な一覧を指定する必要があります。</p>

<p>ComplianceType には次のいずれかを指定できます。</p>

<ul><li><p>ExecutionId: パッチ、関連付け、またはカスタムコンプライアンス項目が適用されたときの実行 ID。</p></li><li><p>ExecutionType: patch、association、または Custom:<code>string</code> を指定します。</p></li><li><p>ExecutionTime。パッチ、関連付け、またはカスタムコンプライアンス項目がマネージドノードに適用された時刻。</p></li></ul>

#### 警告 {#Warning}


<p>State Manager の関連付けでは、これは Systems Manager サービスが内部のコンプライアンス集約ワークフロー中にコンプライアンス状態を取得した時刻を表し、必ずしも関連付けがマネージドノードで実行された時刻ではありません。State Manager は、いずれかの関連付けが実行されるたびに、そのインスタンス上のすべての関連付けのコンプライアンス情報を更新するため、複数の関連付けに同じ実行時刻が表示される場合があります。</p>

<ul><li><p>Id: パッチ、関連付け、またはカスタムコンプライアンスの ID。</p></li><li><p>Title: タイトル。</p></li><li><p>Status: コンプライアンス項目の状態。例: パッチでは <code>approved</code>、関連付けでは <code>Failed</code>。</p></li><li><p>Severity: パッチの重要度。例: <code>Critical</code>。</p></li><li><p>DocumentName: SSM ドキュメント名。例: <code>AWS-RunPatchBaseline</code>。</p></li><li><p>DocumentVersion: SSM ドキュメントのバージョン番号。例: 4。</p></li><li><p>Classification: パッチの分類。例: <code>security updates</code>。</p></li><li><p>PatchBaselineId: パッチベースラインの ID。</p></li><li><p>PatchSeverity: パッチの重要度。例: <code>Critical</code>。</p></li><li><p>PatchState: パッチの状態。例: <code>InstancesWithFailedPatches</code>。</p></li><li><p>PatchGroup: パッチグループの名前。</p></li><li><p>InstalledTime: 関連付け、パッチ、またはカスタムコンプライアンス項目がリソースに適用された時刻。次の形式で指定します: <code>yyyy-MM-dd&#39;T&#39;HH:mm:ss&#39;Z&#39;</code></p></li></ul>

<p>関連項目: <a href="https://docs.aws.amazon.com/goto/WebAPI/ssm-2014-11-06/PutComplianceItems">AWS API Documentation</a></p>
