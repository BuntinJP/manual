## put-parameter¶ {#put-parameter}


### 説明¶ {#Description}


<p>Parameter Store 内のパラメーターを作成または更新します。</p>

#### 注記 {#Note}


<p>Parameter Store のスループットは、Systems Manager が処理できる 1 秒あたりの API トランザクション数 (TPS) を定義します。これは、Amazon Web Services アカウントおよび Amazon Web Services リージョンの <code>GetParameter</code>、<code>GetParameters</code>、<code>PutParameter</code> API 呼び出しに適用されます。既定では、Parameter Store は低量から中量のワークロードに適した標準のスループットクォータで設定されています。設定データを取得する頻度が低いアプリケーションや、小規模で動作するアプリケーションは、追加料金なしでこの既定の設定を使用できます。</p>

<p>より大量のワークロードには、高スループットを有効にできます。これにより、アカウントとリージョンでサポートされる 1 秒あたりの最大トランザクション数が増えます。スループットの引き上げは、複数のパラメーターへの同時アクセスが必要なアプリケーションやワークロードをサポートします。<code>ThrottlingException: Rate exceeded</code> エラーが発生する場合は、高スループットを有効にしてください。詳細については、<a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-throughput.html">Changing Parameter Store throughput</a> を参照してください。</p>

<p>関連項目: <a href="https://docs.aws.amazon.com/goto/WebAPI/ssm-2014-11-06/PutParameter">AWS API Documentation</a></p>

### オプション¶ {#Options}


<p><code>--name</code> (string) [必須]</p>

<blockquote><p>作成または更新するパラメーターの完全修飾名。</p>
<h4 id="Note-2">注記</h4>
<p>パラメーターの Amazon リソースネーム (ARN) は入力できません。入力できるのはパラメーター名そのものだけです。</p>
<p>完全修飾名には、パラメーターパスと名前の完全な階層が含まれます。階層内のパラメーターを作成または参照する際は、先頭にスラッシュ (/) を含める必要があります。例: <code>/Dev/DBServer/MySQL/db-string13</code></p>
<p>命名上の制約:</p>
<ul><li><p>パラメーター名は大文字と小文字を区別します。</p></li><li><p>パラメーター名は Amazon Web Services リージョン内で一意でなければなりません。</p></li><li><p>パラメーター名の先頭に「<code>aws</code>」または「<code>ssm</code>」は使用できません (大文字と小文字を区別しません)。</p></li><li><p>パラメーター名に使用できる記号と文字は次のものだけです: <code>a-zA-Z0-9_.-</code>。また、スラッシュ (/) はパラメーター名の階層の区切りに使用します。例: <code>/Dev/Production/East/Project-ABC/MyParameter</code></p></li><li><p>パラメーター名にスペースを含めることはできません。サービスは、パラメーター名の先頭または末尾に指定されたスペースをすべて削除します。指定したパラメーター名の文字の間にスペースがある場合、リクエストは <code>ValidationException</code> エラーで失敗します。</p></li><li><p>パラメーター階層の深さは最大 15 レベルです。</p></li></ul>
<p>パラメーター名の有効な値について詳しくは、<em>Amazon Web Services Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/sysman-paramstore-su-create.html">Creating Systems Manager parameters</a> を参照してください。</p>
<h4 id="Note-3">注記</h4>
<p>パラメーター名の最大長として表示される 2048 文字には、Systems Manager の内部使用のために予約された 1037 文字が含まれます。自分で指定できるパラメーター名の最大長は 1011 文字です。</p>
<p>この 1011 文字には、指定した名前より前にある ARN の文字も含まれます。ARN の長さはパーティションとリージョンによって異なります。たとえば、米国東部 (オハイオ) リージョンで作成したパラメーターでは、次の 45 文字が 1011 文字の上限に含まれます: <code>arn:aws:ssm:us-east-2:111122223333:parameter/</code>。</p>
<p>制約:</p>
<ul><li><p>最小: <code>1</code></p></li><li><p>最大: <code>2048</code></p></li></ul></blockquote>

<p><code>--description</code> (string)</p>

<blockquote><p>システムに追加するパラメーターの情報。省略可能ですが、指定をお勧めします。</p>
<h4 id="Warning">警告</h4>
<p>このフィールドに個人を特定できる情報を入力しないでください。</p>
<p>制約:</p>
<ul><li><p>最小: <code>0</code></p></li><li><p>最大: <code>1024</code></p></li></ul></blockquote>

<p><code>--value</code> (string) [必須]</p>

<blockquote><p>システムに追加するパラメーターの値。スタンダードパラメーターの値の上限は 4 KB、アドバンストパラメーターの上限は 8 KB です。</p>
<h4 id="Note-4">注記</h4>
<p>パラメーターを、ほかのパラメーターの値の中で参照したりネストしたりすることはできません。二重括弧 <code>{{}}</code> または <code>{{ssm:*parameter-name* }}</code> で囲んだ値を、パラメーター値に含めることはできません。</p></blockquote>

<h4 id="Note-5">注記</h4>
<p>現在、CloudFormation テンプレートでは <code>SecureString</code> はサポートされていません。</p>
<p><code>StringList</code> 内の項目はカンマ (,) で区切る必要があります。ほかの句読点や特殊文字を使用して一覧内の項目をエスケープすることはできません。カンマを必要とするパラメーター値には、<code>String</code> データタイプを使用してください。</p>
<h4 id="Warning-2">警告</h4>

<p>指定可能な値:</p>
<ul><li><p><code>String</code></p></li><li><p><code>StringList</code></p></li><li><p><code>SecureString</code></p></li></ul></blockquote>

<p><code>--key-id</code> (string)</p>

<blockquote><p>パラメーターの暗号化に使用する Key Management Service (KMS) ID。より高いセキュリティのためにカスタムキーを使用してください。<code>SecureString</code> データタイプを使用するパラメーターでは必須です。</p>
<p>キー ID を指定しない場合、システムは Amazon Web Services アカウントに関連付けられた既定のキーを使用します。これはカスタムキーの使用ほど安全ではありません。</p>
<ul><li><p>カスタム KMS キーを使用するには、<code>Key ID</code> パラメーターで <code>SecureString</code> データタイプを選択します。</p></li></ul>
<p>制約:</p>
<ul><li><p>最小: <code>1</code></p></li><li><p>最大: <code>256</code></p></li><li><p>パターン: <code>^([a-zA-Z0-9:/_-]+)$</code></p></li></ul></blockquote>

<p><code>--overwrite</code> | <code>--no-overwrite</code> (boolean)</p>

<blockquote><p>既存のパラメーターを上書きします。既定値は <code>false</code> です。</p></blockquote>

<p><code>--allowed-pattern</code> (string)</p>

<p>制約:</p>
<ul><li><p>最小: <code>0</code></p></li><li><p>最大: <code>1024</code></p></li></ul></blockquote>

<p><code>--tags</code> (list)</p>

<blockquote><p>リソースに割り当てる任意のメタデータ。タグにより、目的、所有者、環境など、さまざまな方法でリソースを分類できます。たとえば、Systems Manager パラメーターの適用先リソースの種類、環境、参照する設定データの種類を識別するためにタグを付ける場合、次のキーと値のペアを指定できます。</p>
<ul><li><p><code>Key=Resource,Value=S3bucket</code></p></li><li><p><code>Key=OS,Value=Windows</code></p></li><li><p><code>Key=ParameterType,Value=LicenseKey</code></p></li></ul>
<h4 id="Note-6">注記</h4>
<p>既存の Systems Manager パラメーターにタグを追加するには、AddTagsToResource 操作を使用します。</p>
<p>制約:</p>
<ul><li><p>最大: <code>1000</code></p></li></ul>
<p>(structure)</p>
<blockquote><p>Amazon Web Services リソースに割り当てるメタデータ。タグにより、目的、所有者、環境など、さまざまな方法でリソースを分類できます。Amazon Web Services Systems Manager では、Systems Manager ドキュメント (SSM ドキュメント)、マネージドノード、メンテナンスウィンドウ、パラメーター、パッチベースライン、OpsItem、および OpsMetadata にタグを適用できます。</p>

<blockquote><p>タグの名前。</p>

<p><code>--tier</code> (string)</p>

<blockquote><p>パラメーターに割り当てる階層。</p>
<p>Parameter Store は、スタンダードとアドバンストの 2 つの階層を提供します。スタンダードパラメーターの内容サイズの上限は 4 KB で、パラメーターポリシーを使用するよう設定することはできません。Amazon Web Services アカウントの各リージョンで最大 10,000 個のスタンダードパラメーターを作成できます。スタンダードパラメーターは追加料金なしで提供されます。</p>
<p>アドバンストパラメーターの内容サイズの上限は 8 KB で、パラメーターポリシーを使用するよう設定できます。Amazon Web Services アカウントの各リージョンで最大 100,000 個のアドバンストパラメーターを作成できます。アドバンストパラメーターには料金が発生します。詳細については、<em>Amazon Web Services Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-advanced-parameters.html">Managing parameter tiers</a> を参照してください。</p>
<p>スタンダードパラメーターはいつでもアドバンストパラメーターに変更できますが、アドバンストからスタンダードに戻すことはできません。戻すと、システムがパラメーターのサイズを 8 KB から 4 KB に切り詰めるため、データが失われます。また、パラメーターに付いているポリシーも削除されます。さらに、アドバンストパラメーターはスタンダードとは異なる暗号化方式を使用します。</p>
<p>アドバンストパラメーターが不要になった場合、または課金を避けたい場合は、削除してから新しいスタンダードパラメーターとして再作成する必要があります。</p>
<blockquote><p><strong>既定の階層設定の使用</strong></p></blockquote>
<p><code>PutParameter</code> リクエストでは、パラメーターを作成する階層を指定できます。指定した場合、Parameter Store はそのリクエストに従ってパラメーターを作成または更新します。指定しない場合は、現在の Parameter Store の既定の階層設定に基づいて階層を割り当てます。</p>
<p>Parameter Store の使用開始時の既定の階層は、スタンダードパラメーター階層です。アドバンストパラメーター階層を使用する場合、次のいずれかを既定に指定できます。</p>
<ul><li><p><strong>Advanced</strong>: このオプションでは、Parameter Store はすべてのリクエストをアドバンストパラメーターとして評価します。</p></li><li><p><strong>Intelligent-Tiering</strong>: このオプションでは、Parameter Store は各リクエストを評価し、パラメーターがスタンダードかアドバンストかを判断します。アドバンストパラメーターが必要なオプションがなければ、スタンダード階層に作成します。必要なオプションが 1 つ以上含まれていれば、アドバンスト階層に作成します。この方式では、必要な場合を除き常にスタンダードパラメーターを作成することで、パラメーター関連のコストを抑えられます。</p></li></ul>
<p>アドバンストパラメーターを必要とするオプションは次のとおりです。</p>
<ul><li><p>パラメーターの内容サイズが 4 KB を超える。</p></li><li><p>パラメーターがパラメーターポリシーを使用する。</p></li><li><p>現在の Amazon Web Services リージョンのアカウント内に、既に 10,000 個を超えるパラメーターが存在する。</p></li></ul>
<p>既定の階層オプションの設定について詳しくは、<em>Amazon Web Services Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-advanced-parameters.html#ps-default-tier">Specifying a default parameter tier</a> を参照してください。</p>
<p>指定可能な値:</p>
<ul><li><p><code>Standard</code></p></li><li><p><code>Advanced</code></p></li><li><p><code>Intelligent-Tiering</code></p></li></ul></blockquote>

<p><code>--policies</code> (string)</p>

<blockquote><p>パラメーターに適用する 1 つ以上のポリシー。この操作は JSON 配列を受け取ります。Amazon Web Services Systems Manager のツールである Parameter Store は、次のポリシータイプをサポートします。</p>
<p>Expiration: このポリシーは、有効期限が切れた後にパラメーターを削除します。ポリシーの作成時に有効期限を指定します。ポリシーの更新により有効期限の日時を変更できます。<em>パラメーター</em>を更新しても有効期限の日時には影響しません。有効期限に達すると、Parameter Store はパラメーターを削除します。</p>
<p>ExpirationNotification: このポリシーは、有効期限を通知する Amazon CloudWatch Events イベントを発生させます。有効期限の前または後に、日または時間単位で通知を受け取れます。</p>
<p>NoChangeNotification: このポリシーは、パラメーターが指定した期間変更されていない場合に CloudWatch Events イベントを発生させます。たとえば、一定期間内に変更すべきシークレットが変更されていない場合に役立ちます。</p>
<p>新しいポリシーまたは空のポリシーを送信するまで、既存のポリシーはすべて保持されます。パラメーターポリシーの詳細については、<a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-policies.html">Assigning parameter policies</a> を参照してください。</p>
<p>制約:</p>
<ul><li><p>最小: <code>1</code></p></li><li><p>最大: <code>4096</code></p></li></ul></blockquote>

<p><code>--data-type</code> (string)</p>

<blockquote><p><code>String</code> パラメーターのデータ型。サポートされるデータ型には、プレーンテキストと Amazon Machine Image (AMI) ID があります。</p>
<blockquote><p><strong>次のデータ型の値がサポートされています。</strong></p></blockquote>
<ul><li><p><code>text</code></p></li><li><p><code>aws:ec2:image</code></p></li><li><p><code>aws:ssm:integration</code></p></li></ul>
<p><code>String</code> パラメーターを作成して <code>aws:ec2:image</code> を指定すると、Amazon Web Services Systems Manager は、値が <code>ami-12345abcdeEXAMPLE</code> などの必要な形式であることと、指定した AMI が Amazon Web Services アカウントで利用可能であることを検証します。</p>
<h4 id="Note-7">注記</h4>
<p>操作が成功すると、サービスは HTTP 200 応答を返します。これは、データ型 <code>aws:ec2:image</code> を除くすべての場合で <code>PutParameter</code> 呼び出しの成功を示します。<code>aws:ec2:image</code> データ型で <code>PutParameter</code> を呼び出した場合、成功を示す HTTP 200 応答はパラメーターの作成・更新の成功を保証しません。<code>aws:ec2:image</code> の値は非同期で検証され、<code>PutParameter</code> 呼び出しは検証完了前に応答を返します。無効な AMI 値を送信すると、PutParameter 操作は成功を返しますが、非同期検証は失敗し、パラメーターは作成・更新されません。<code>aws:ec2:image</code> パラメーターが正常に作成されたかを監視するには、<a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/sysman-paramstore-cwe.html">Setting up notifications or trigger actions based on Parameter Store events</a> を参照してください。AMI 形式の検証について詳しくは、<a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-ec2-aliases.html">Native parameter support for Amazon Machine Image IDs</a> を参照してください。</p>
<p>制約:</p>
<ul><li><p>最小: <code>0</code></p></li><li><p>最大: <code>128</code></p></li></ul></blockquote>

<p><code>--cli-input-json</code> | <code>--cli-input-yaml</code> (string) 指定された JSON 文字列から引数を読み取ります。JSON 文字列は <code>--generate-cli-skeleton</code> が提供する形式に従います。コマンドラインでほかの引数を指定した場合、その値が JSON で指定した値を上書きします。文字列はそのまま解釈されるため、JSON で指定する値を使って任意のバイナリ値を渡すことはできません。<code>--cli-input-yaml</code> と同時には指定できません。</p>

<p><code>--generate-cli-skeleton</code> (string) API リクエストを送信せずに、JSON スケルトンを標準出力に表示します。値を指定しない場合、または値に <code>input</code> を指定した場合は、<code>--cli-input-json</code> の引数に使用できる入力 JSON のサンプルを表示します。同様に、<code>yaml-input</code> を指定した場合は、<code>--cli-input-yaml</code> で使用できる入力 YAML のサンプルを表示します。値に <code>output</code> を指定した場合は、コマンドの入力を検証し、そのコマンドの出力 JSON のサンプルを返します。生成される JSON スケルトンは AWS CLI のバージョン間で一定ではなく、生成される JSON スケルトンの後方互換性は保証されません。</p>

### グローバルオプション¶ {#Global-Options}


<p><code>--debug</code> (boolean)</p>

<p>デバッグログを有効にします。</p>

### 例¶ {#Examples}


#### 注記 {#Note-8}


<p>以下の例を使用するには、AWS CLI をインストールして設定しておく必要があります。詳細については、<em>AWS CLI ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/cli/latest/userguide/cli-chap-getting-started.html">Getting started guide</a> を参照してください。</p>

<p>特に断りのない限り、すべての例は Unix 系の引用符規則を使用しています。これらの例は、使用する端末の引用符規則に合わせて調整する必要があります。<em>AWS CLI ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/cli/latest/userguide/cli-usage-parameters-quoting-strings.html">Using quotation marks with strings</a> を参照してください。</p>

<p><strong>例 1: パラメーター値を変更するには</strong></p>

<p>次の <code>put-parameter</code> の例は、指定したパラメーターの値を変更します。</p>

<pre><code>aws ssm put-parameter \
    --name &quot;MyStringParameter&quot; \
    --type &quot;String&quot; \
    --value &quot;Vici&quot; \
    --overwrite</code></pre>

<p>出力:</p>

<pre><code>{
    &quot;Version&quot;: 2,
    &quot;Tier&quot;: &quot;Standard&quot;
}</code></pre>

<p>詳細については、<em>AWS Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/param-create-cli.html">Create a Systems Manager parameter (AWS CLI)</a>、<a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-advanced-parameters.html">Managing parameter tiers</a>、<a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-policies.html">Working with parameter policies</a> を参照してください。</p>

<p><strong>例 2: アドバンストパラメーターを作成するには</strong></p>

<p>次の <code>put-parameter</code> の例は、アドバンストパラメーターを作成します。</p>

<pre><code>aws ssm put-parameter \
    --name &quot;MyAdvancedParameter&quot; \
    --description &quot;This is an advanced parameter&quot; \
    --value &quot;Lorem ipsum dolor sit amet, consectetur adipiscing elit, sed do eiusmod tempor incididunt ut labore et dolore magna aliqua. Ut enim ad minim veniam, quis nostrud exercitation ullamco laboris nisi ut aliquip ex ea commodo consequat [truncated]&quot; \
    --type &quot;String&quot; \
    --tier Advanced</code></pre>

<p>出力:</p>

<pre><code>{
    &quot;Version&quot;: 1,
    &quot;Tier&quot;: &quot;Advanced&quot;
}</code></pre>

<p>詳細については、<em>AWS Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/param-create-cli.html">Create a Systems Manager parameter (AWS CLI)</a>、<a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-advanced-parameters.html">Managing parameter tiers</a>、<a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-policies.html">Working with parameter policies</a> を参照してください。</p>

<p><strong>例 3: スタンダードパラメーターをアドバンストに変換するには</strong></p>

<p>次の <code>put-parameter</code> の例は、既存のスタンダードパラメーターをアドバンストパラメーターに変換します。</p>

<pre><code>aws ssm put-parameter \
    --name &quot;MyConvertedParameter&quot; \
    --value &quot;abc123&quot; \
    --type &quot;String&quot; \
    --tier Advanced \
    --overwrite</code></pre>

<p>出力:</p>

<pre><code>{
    &quot;Version&quot;: 2,
    &quot;Tier&quot;: &quot;Advanced&quot;
}</code></pre>

<p>詳細については、<em>AWS Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/param-create-cli.html">Create a Systems Manager parameter (AWS CLI)</a>、<a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-advanced-parameters.html">Managing parameter tiers</a>、<a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-policies.html">Working with parameter policies</a> を参照してください。</p>

<p><strong>例 4: ポリシー付きパラメーターを作成するには</strong></p>

<p>次の <code>put-parameter</code> の例は、パラメーターポリシーを付けたアドバンストパラメーターを作成します。</p>

<pre><code>aws ssm put-parameter \

<p>出力:</p>

<pre><code>{
    &quot;Version&quot;: 1,
    &quot;Tier&quot;: &quot;Advanced&quot;

<p>詳細については、<em>AWS Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/param-create-cli.html">Create a Systems Manager parameter (AWS CLI)</a>、<a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-advanced-parameters.html">Managing parameter tiers</a>、<a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-policies.html">Working with parameter policies</a> を参照してください。</p>

<p><strong>例 5: 既存のパラメーターにポリシーを追加するには</strong></p>

<p>次の <code>put-parameter</code> の例は、既存のアドバンストパラメーターにポリシーを付けます。</p>

<pre><code>aws ssm put-parameter \

    --overwrite</code></pre>

<p>出力:</p>

<p>詳細については、<em>AWS Systems Manager ユーザーガイド</em>の <a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/param-create-cli.html">Create a Systems Manager parameter (AWS CLI)</a>、<a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-advanced-parameters.html">Managing parameter tiers</a>、<a href="https://docs.aws.amazon.com/systems-manager/latest/userguide/parameter-store-policies.html">Working with parameter policies</a> を参照してください。</p>
