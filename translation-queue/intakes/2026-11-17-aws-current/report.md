These results are **structural body comparisons, not semantic review or certification of existing translations**. The numerous changes justify stopping at an audit/list rather than automatically importing or translating them.

## Method and evidence
Fetched each existing manifest.origin with normal HTTPS curl, maximum concurrency 4, max-time 20 seconds per request, no retries or bypasses. Fetch phase completed in about 10 seconds. Exact times, status, effective URLs and original leaf paths are in `fetch-results.json`. All fetches and analysis completed within the requested bounded few-minute window.

Reconstructed current IR with repository `parseManualHtml`, the identical manifest.origin and identical extraction selector (`div.body`). Compared the full segments(kind/text/protected) sequence and full blocks; excluded top-level source hash, parser metadata and extraction metadata. Segment IDs were excluded from segment content comparison, but retained in blocks and evidence. Sequence alignment for difference groups uses exact kind/text/protected signatures, not fuzzy semantic equivalence. Insertions can shift later IDs and cause broad block differences; the segment list gives the meaningful structural alignment rather than claiming every shifted block represents a distinct prose edit.

Local evidence only under this directory:
- Per page `current.html` (raw response) and `current.ir.json`.
- `comparison.json`: page title version, current source hash, counts, full/segment/block identity flags, baseline reparse check.
- `segment-deltas.json`: full before/after changed segment objects, including IDs and protected inline content.
- `fetch.py`, `compare.ts`, `report.py`: bounded audit scripts. No API command from the documents executed.

Existing 2.39.3 source/IR/queue/translations remain intact. This does not establish the first release introducing each change or verify every new statement against AWS behavior. Do not advertise the old155 translations as matching latest2.40.4 body content.
