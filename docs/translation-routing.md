# 翻訳の工程別モデル運用

## 方針と現在地

安定した取得・保存・解析・生成・検証はBun CLIが担当します。これらの実行にLLMは不要です。
モデルは、取得先の判断、自然言語の翻訳、意味の判断、失敗原因の特定にだけ使います。
この文書はエージェントが従う作業手順です。自動配車や課金上限を実装したサービスではありません。

2026-09-06現在、macOS 8件のパイプライン検証は完了していますが、Luna / Terra / Solの
翻訳品質と実費を同条件で比較した評価は未実施です。以下の割り当ては暫定で、削減率を
実測済みとは扱いません。モデル単価だけでなく、再試行・レビュー・調整も含めて評価します。

## 工程の割り当て

1. **取得と準備**: `content:apple-macos` または `content:ingest`、`content:parse`、
   `content:translate` を直接実行します。既知の取得先を毎回LLMで探索しません。
   新しい取得先の調査・定型的なファイル操作にエージェントが必要な場合だけComposer 2.5
   通常版を使います。原文とIRの抽出漏れを照合し、翻訳依頼まで作成して終了します。
   `translation/ja.json`の生成や意味レビューはGPT担当に渡します。
2. **通常の翻訳**: GPT-5.6 Luna、reasoning mediumを評価の開始候補とします。
   原文セグメント、保護トークン、当該見出し、必要な隣接文、用語集だけ渡します。
   担当者が全文の否定・数値・既定値・条件・使用例を原文と照合します。
3. **難しい翻訳と独立レビュー**: GPT-5.6 Terra、reasoning mediumを開始候補とします。
   原文の条件が重なる箇所、破壊的操作、権限・評価順序、曖昧な訳語を優先します。
   初稿を全文書き直さず、対象IDと問題を返します。必要な修正は該当範囲だけ適用します。
4. **例外対応**: Terraでも根拠が定まらない意味判断、未知のroff構造や取得方式の設計を
   GPT-5.6 Solに渡します。問題と周辺資料だけ渡し、修正後は通常経路へ戻します。
5. **受理と生成**: `content:translate --accept`、`bun run verify`、必要な表示検証を
   スクリプトで実行します。機械検証は意味の正しさの代用にはしません。

同じ失敗への同一モデルの修正は1回までを目安とし、次は原因を明記して上位担当に渡します。
原文欠落やIR抽出失敗は翻訳モデルを上げても直らないため、準備工程へ戻します。
上位担当でも解決しないものは未解決として記録し、無制限にモデルを呼び続けません。

## 初回の小規模評価と既定化

新しい文書形式・言語・用語分野では、短い通常説明、否定、数値境界、既定値、複数条件、
破壊的操作、使用例説明を含む12〜20セグメントを固定します。既存8件の原文を評価に
再利用できますが、既存訳は正解保証された教師データとは扱いません。

まずLunaでその範囲だけ翻訳し、機械検証とTerraによる全サンプルの意味レビューを行います。
重大な誤訳（否定の逆転、数値・単位・条件・操作対象の変更、訳抜け）は0件を合格条件とします。
問題が出た種類だけTerraでも同じ入力を翻訳し、必要な場合にSolが原文根拠で裁定します。
全モデルで全文を翻訳して比較することは既定にしません。

合格した種類はLunaを既定にし、難しい種類はTerraを直接使います。通常運用では翻訳担当の
全文照合に加え、Terraが高リスク箇所すべてと通常箇所の固定サンプルを独立照合します。
通常箇所のサンプルは各見出しから少なくとも1件、通常セグメント総数の10%以上とし、
対象IDを記録します。抽出で誤訳が見つかった場合は同種の箇所全体へレビューを拡大します。
これは暫定的な運用基準で、全件の独立二重レビューを実施したという意味ではありません。

## 使用量と引き継ぎ

各 `translation/review.md` に、実施した範囲に限って以下を残します。

- 工程、対象セグメントID、原文・IR・用語集の版またはハッシュ
- 実行環境（Codexサブエージェント / Cursor CLI）、指定モデルIDとreasoning
- 初稿生成者と意味レビュー担当者、独立照合した範囲
- 再試行数、上位モデルへ渡した理由、修正したID、未解決事項
- 入力・キャッシュ・出力・推論トークンなど実行環境から観測できる使用量、所要時間
- 実請求額が取得できる場合は金額と出典。取得できなければ「不明」

使用量が提供されない場合、出力文字数をトークン数や料金として扱いません。
API定価をCodexやCursorの契約の実請求額へそのまま置き換えません。
認証情報や生の環境変数は記録しません。

分担はコマンドまたは見出し単位とし、会話全体・他コマンドの全文を引き継ぎません。
1セグメントごとにエージェントを起動することも避けます。変更のない受理済み成果物は
再翻訳しません。source/IRハッシュが変わった場合は既存の整合性検証に従い、古いハッシュを
付け替えて流用することはしません。安全なセグメント差分再利用の自動化は未実装です。

## モデル指定

2026-09-06に、この環境の `cursor-agent --help` と `cursor-agent models` で次のIDを
確認しました。実行直前にもモデル一覧を確認し、利用不能なら無断でAutoへ切り替えません。

- 準備: `composer-2.5`（`composer-2.5-fast`を既定にしない）
- 翻訳開始候補: `gpt-5.6-luna-medium`
- 難しい翻訳・レビュー: `gpt-5.6-terra-medium`
- 例外対応: `gpt-5.6-sol-medium`

Cursorで準備だけを委譲する例です。対象コマンド・版を実際の依頼に置き換えます。

```sh
cursor-agent --workspace /Users/larchel/gits/manual-japanese-manual \
  --model composer-2.5 --print --output-format json \
  'docs/translation-start.md と docs/translation-routing.md に従い、macOS 26.6.2 の find だけを準備してください。既存CLIで原文取得・版固定・解析・IR照合・翻訳依頼生成まで実施してください。受理済み訳文は変更せず、翻訳や他モデルの起動は行わず、成果物パスと残る問題だけ報告してください。'
```

Codexサブエージェントでは `gpt-5.6-luna` / `gpt-5.6-terra` / `gpt-5.6-sol` と
reasoning `medium` を明示します。CursorのCLI用IDをそのまま流用しません。
どちらも担当工程を越えるモデル再委譲は禁止し、必要な例外は調整担当へ返します。
モデルの自己申告は実行時メタデータの代わりにしません。

## 初回8件の実行記録

macOS 26.6.2の初回8件では、Sol→Terra→Lunaの分担に加え、6件はCursorの
`gpt-5.6-sol-xhigh`で初稿を生成しました。tar/sqlite3のCursor初稿はモデル未指定でした。
この経路は低コスト経路の比較実験ではなく、今後の既定にも採用しません。
各資料のレビューは当時の事実として保持し、今回の新しい方針で書き換えません。
