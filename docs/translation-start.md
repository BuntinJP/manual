# 翻訳タスクの起点

この作業ツリーを Codex で開き、タスクのモデルを GPT-5.6 Sol / Terra / Luna から選んで、下の依頼文を渡します。モデルの選択は Codex 側で行います。このリポジトリは特定の LLM API を呼び出しません。

まず Sol で 1 本を通し、同じ手順を Terra / Luna でも使えます。モデルを変えても、原文保存・翻訳データ・検証コマンドは共通です。長文は見出し単位に分けて保存し、最後に全セグメントを統合して照合します。

## コピーして使う依頼文

```text
docs/translation-start.md に沿って、次のマニュアルを日本語化してください。
対象: <HTML の URL または roff ファイルのパス>
対象版: <指定があれば記入>

原文取得、版別保存、解析、全文翻訳、原文との照合、サイト生成、検証まで進めてください。
```

公開も依頼する場合は「検証後、Wrangler で公開してください」を追記します。

## AI が実行する順序

1. ルートの `AGENTS.md` と `tools/manual/README.md` を読む。対象資料から提供元・製品・版・バリエーション・セクション・名前を特定する。
2. `content:ingest` → `content:parse` を実行。保存原文と `ir.json` を照合し、見出し・表・使用例などの抽出漏れを直す。
3. 資料内の `translation/glossary.json` を整え、`content:translate` で依頼 JSON を生成する。全セグメントを日本語化し、保護トークンを保持して `translation/ja.json` を作成する。
4. `content:translate --accept` で受け渡しを検証する。原文と訳文の否定・数値・単位・既定値・条件・使用例を照合し、確認範囲を `translation/review.md` に残す。
5. `bun run verify` と実ページでの表示確認を実行する。完了した範囲と、残る不明点だけを短く報告する。

各コマンドの引数は `tools/manual/README.md` を参照します。途中で区切る場合は対象ディレクトリの `translation/progress.md` に処理済みセグメントと次の作業を残し、続きをそこから再開します。

権利に関する懸念は根拠とともに報告し、翻訳・生成は続けます。モデル名を記録する場合は実際に確認できる名前を使い、推測で埋めません。
