# 構成

Astro 7.3.1 / Starlight 0.42.0 の静的サイトです。翻訳の管理単位と、サイト上の URL を同じ識別情報で対応づけています。

```text
manuals/
  freebsd/ports/15.quarterly/15.1-release-and-ports/1/find/609f6787f2c5/
    manifest.json                   取得元・取得日時・識別情報・SHA-256
    source.html                     取得したバイト列
    ir.json                         意味構造と翻訳セグメント
    translation/
      glossary.json                 この資料の用語集
      request.ja.json               原文、保護トークン、翻訳指示
      ja.json                       日本語訳
      review.md                     確認範囲と対象ハッシュ
    rendered/ja.md                  決定的に生成したページ
  gnu/findutils/4.10.0/upstream/1/find/<sha12>/
    ...                             別実装の取り込み例（未収録）
  apple/macos/26.6.2/25g83/1/find/<sha12>/
    source.roff                     Apple OSS と実機で一致した原文
    provenance/                     固定した Apple の公開版情報
    licenses/                       公開元に独立ファイルがある場合の許諾表示
tools/manual/                       取り込み・解析・翻訳の受け渡し・生成
translation-queue/*.json             未処理・処理中・保留・完了、途中訳文、担当、引継ぎ履歴
src/content/docs/manuals/            サイト向けの生成 Markdown
src/data/manual-catalog.json         版別の検索・ナビゲーション情報
src/data/manual-providers.json       提供元の固定ID・表示名・説明・既存資料の場所
src/components/                     サイトの表示と検索
public/fonts/cica/                  Cica、同梱通知、取得・変換記録
```

識別子は `提供元 / 製品 / 版 / バリエーション / manセクション / 名前 / 原文ハッシュ先頭12桁` です。名前だけではまとめません。版が変わった場合も、同じ版の原文が変更された場合も、以前の原文と日本語訳を残します。短縮ハッシュが衝突した場合は完全な SHA-256 の比較で検出します。

Apple の経路では `version` を検証対象の安定版 macOS、`variant` をビルド番号にします。Apple Open Source の `distribution-macOS` が示す公開版、個別構成要素のタグとコミット、実機のOS版、実際のmanページが同じ事実とは限らないため、`manifest.json` の `provenance` で分離します。画面にも対象OS・構成要素・原文種別・Apple OSS公開版を表示します。

提供元や版の識別子は小文字 ASCII の slug とし、大文字小文字や空白の表記違いを統一します。`variant` はアーキテクチャ、配布パッチ、manpath など、同じ版で内容が変わる条件を表します。識別子の根拠や原文で確認できなかった情報は各ディレクトリのメモに残せます。

roff は `mandoc` で HTML にし、段落、定義リスト、入れ子のリスト、表、見出し、コードを IR に変換します。HTML の URL も同じ IR に入るため、元の roff を指定する必要はありません。HTML 内の本文領域は自動選択し、必要な場合は `--selector` で指定できます。古い `<pre>` 型の man ページも、説明文と構文を分離して扱います。

翻訳はこのリポジトリを操作する AI が `request.ja.json` を読んで実行できます。LLM プロバイダーや API キーは固定せず、通常ビルド時にも翻訳 API は呼びません。用語集と翻訳指示を依頼ファイルに含め、翻訳の前後をファイルで確認できます。

[翻訳キュー](translation-queue.md) は原文・IRハッシュごとのジョブを保持し、1マニュアルから指定数の未保存セグメントをエージェントへ渡します。途中訳文と担当の更新は1つのJSONへ原子的に保存します。古い担当トークンを拒否し、時間経過による横取りは行いません。処理に使う作業ツリーを1つに固定し、ローカルファイルロックで同時更新を直列化します。全訳文が揃っても未完了とし、原文・IR・訳文ハッシュを含む意味レビュー記録と受理・生成・対象検証の後で完了にします。起動時刻の判断とエージェントの実行は呼び出し元が担います。

自動検証は、セグメントの欠落、保護トークン、原文・IR のハッシュ、生成の再現性、HTML の安全な描画を対象にします。訳文の意味の正しさは別途原文と照合します。権利に関する情報は参考メモであり、生成を停止する判定には使用しません。

Starlight のコンポーネント差し替えはヘッダー・テーマ・タイトル・フッター・検索に限定し、ナビゲーションと目次の基本動作を利用します。明示的な slug と原文の見出し ID により、翻訳や版名に含まれる日本語・ドットでリンクが変わるのを防ぎます。

従来の isync / MEGAcmd / Wrangler のページは URL と本文を維持しています。これらは原文・版情報が十分に保存されていなかった既存資料であり、今回新たに取得した原文と同じ検証済み資料として扱いません。今後原文を取得できたものから版別構成に移せます。

全文検索は Pagefind を基本にし、日本語の複合語などで結果が 0 件になった場合に、同じサイト内の本文文字列索引を遅延読み込みします。単語分割の違いによる見落としを補います。索引はビルド時に生成し、ページ数が大きく増える場合は分割して配信する余地があります。

## 提供元と HOME

Apple、FreeBSD、isync、MEGAcmd などの収録元を「提供元（provider）」として管理します。企業・OS・個別プロジェクトをまとめて扱うナビゲーション上の単位であり、`product`（macos、base、ports など）や man セクションとは別です。識別子は既存の `manifest.identity.provider` を維持し、表示名と説明は `src/data/manual-providers.json` を正本とします。サイドバー、コマンド検索、全文検索の選択肢も同じ定義を使います。

`content:render` は収録済みの版別カタログから `/<provider>/home/` を生成します。HOME は製品・版・バリエーションごとにマニュアルを一覧し、サイドバーの先頭に表示します。既存 isync / MEGAcmd の HOME は手書き資料として保持します。生成 HOME を手で変更せず、説明は提供元定義、収録内容は `manuals/` を更新します。

OpenBSD と GNU は提供元として登録済みですが、訳文の収録がない間は HOME・サイドバー・検索候補に表示しません。OpenBSD の訳文を収録して `bun run build` を実行すると HOME と導線が生成されます。さらに別の提供元を増やす場合は、同じ JSON に小文字の固定 ID・表示名・説明を追加し、その ID で原文を取り込みます。提供元を登録せずにサイト生成しようとすると、登録先を示して検出します。

## フォントの読み込み

Regular と Bold の `@font-face` と preload は `astro.config.ts` が同じ URL から生成します。`font-display: block` により、通常の読み込み中に幅の異なる代替フォントを一瞬表示することを防ぎます。初回やキャッシュがない場合はフォントが用意できるまで短時間文字が表示されず、長い遅延や失敗時はブラウザー標準のフォールバックを使用します。

`public/_headers` はフォントのブラウザーキャッシュを 1 年に設定します。URL の `v` はフォント実体の SHA-256 先頭12桁からビルド時に計算し、フォントを更新するとキャッシュも切り替わります。HTML と本文のキャッシュ方針は配信環境の既定値を使用します。Cica 本体とライセンス類は従来どおり同梱し、外部フォント配信は使いません。
